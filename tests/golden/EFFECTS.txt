# Declared effects that differ from docs/arity.md's probed column, and why.
#
# Written by hand, read by `cargo xtask effects`. Format:
#
#   <word>\t<reason>
#
# A divergence here is NOT a defect — it is a case where the *probe* measured
# something other than the word's arity. The probe feeds sentinels of one type
# at a time, so for a polymorphic word it measures one arm, and for a word that
# rejects every sentinel it measures a failure path. Both produce a number, and
# a number that means nothing is worse than a blank.
#
# A word that simply declares the wrong arity does not belong here. Fix it:
# `?object` (1->1 where it peeks and leaves 1->2) and `swap` (1->0 where the
# stack comes back the size it went in) were both found by this tool and both
# were corrected in the code.
#
# **`move_from` was in this file and should not have been.** It was recorded as
# a failure-path artefact; the probe's 2->0 was simply right, and Bund2's
# 1->1 was a different word — one name and one value moved to the current
# stack, where the reference takes two names and drains between them
# (`stack_move.rs:65-71`). Q21 found it. The lesson is that this register can
# be used to explain away a true finding, so an entry needs the source read,
# not a plausible story.

apply	arm — the probe applied an INTEGER sentinel, which `apply` pushes back, so it read 1->1. Applied to a CALL the effect is whatever the call does. Genuinely not a fixed arity; RFC-0004 §S1's `Opaque` is the arm that will say so, and 1->0 is the closest the current shape allows.
graph!	arm — the probe fed INTEGER sentinels, which are not LISTs, so `graph!` pushed them back and built an empty graph: 0->1. Given the two LISTs it is written for it consumes both, which is the declared 2->1. See `mod.rs:68-93` — the word never fails and its arity depends on the tags it is handed.
move	variadic — `move` **drains** the current stack into a named one (`ts_move.rs:17-31`), so it consumes the name plus everything below it. There is no fixed arity to declare; 2->0 is the name and one value, the smallest true case. The probe read 1->0 from a failure path — an INTEGER where a STRING name was wanted — which is a second reason its number does not describe the word.
