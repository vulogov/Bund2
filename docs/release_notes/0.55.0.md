# Bund2 0.55.0

*In development.*

A Bund program can start VMs. Until now concurrency in Bund2 was an
embedding feature (RFC-0007 §C6): a Rust host started the VMs and each ran
a Bund program. D249 adds three words that let a program do it itself,
alongside everything that was there, and amends RFC-0007.

## Words that start VMs (D249)

In every build:

| Word | Stack | What it does |
|---|---|---|
| `vm.spawn` | `program values -- handle` | Starts a VM on its own thread. `program` is a LAMBDA or a STRING; `values` is a LIST whose items the new VM finds on its stack, first item lowest |
| `vm.join` | `handle -- list` | Waits for that VM and answers its final stack as a LIST; fails if the VM stopped with an error |
| `vm.done?` | `handle -- bool` | Whether that VM has finished, without waiting |

    :w { 6 7 * } list vm.spawn var
    :w var? vm.join println        // [ 42 :: ]

- A new VM has the standard vocabulary and nothing of its parent's, and
  the same `--noio`, `--noeval` and `--nocolor`. Under `--noeval` a STRING
  program is refused; a LAMBDA is not.
- VMs talk over the local bus, as VMs started by a host do.
- A handle is never reused and is joined once.
- At most 64 VMs started with `vm.spawn` run at once.
- A program that ends with VMs it never joined gets one warning.

**Additive.** A program that defines its own `vm.spawn`, `vm.join` or
`vm.done?` still calls its own. `bund2_async::host::Host` keeps its API;
its thread set-up moved into `bund2-runtime` as `vm_thread` and
`vm_on_this_thread`, which `vm.spawn` shares.

## Examples

- **`threads_demo`**: several VMs on threads, joined by the local bus, a
  worker pool and a pipeline, started by a Rust host with
  `bund2_async::host::Host`.
- **`threads_demo_inner`**: the same pool and pipeline in one `demo.bund`,
  started and joined with the `vm.` words.
