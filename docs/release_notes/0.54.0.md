# Bund2 0.54.0

The release that connects Bund to SMYSL. RFC-0014 was drafted, reviewed
nineteen times, accepted at revision 21, and built in ten milestones, M1 to
M10. A Bund program can now form a SMYSL library, research it, query it,
and reason over it with the logic engine 0.53.0 added. Three decisions
record the rulings: D244 (R1–R21), D245 (R22–R25) and D246 (R26–R28).

**Health.** conform **143/159**, CEILING **143/159**, unchanged from
0.53.0: at the ceiling, and no golden regressed. COVERAGE 577/602 in-scope
words, IMPLEMENTED 597/602, also unchanged, because the `smysl.` words have
no counterpart in the reference and no golden can hold them. Unit tests
and the demo cover them instead. The decisions register holds 246
entries, none OPEN.

## SMYSL corpora (RFC-0014)

**Off by default.** The words exist only in a `bund2` built with the
`smysl` feature:

    cargo build --release -p bund2-cli --features smysl

`bund2 --version` names `smysl` among the built-in features of such a
build. The feature links eight of SMYSL's crates, pinned to the git
revision `4f5ecb9`, with their default features off. It reads plain text
and Markdown, and it builds without a C compiler. The default build links
none of it.

A library is named by a **handle**, a MAP of `type`, `root` and `agent`.
`smysl.create` and `smysl.open` answer one, and `smysl.agent` changes the
agent that the handle's writes are attested as. Units, relations and
labels are MAPs, so they print, save and compare like any other value.

    :lib "mill" smysl.create var
    :lib var?
      dict :schema "observation" set
           :gist   "The oak axle of the wheel has split along the grain." set
           :status "cited" set
           :source dict :kind "doc" set :reference "Inspection log, 3 May" set set
      smysl.unit

- **Forming.**
  - `smysl.unit`, `smysl.rel`, `smysl.label` and `smysl.append` write
    units, relations and labels. Each record is attested, and either a
    batch is written whole or nothing is.
  - `smysl.text.add` reads a text in, and `smysl.texts` lists the texts
    under each alias.
  - `smysl.parse` reads SMYSL's own syntax into MAPs, and `smysl.write`
    gives a library back as that syntax. It warns about anything the syntax
    cannot hold.
  - `smysl.check` runs SMYSL's checks.
  - `smysl.retract` retracts a unit as SMYSL's own `retract` does, after
    SMYSL's authority check. It is the only way to write a `retracts`
    edge.
- **Researching.**
  - `smysl.get` reads a unit back.
  - `smysl.trace` follows parents, grounds, both, what a unit rests on,
    or what depends on it.
  - `smysl.status` gives each unit's effective status after retraction.
  - `smysl.salience` ranks units, and `smysl.pack` selects units to a
    token budget.
  - `smysl.dossier` assembles SMYSL's answer to a question, and
    `smysl.measure` runs SMYSL's measures over a scope.
- **Querying.** `smysl.query` runs one `sq/1` query and answers a MAP for
  each kind of result: a scope, a ranking, a count, groups, or a packed
  selection. The `smysl` conditional runs a lambda once for each unit a
  query names.
- **Reasoning.**
  - `smysl.kb` turns a library, or part of one, into a knowledge base of
    facts for the `kb.` words: `unit`, `gist`, `grounds`, `deps`, `label`,
    `effective`, `rel` and `rank`.
  - `smysl.prove` proves a goal against such a KB and writes each proof
    back into the library:
    - A fact the library bears out stands for its units. Any other fact is
      written as a program fact, at the status `opts.facts` names.
    - Each conclusion is a unit grounded on its premises, at a status no
      stronger than they are. Its attestation names them as parents.
    - Gists are fitted to every granularity profile of the library's
      views.
- **Refusals** carry codes SM00 to SM12, each with a fixed text. Examples:
  SM00 for a value that is not a handle, SM07 for a library locked by
  another writer, SM09 for a retraction SMYSL's plan refuses, and SM12 for
  a view with no room for a proof's gist. Warnings from SMYSL arrive as
  `Warning`s, one per diagnostic.

**Locks.**
- Every word that writes takes SMYSL's own locks on the library, and
  takes a mutex in this process too. Writes are therefore serialised
  against other Bund programs and against SMYSL's `lib` and `text`
  commands.
- If a write fails part way or panics, the library stays locked so an
  operator can look at it. `bund2 smysl-unlock <root>` lists each lock
  and who holds it; `--yes` breaks them.
- **Six SMYSL commands write without locking:** `q --save`, `ask --save`,
  `measure` and `assess` without `--dry-run`, `same-as`, and
  `ingest --text`. A library a Bund program writes must not be written by
  any of them at the same time (R22). The fix belongs to SMYSL, which has
  been asked to lock them.

**`--noio`** stubs every `smysl.` word that touches disk, the constructor
`smysl`, and the conditional's handler (SM06). `smysl.parse` and
`smysl.agent` do no I/O and still work.

**Not in this release:** SMYSL's model-driven steps (`smysl-ingest`,
`smysl-provider`) are Phase 2, left to a later amendment (R1).

## Examples

- `bund_examples/smysl_demo/` builds a library about why an old mill
  grinds slowly:
  - it forms units one MAP at a time and from SMYSL's syntax;
  - it researches their grounds and salience, then retracts a ground;
  - it queries the library and writes it back out;
  - it reasons over it with `smysl.kb` and `smysl.prove`, which writes
    its proof back into the library as a finding.

  Its Makefile builds a `smysl` `bund2` and runs the demo from no library.
  A test runs it in a fresh directory and compares the output with
  `expected.txt`.

## Tooling

- CI gains RFC-0014's seven steps:
  - the `smysl` suites, with and without the probe that makes a write
    fail at a named point;
  - clippy over the feature and over the probe;
  - the demo;
  - `--features smysl` in the feature matrix, and a build with `CC` and
    `CXX` set to `false`;
  - a second `cargo deny` run under the feature.
- `deny.toml` allows SMYSL's git source (D244). It ignores three advisories
  in crates SMYSL pins, each with its reason: two `pulldown-cmark` issues
  in a parser option SMYSL never sets, and `fxhash`, which is unmaintained.
  The default build contains none of them.
- `tests/golden/PROMOTABLE.txt` names each `smysl` word among the
  feature-gated natives. Its list of promotable natives is unchanged. Its
  comments also catch up on 0.53.0: `kb.askable`, `kb.table` and their
  `.` forms are listed as not reached, and the count of fixed-effect
  natives is 494.
- The palette audit's `FEATURE_GATED` and `ACTS_ON_HOST` lists are now
  checked against the registry, so a new `smysl` word that is left out of
  them fails a test.
