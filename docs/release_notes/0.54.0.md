# Bund2 0.54.0

The release that connects Bund to SMYSL. RFC-0014 was drafted, reviewed
nineteen times, accepted at revision 21, built in ten milestones, M1 to
M10, and amended once (D247). A Bund program can now form a SMYSL library,
research it, query it, and reason over it with the logic engine 0.53.0
added. Phase 2, accepted at revision 27 after five more reviews and built
in five milestones, M11 to M15, lets it call a model too: to extract units
from a document or a text, and to answer a question from what a library
holds. Five decisions record the rulings: D244 (R1–R21), D245 (R22–R25),
D246 (R26–R28), D247 (R29) and D248 (R30–R50).

**Health.** conform **143/159**, CEILING **143/159**, unchanged from
0.53.0: at the ceiling, and no golden regressed. COVERAGE 577/602 in-scope
words, IMPLEMENTED 597/602, also unchanged, because the `smysl.` words have
no counterpart in the reference and no golden can hold them. Unit tests
and the demos cover them instead. The decisions register holds 248
entries, none OPEN.

## SMYSL corpora (RFC-0014)

**Off by default.** The words exist only in a `bund2` built with the
`smysl` feature:

    cargo build --release -p bund2-cli --features smysl

`bund2 --version` names `smysl` among the built-in features of such a
build. The feature links eight of SMYSL's crates, pinned to the git
revision `4f5ecb9`, with their default features off. It reads plain text
and Markdown, and it builds without a C compiler. The default build links
none of it.

A library is named by a **handle**, a MAP of `type`, `root` and `agent`.
`smysl.create` and `smysl.open` answer one, and `smysl.agent` changes the
agent that the handle's writes are attested as. Units, relations and
labels are MAPs, so they print, save and compare like any other value.

    :lib "mill" smysl.create var
    :lib var?
      dict :schema "observation" set
           :gist   "The oak axle of the wheel has split along the grain." set
           :status "cited" set
           :source dict :kind "doc" set :reference "Inspection log, 3 May" set set
      smysl.unit

- **Forming.**
  - `smysl.unit`, `smysl.rel`, `smysl.label` and `smysl.append` write
    units, relations and labels. Each record is attested, and either a
    batch is written whole or nothing is.
  - `smysl.text.add` reads a text in, and `smysl.texts` lists the texts
    under each alias.
  - `smysl.parse` reads SMYSL's own syntax into MAPs, and `smysl.write`
    gives a library back as that syntax. It warns about anything the syntax
    cannot hold.
  - `smysl.check` runs SMYSL's checks.
  - A batch that writes a unit or relation of SMYSL's `x.text` schema,
    such as the entity and `mentions` edges a dossier needs, also writes
    the schema's declaration when the library lacks it, as SMYSL's text
    ingest does. Without it, every check would warn `SMY-W013` (D247).
  - `smysl.retract` retracts a unit as SMYSL's own `retract` does, after
    SMYSL's authority check. It is the only way to write a `retracts`
    edge.
- **Researching.**
  - `smysl.get` reads a unit back.
  - `smysl.trace` follows parents, grounds, both, what a unit rests on,
    or what depends on it.
  - `smysl.status` gives each unit's effective status after retraction.
  - `smysl.salience` ranks units, and `smysl.pack` selects units to a
    token budget.
  - `smysl.dossier` assembles SMYSL's answer to a question, and
    `smysl.measure` runs SMYSL's measures over a scope.
- **Querying.** `smysl.query` runs one `sq/1` query and answers a MAP for
  each kind of result: a scope, a ranking, a count, groups, or a packed
  selection. The `smysl` conditional runs a lambda once for each unit a
  query names.
- **Reasoning.**
  - `smysl.kb` turns a library, or part of one, into a knowledge base of
    facts for the `kb.` words: `unit`, `gist`, `grounds`, `deps`, `label`,
    `effective`, `rel` and `rank`.
  - `smysl.prove` proves a goal against such a KB and writes each proof
    back into the library:
    - A fact the library bears out stands for its units. Any other fact is
      written as a program fact, at the status `opts.facts` names.
    - Each conclusion is a unit grounded on its premises, at a status no
      stronger than they are. Its attestation names them as parents.
    - Gists are fitted to every granularity profile of the library's
      views.
- **Refusals** carry codes SM00 to SM12, each with a fixed text. Examples:
  SM00 for a value that is not a handle, SM07 for a library locked by
  another writer, SM09 for a retraction SMYSL's plan refuses, and SM12 for
  a view with no room for a proof's gist. Warnings from SMYSL arrive as
  `Warning`s, one per diagnostic.

**Locks.**
- Every word that writes takes SMYSL's own locks on the library, and
  takes a mutex in this process too. Writes are therefore serialised
  against other Bund programs and against SMYSL's `lib` and `text`
  commands.
- If a write fails part way or panics, the library stays locked so an
  operator can look at it. `bund2 smysl-unlock <root>` lists each lock
  and who holds it; `--yes` breaks them.
- **Six SMYSL commands write without locking:** `q --save`, `ask --save`,
  `measure` and `assess` without `--dry-run`, `same-as`, and
  `ingest --text`. A library a Bund program writes must not be written by
  any of them at the same time (R22). The fix belongs to SMYSL, which has
  been asked to lock them.

**`--noio`** stubs every `smysl.` word that touches disk, the constructor
`smysl`, and the conditional's handler (SM06). `smysl.parse` and
`smysl.agent` do no I/O and still work.

## SMYSL's model steps (RFC-0014, Phase 2)

**Off by default, and in builds of their own.** The model words exist only
in a `bund2` built with `smysl-model`, which implies `smysl`, and reach a
provider only through the mapper built for it:

    cargo build --release -p bund2-cli --features smysl-ollama

- `smysl-ollama` drives a local or remote Ollama. Like `smysl`, it builds
  without a C compiler: it links an HTTP client with no TLS.
- `smysl-anthropic`, `smysl-openai`, `smysl-gemini` and `smysl-deepseek`
  drive the hosted providers. They link TLS through `rustls` and `ring`,
  so they need a C compiler, as `grok` does.
- `smysl-model` alone builds, and every provider its configuration names is
  skipped with a warning as not compiled into this build.

`bund2 --version` names `smysl-model` and each mapper a build has.

**Four words** (D248):

- `smysl.ingest` *handle input opts* sends `input`, a STRING, to the model
  and answers the units it extracted as a **staged** value. It writes
  nothing.
- `smysl.answer` *handle question opts* assembles the dossier
  `smysl.dossier` would, asks the model to answer the question from it, and
  stages the dossier and the answer together. It writes nothing.
- `smysl.commit` *handle staged* checks a staged value again against the
  library under the locks, writes it as one batch, and answers the uids it
  newly wrote.
- `smysl.ingest.text` *handle target opts* sends one text of the library to
  the model window by window, two calls a window. It commits and journals
  each window as it goes, and answers the run's report as a MAP. A second
  run finds the journal and calls the model only for windows not yet done.

A staged value is a MAP: the units, relations and labels as MAPs for a
program to read and decide on; `clean`, whether the batch would add an
error to those the library already has, or a model call failed; the
provider, model, usage and recipe; and the records themselves as a
**BIN**. A commit trusts none of it. It decodes the records and checks them
again, and refuses with SM03 a batch that no longer checks clean. Nothing
the model said is written until the program commits it.

- **Attestation.** A document's units are written Imported, by the
  handle's agent, at the Document rung. An answer's are written at the
  Model rung and capped at `inferred`, whatever the model claimed. A
  dossier's own units and relations are written as Authored, by the
  handle's agent. A label the model binds that the library already binds
  elsewhere is dropped with a warning.
- **`opts`** is a MAP of `config`, `offline`, `model`, `temperature`,
  `path`, `max_output`, `granularity`, `source`, `level`, `reextract` and
  `digest`, each optional and each checked. A key a word does not take is
  SM03.
- **The configuration is SMYSL's own.** It is `opts.config`, else
  `.smysl/config.hjson` beside the library, else SMYSL's default: one
  local Ollama, model `llama3.2`. A configuration names a key only by an
  environment variable or a command, never the key itself.
- **Before any call, each word probes the provider.** A provider that is
  unreachable, refuses, or does not offer the model asked for is SM13,
  new in this release, and nothing is sent.
- **`opts.offline`** is SMYSL's `--offline`. It refuses, SM13, a provider
  whose endpoint is not a loopback address, before any socket is opened.
- **What leaves the machine.** `smysl.ingest` sends its input,
  `smysl.answer` the dossier's gists, and `smysl.ingest.text` the text's
  windows. Model calls ignore `http_proxy`. An Ollama at `https://` needs a
  hosted mapper in the build for its TLS.
- **`--noio`** stubs all four words with SM06.

**Locks, a table rather than a mutex** (R42).
- `smysl.ingest` and `smysl.answer` hold no lock while the model works.
- `smysl.ingest.text` holds SMYSL's locks for its whole run. While it does,
  another write to the same library from this process is refused at once
  with SM07, naming the run, instead of waiting behind it.
- Each library root now has a held flag and, for a text run, a mark. Both
  are cleared on every exit, a panic's included, so a failed write leaves
  SMYSL's locks for an operator, as before, and never a stuck process.
- `smysl.create` can now be SM07 while a text run marks its root.

**BIN.** Bund2 gains the reference's binary value (`dt` 8, RFC-0001's
amendment), for a staged value's records. No Bund word makes one, as in
the reference: `convert.to_*` turns one into a LIST of one-byte BINs,
`len` gives its byte count, and `+` and `push` append to it.

**Not in this release.** `--offline` as a `bund2` flag (R33), and a
scripted provider for users' tests (R38): both were ruled out. Whether a
hosted provider's model list names every model it accepts (Q60) is still
open. The probe refuses a model the list does not name.

## Examples

- `bund_examples/smysl_demo/` builds a library about why an old mill
  grinds slowly:
  - it forms units one MAP at a time and from SMYSL's syntax;
  - it researches their grounds and salience, then retracts a ground;
  - it queries the library and writes it back out;
  - it reasons over it with `smysl.kb` and `smysl.prove`, which writes
    its proof back into the library as a finding.

  Its Makefile builds a `smysl` `bund2` and runs the demo from no library.
  A test runs it in a fresh directory and compares the output with
  `expected.txt`.
- `bund_examples/smysl/` is the long tour of SMYSL with logic
  programming, over why a village well ran dry. It uses every `smysl.`
  word, and every place the `kb.` words meet a library:
  - the library's facts asked together, with CLP(FD) over their ranks;
  - tabled rules, and a predicate made into a word;
  - bridges that call `smysl.trace` while a rule is being solved;
  - saturation, and askable goals with seeded replies;
  - proofs written back as findings, including a proof by negation and a
    cited program fact;
  - a rule resting on those findings, and a retraction seen through
    `effective` facts.

  A test compares its output and its three warnings with `expected.txt`
  and `expected.stderr.txt`.
- `bund_examples/smysl_model/` has a model build a library about why a
  harbour silted up:
  - it ingests a document and commits it;
  - it answers a question over the library and commits the answer;
  - it ingests and commits a second document;
  - it ingests a Markdown text window by window, then runs it again and
    finds every window journalled.

  It runs by hand against a local Ollama. Its README says what each word
  sends, how `offline` keeps it local, that model calls ignore
  `http_proxy`, and what an `https://` Ollama needs. A model's answers are
  not fixed, so an `#[ignore]`d test asserts only that every step returns.

## Tooling

- CI gains RFC-0014's seven steps:
  - the `smysl` suites, with and without the probe that makes a write
    fail at a named point;
  - clippy over the feature and over the probe;
  - the demo;
  - `--features smysl` in the feature matrix, and a build with `CC` and
    `CXX` set to `false`;
  - a second `cargo deny` run under the feature.
- CI gains Phase 2's steps:
  - the model suites, run against `bund2-script`, a scripted provider that
    exists only in a test-only feature;
  - clippy over them;
  - a build with `smysl-ollama` and `CC` and `CXX` set to `false`;
  - a `cargo check` with every mapper;
  - a `cargo deny` run with every mapper.
- `deny.toml` allows `CDLA-Permissive-2.0`, the licence of `webpki-roots`,
  which only the hosted mappers link (R43).
- `deny.toml` allows SMYSL's git source (D244). It ignores three advisories
  in crates SMYSL pins, each with its reason: two `pulldown-cmark` issues
  in a parser option SMYSL never sets, and `fxhash`, which is unmaintained.
  The default build contains none of them.
- `tests/golden/PROMOTABLE.txt` names each `smysl` word among the
  feature-gated natives. Its list of promotable natives is unchanged. Its
  comments also catch up on 0.53.0: `kb.askable`, `kb.table` and their
  `.` forms are listed as not reached, and the count of fixed-effect
  natives is 494.
- The palette audit's `FEATURE_GATED` and `ACTS_ON_HOST` lists are now
  checked against the registry, so a new `smysl` word that is left out of
  them fails a test.
