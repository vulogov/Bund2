# Where a fetch goes: the oracle and Bund2, 278 settings

Measured 2026-10-09 on macOS (Darwin 27.0.0), arm64. The oracle is
`reference/Bund` at `21b40b0`, built out of tree, linking the system's
libcurl, 8.7.1. Bund2 is the commit that adds this table: `acf448d` and the
answers to RFC-0006's thirteenth review. *(The first version of this file,
at `acf448d`, had 175 rows; rows 1 to 175 here are those settings, measured
again.)*

`fetch.py`, beside this file, printed the table below exactly, run with
`--port80`. Each row runs `"<url>" use` on both binaries with the proxy
variables shown and no others. Listeners on `127.0.0.1` and `::1` answer an
HTTP request with a Bund program that prints the listener's name; a
connection that is not HTTP is sent the bare program after a second.

A cell is **what was printed**, then **every connection any listener
received**, in order:

- `origin` — the host the URL names. `p1`, `p2` — the proxies the variables
  name. `p1080` — port 1080, libcurl's default for a proxy. `p80` — port
  80, where a client goes that has lost the port it was given. `file` — a
  file was read. `fail` — nothing was evaluated. `timeout` — a direct
  connection to an address nothing answers on.
- `p1:GET http://…` is the reference asking a proxy for the URL, and
  `p1:CONNECT …, p1:GET /…` is Bund2 asking it for a tunnel: D124's first
  deviation, in every proxied row, and not counted as a difference below.
- `SOCKS5`, `TLS`, `other …` and `silent` are a connection that spoke
  something else, or waited to be spoken to.
- `-` is nobody asked. **A `fail` beside `-` and a `fail` beside a
  connection are different outcomes**, which the first version of this file
  could not tell apart.

Unless a row says otherwise the URL is `http://127.0.0.1:<origin>/lib.bund`
and `http_proxy` names `p1`. `O`, `P1` and `P2` are the ports of the origin
and the proxies; in a setting they are written `OPORT`, `P1`, `P2`.

## What differs

**31 rows.** In 30 of them Bund2 refuses and asks nobody, where the
reference asks somebody. In one Bund2 reads a file the reference refuses. In
no row does Bund2 ask a listener the reference does not ask.

| rows | what | covered by |
|---|---|---|
| 39, 40, 93, 263 | a SOCKS or HTTPS proxy: the reference speaks to it, Bund2 fails the fetch | D124 |
| 158, 277, 278 | a URL with no scheme: libcurl guesses `http` | D54 |
| 160, 272, 273 | `https://` | D54 |
| 174 | a `file:` URL with a literal space: libcurl refuses, Bund2 reads | D125 |
| 161, 264 to 271, 275, 276 | another scheme: the reference evaluates what `gopher://`, `dict://`, `telnet://`, and `ftp://` through a proxy, return, and connects for `ftp://` and `smb://` | D126 |
| 208 to 211, 239 to 242, 261 | a spelling of an `http:` URL or proxy that libcurl takes and Bund2 refuses: `<`, `>`, a backtick, `%xx` in a host, an IPv6 zone, a host that is not ASCII | D127 |

Row 219, an empty port, is the one row that reaches `p80`, on both.

What this is not: libcurl's URL parser. It is 278 spellings somebody thought
to try, on one libcurl, on one system.
