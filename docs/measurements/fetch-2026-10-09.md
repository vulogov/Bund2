# Where a fetch goes: the oracle and Bund2, 175 settings

Measured 2026-10-09 on macOS (Darwin 27.0.0), arm64. The oracle is `reference/Bund` at
`21b40b0`, built out of tree, linking the system's libcurl, 8.7.1. Bund2 is
the tree that carries F182's note of the same day and F183.

`fetch.py`, beside this file, produced the table. Each row runs
`"<url>" use` on both binaries with the proxy variables shown and no others.
Listeners on `127.0.0.1` and `::1` answer any request with a Bund program
that prints the listener's name, so a cell is who answered:

- `origin` — the host the URL names; a direct fetch.
- `p1`, `p2` — the proxies the variables name. `/GET` and `/CONNECT` are
  what the proxy was sent first: D124's first deviation, in every proxied
  row.
- `p1080` — a listener on port 1080, libcurl's default for a proxy.
- `file` — a file was read.
- `fail` — nothing was evaluated. For a host nothing resolves, that is a
  direct fetch.
- `timeout` — a direct connection to an address nothing answers on.

Unless a row says otherwise the URL is `http://127.0.0.1:<origin>/lib.bund`
and `http_proxy` names `p1`. `OPORT` is the origin's port, `P1` and `P2` the
proxies'.

**Two rows differ in who answers**, 158 and 174:

- **158, a URL with no scheme.** libcurl guesses `http`; Bund2 refuses. An
  approved deviation, D54.
- **174, a `file:` URL with a literal space.** libcurl refuses the URL;
  Bund2 reads the file. An approved deviation, D125.

What this is not: libcurl's URL parser. It is 175 spellings somebody thought
to try, on one libcurl, on one system.
