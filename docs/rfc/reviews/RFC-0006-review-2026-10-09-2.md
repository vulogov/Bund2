## Blocking

**B1 — A proxy named without a port is not "chosen as libcurl chooses it".
The reference connects to port 1080 and Bund2 to port 80.**

§B7: "A proxy is chosen as libcurl chooses it for the reference", then a table
of rules, then "All 73 agree on where the request goes. **Two differences
remain**". The table has a row for a proxy with no scheme and none for a proxy
with no port. The preservation row for `use` and the status paragraph both
repeat "two differences"; D124 says "two differences were left", and F182
"the request goes to the same place in all 73".

`proxy_for` returns the variable's text unchanged, and `fetch_uri_in` hands it
to `ureq::Proxy::new` (`crates/bund2-stdlib/src/host.rs`). `ureq` takes the
port from the URI and, when there is none, the protocol's default
(`ureq` 3.4.0, `src/proxy.rs:290-294`), which for an HTTP proxy is 80
(`:36`). libcurl's default for a proxy is 1080 — measured below, not cited
from libcurl.

Measured 2026-10-09. The program is `"http://127.0.0.1:18730/lib.bund" use`.
Each listener answers any request with a program that prints its own name.

| the one variable set | oracle | Bund2 |
|---|---|---|
| `http_proxy=127.0.0.1` | **the listener on 1080** | **the listener on 80** |
| `all_proxy=http://localhost` | **the listener on 1080** | **the listener on 80** |
| `http_proxy=http://127.0.0.1:1080` (control) | the listener on 1080 | the listener on 1080 |

With nothing on port 80, Bund2's fetch fails where the reference's succeeds.
With something on port 80 of the proxy's host, **Bund2 evaluates what that
listener returns and the reference evaluates what another one does.**

**Why it blocks.**

- It is the eleventh review's B1 again, in the half F182 said it closed.
  D124's own reasoning draws the line: "Which proxy is asked, and for which
  hosts, is the part with a security consequence, and F182 makes that the
  reference's." For a proxy written as a host name, it does not.
- The row says two differences remain and D124 approves two. This is a third
  and nobody approved it — CLAUDE.md's shape, "a required deviation filed as
  a non-deviation, so no criterion covers it". No test names a proxy without
  a port: `the_proxy_is_the_one_libcurl_would_take` stops at the string
  `proxy_for` returns, and both wire tests give the proxy a port.
- A proxy given as a bare host is an ordinary setting, not a constructed one.
- Unlike D124's two, `ureq` can close it. Bund2 chooses the string it hands
  over.

**What it needs.** A ruling first, because either answer is the owner's: a
defect under F182 (the port libcurl would take is supplied before `ureq` sees
the proxy), or a fifth approved deviation under D54. Then the row in §B7's
table, the count in the status paragraph, the `use` row and D124's and
F182's "two" and "all 73", and a wire test with a port-less proxy.

**What the 73 were is not recorded.** The figure is in §B7 and F182; neither
lists the settings, and no script that ran them is in the repository. The
unit tests carry rows that "are a measurement of the oracle", uncounted. So a
reader cannot tell which forms of the *proxy's value* were among the 73, and
this review found the missing one by reading `ureq`, not by reading the list.

## Should fix

**S1 — `no_proxy` is matched against the host as written; the reference
matches the address the host is.** `bypasses` parses the URL's host with
`ipv4`, which takes four decimal parts and nothing else. libcurl normalises an
IPv4 host first. Measured with `http_proxy` naming the listener on 18731 and
`no_proxy=127.0.0.1`:

| the URL's host | oracle | Bund2 |
|---|---|---|
| `127.0.0.1` | direct | direct |
| `127.1` | **direct**; `Host: 127.0.0.1:18730` | **through the proxy**; `CONNECT 127.1:18730` |
| `2130706433` | **direct** | **through the proxy** |
| `0x7f.0.0.1` | **direct** | **through the proxy** |

The same class as B1 — the environment's proxy answers for a URL the
reference fetches directly — and much narrower: it needs a program that
writes an address in a short, decimal or hexadecimal form. §B7's table says
"an IPv4 host | by address", which is true of the entry and not of the host.
Whether it is a defect or a deviation is the same ruling as B1's.

**S2 — `HTTP://` is refused; the reference fetches it.** `fetch_uri_in`
tests `uri.starts_with("http://")`. Measured with no proxy:
`"HTTP://127.0.0.1:18730/lib.bund" use` prints `origin` on the oracle and
fails on Bund2. D54 approves two deviations — a string with no scheme, and
`https://` — and this is neither; the registers do not mention a scheme's
case. It is D54's and older than this RFC, and the `use` row "Preserved
under D54's scheme set" inherits it. `file://` was not measured in upper
case.

**S3 — Criterion 12 gives a reason for the flags check that D118 rules
out.** "a later bund2 that defined a third restriction in the same container
version would [write such a byte], and every earlier one would have loosened
it silently", and "the old runtime declines". Under D118 an artefact *is* the
bund2 that built it: the runtime that reads a flags byte is the binary that
wrote it, so no earlier runtime ever meets a later bund2's flags. What can
meet them is an earlier bund2's `--inspect` — which is what the eleventh
review's S2 said — and every bund2 before `9b9154c` still prints
`restrictions none` for it. So `carried`'s new arm fires on a patched or
damaged byte only, which is what the test does, and the preservation row "A
restriction a later bund2 defines | **Refused**" describes a meeting that
cannot happen without cross-target bundling. The check is right and cheap;
the reason given is §B1's superseded construction. `Damaged::Restriction`'s
text, "built by a different bund2", has the same premise.

**S4 — §B1 still lists four kinds of damage.** "One case that is not a
failure and four that are", and "Criterion 12 checks all five", where five is
four and the empty region. Criterion 12 now has "A fifth since 2026-10-09"
and the preservation row says "five kinds of damage are errors … (§B1,
criterion 12)". §B1's list has no bullet for an unknown restriction bit, and
its "all five" now means something else in the criterion it points at.

**S5 — "Seven things about this list" heads six bullets.** §B3: "Four were
not written down until 2026-10-08 — the seventh review — and the last three
were added by the eighth, tenth and eleventh." The bullets are `--`,
`--debugger`, the restriction variables, `BUND_LOG_LEVEL` and `COLUMNS`, the
three history variables, and the five proxy variables. The eleventh review's
S4 was "Four" heading five; this is the third correction of this count.

**S6 — Carried, all stated in the RFC and none changed.** `cargo xtask
bundle` in neither `cargo test` nor CI; `black_box` a hint; ELF and PE
unmeasured in the built form; `/usr/bin/codesign` possibly a stub; no
criterion has run in CI; the recorded version is `0.0.0`; Q42; the three
loose citations.

## What the RFC assumes and does not state

1. **The 73 settings vary everything the choice depends on.** They vary the
   variables and the `no_proxy` entry. The proxy's own value was varied in
   scheme and not in port (B1), and the URL's host in kind and not in
   spelling (S1).
2. **Handing `ureq` the string libcurl would pick is handing it the proxy
   libcurl would pick.** Past the choice of variable, `ureq` parses the
   value by its own rules. Measured the same on both: an upper-case scheme,
   a trailing path, credentials (sent on `CONNECT` by Bund2, on `GET` by the
   reference — inside D124's first deviation), and a leading blank, which
   fails both. The port is the one that differs.
3. **A scheme is written in lower case** (S2).
4. **`file://` and `http://` are the only schemes the reference would have
   fetched.** D54 says "Anything else fails" and lists two approved
   deviations. The system libcurl speaks others; none was measured here, and
   nothing in the registers says whether a program in the reference can
   `use` one.
5. **The binary that reads a flags byte may not be the one that wrote it**
   (S3). Stated as the reason for criterion 12's fifth case; false under
   D118.
6. **A proxy variable that is not UTF-8 is unset.** `fetch_uri` reads with
   `std::env::var(..).ok()`, so such a value falls through to the next
   variable, where libcurl would use the bytes. Read, not measured.
7. **Nothing else in the process reads a variable.** §B3 now says its list
   is not whole, which is the right claim. Checked here for Bund2's side:
   every `env::var` under `crates/` outside tests and benches is one §B3
   names.
8. Carried from the eleventh review and unchanged: the sentinel cannot occur
   in what a build writes; no golden fails to parse; `--inspect` reports what
   a header says and not what the runtime does; the executable on disk is
   the one running when `build` copies it.
9. Carried, and stated in the RFC: the compiler does not fold reads of the
   region; the in-place write works on ELF and PE; `/usr/bin/codesign` is
   present and real; a refusal is text and not an exit status; the rules are
   one libcurl's, 8.7.1, on macOS.

**On where this came from.** F182 measured which variable libcurl reads and
which hosts it excuses, carefully, and the code that came of it is faithful
to the measurement. Then it passes the variable's text to a second parser
and stops looking. B1 is what that parser does with a value that has no
port; S1 is the same gap on the other operand, the URL's host, which libcurl
parses before it compares and Bund2 compares as text. Both are one call past
`proxy_for`, which is where CLAUDE.md says this document's findings keep
being. B1 is a ruling, a line of code or a line in D54, and a row.
