## Blocking

### B1. `ward.D2` squares the distances first, so §S5's sentinel check does not protect it (RFC:628-633)

§S5 refuses a cell at or above 10³⁰⁰, so that the port's
nearest-neighbour search always finds an index. That check runs on D as
given. Under `ward.D2`, `hclust.f` squares every distance before the
search (`hclust.f:65-69`).
- **The failure.** A cell of 10¹⁶⁰ passes the check, and its square
  overflows to +∞. Every comparison `DMIN .GT. DISS(IND)` (`:80`) then
  fails, and `NN(I)` keeps `JM = 0` (`:53`). That is the index hazard of
  the first review's SF3, which this amendment meant to close.
- **R itself goes wrong here.** On R 4.6.2,
  `hclust(as.dist(matrix(c(0,1e160,2e160, 1e160,0,3e160,
  2e160,3e160,0),3)), "ward.D2")` answers `merge` (0, 0), (1, 1). Those
  are rows with no singleton or step in them, an invalid tree.
- **Why the RFC's other refusal does not catch it.** The squaring is not
  an "update", so §S5's E114 for an overflowing update does not cover it
  as written.

**Fix:**
- Under `ward.D2`, refuse a cell whose square reaches 10³⁰⁰. That is
  E101 for a cell ≥ 10¹⁵⁰, or E114 naming the squaring.
- Add the case to criterion 4.

## Should fix

### SF1. One of `pretty`'s quoted answers is wrong (RFC:1055-1056)

§Fixture inputs says `pretty(c(123456789, 123456789.5))` gives "six
values from 123456789 to 123456790". On R 4.6.2 it gives 123456789.0,
123456789.1, …, 123456789.5: six values, ending at 123456789.5.

The criterion would be checked against the committed `.R` output, so
the implementation would not be misled. But the RFC states a wrong
reference value, and a reader checking the port against the RFC's text
would fail it. The other five `pretty` cases, the five `hist` cases, the
fuzz case and the zero-df MANOVA values all reproduce on R 4.6.2.

### SF2. Choice 11's reason, "where R drops them", is true of one word in three (RFC:511, :1209; D278's note)

R handles non-finite values differently in each word:

| R function | What it does with a non-finite value | Source |
|---|---|---|
| `hist` | drops it | `hist.R:36` |
| `density` | drops it, keeping the sub-density | |
| `ecdf` | drops NA only; ±∞ stays a knot | `ecdf.R:25` keeps it by `sort`; `knots(ecdf(c(1,2,Inf)))` is 1, 2, Inf on R 4.6.2 |
| `bw.SJ` | stops: "non-finite x[4] in bandwidth calculation" | `bandwidths.c:125-126` |
| `bw.nrd0` | stops, on a missing value in its `if` | |

D278 ruled the refusal, and the refusal is sound under B12. The stated
reason, however, describes R wrongly for `stat.ecdf`, `stat.ecdf.at` and
`stat.bw`.

**Fix:** correct §S1's sentence. D278's note should get a dated
correction note, not an edit, since the register is append-only.

### SF3. Criterion 3's "5-point Manhattan matrix" is not given (RFC:250, :1073)

This is B3's class of gap again. §Fixture inputs gives every other input,
but not the five points behind `mva.mds`'s `add` case. Those points are
also the support for §What R does' "−3.28 ± 0.52i" (RFC:250).

The review reproduced the claim with the points (0, 0), (1, 0), (0, 1),
(1, 1) and (3, 2): Cailliez's matrix then has −3.281650 ± 0.517931i, and
`cmdscale(…, add = TRUE)$ac` is 1.424602.

**Fix:** state those points, or the ones intended, in §Fixture inputs.

### SF4. Criterion 7's "nothing else changes" is false (RFC:1110-1112)

With `levels` reversed, `prior` and `counts` are reversed as well, since
both are per group. The scaling's signs are fixed by §S1's rule. The SVD
of the between-group matrix is the same up to row order, so `svd` and
`scaling` do not change.

**Fix:** "`lev`, `prior`, `counts`, `means` and the posterior columns
are reversed; `svd`, `scaling`, `class` and `x` do not change".

## Notes

- **N1.** §S4 says D "is checked by §S5's distance checks", and §S5 says
  `cluster.hclust`'s "D's checks are `mva.mds`'s (§S4)" (RFC:576, :628).
  The checks themselves are listed only in §S4, so nothing is missing,
  but each section points at the other. Name one home, for example "the
  distance checks of §S4".
- **N2.** §S13 item 4 calls criterion 9's tolerance relative (RFC:926).
  `stat.density`'s `y` is compared at 10⁻¹² *absolute* (criterion 9's
  second bullet).
- **N3.** §S1's general overflow rule (E114) now covers every word, but
  criterion 11's palette (RFC:1133) lists NaN, ±∞ and malformed operands
  only. Large finite values, around 10¹⁶⁰ to 10³⁰⁷, are what reach the
  overflows:
  - squared distances in `cluster.kmeans`, where R answers, assigning
    every point by `+∞` ties (`kmeans(matrix(1e160*(1:6), 3), 2)` gives
    clusters 1, 1, 2);
  - `from − cut·bw` in `stat.density`;
  - the SVD.

  Adding them to the palette makes criterion 11 test the rule.
- **N4.** `cluster.kmeans`'s inputs remain unnamed ("inputs with ties
  and with more than one transfer pass"). Unlike the cases B3 covered,
  R is the check here and the inputs are free, so this is acceptable. It
  is the one criterion whose inputs are still the implementer's choice.
- **N5.** §S13 item 2 cites `nlm.R:55-60` for `uniroot`'s ends and
  `maxiter`. That holds: `f.lower = f(lower, …)` and `f.upper =
  f(upper, …)` are default arguments (`:57`), and `maxiter = 1000`
  (`:60`).
