## Blocking

**B1 — `debug` evaluates its operand. A bundle built `--noeval --noio` runs a
string it holds, with nobody at the keyboard, and the RFC says that route is
closed.**

Measured on a bundle built `--noeval --noio`, standard input closed, whose
whole program is `"40 2 + println" debug`:

    $ ./dbg.bin </dev/null          (the per-word tables elided)
    42
    $ bund2 build --inspect dbg.bin
      restrictions   --noio --noeval

The oracle agrees: `bund --noeval --noio script --file …/dbg.bund` prints
`42`.

The reference's `debug` is not a prompt that happens to evaluate. It pulls a
STRING (`reference/Bund/src/stdlib/functions/debug_fun/debug_debug.rs:126-134`),
parses it (`:52-53`), and **applies every word of it** (`:75`). Only then,
after each word, does it read lines until one is empty (`:81-89`); end of
input breaks that inner loop (`:100-103`) and the outer one carries on to the
next word. Bund2 reproduces it (`crates/bund2-stdlib/src/terminal.rs`,
`debug_word`). The RFC cites `:82-89` — the inner loop — and stops seven lines
below the `apply`.

What the RFC says, in four places:

- §B3a: "`debug` and `debug.shell` read lines and evaluate each one."
- §B3a: "**`debug.shell` needed nobody at the keyboard, and under the flag it
  does again — D121.**"
- §B3a: "So 'the reference's boundary' is the answer for the reference's
  words only… D120 and D121 are that choice for Bund2's two."
- Preservation, `debug.feed`: "the flag stubs it, because before
  `debug.shell` it ran a line nobody typed."

Three things follow.

- **D78 is not met, for the fourth time.** "RFC-0006 states what each flag
  leaves ungated, by name." `debug` is named — as something it is not. A
  builder reading §B3a concludes that under `--noeval` a string runs only if
  it goes through `compile lambda! !` or somebody types it. `"…" debug` is a
  third way and is `bund.eval` with tables.
- **D121's premise is wrong, and its cost was paid for less than it says.**
  D121 stubs `debug.feed` because "before `debug.shell` it removes the
  person", and accepts that under the flag the word "cannot queue a line for
  `input`, `input*` or `password` either". The person was never required:
  the reference's own `debug` runs a held string unattended. D121 still
  closes the route it names. It does not buy what its title implies, and the
  owner ruled on it without that fact.
- **Three RESOLVED decisions carry the same description.** D115: "`debug` and
  `debug.shell` still read lines and run them". D120: "`debug` and
  `debug.shell`, which read lines and run them". D121: "…still read lines and
  run them under `--noeval` when somebody types them". Each needs a dated
  note; none may be rewritten.

**This needs a ruling, not an edit, and it is not D120's kind.** `debug` is
the reference's word and the oracle evaluates the string under both flags, so
D79's reading — the flag names a group, and what is outside it is the
reference's boundary — covers it as written. Two answers:

1. **Leave it and name it accurately.** §B3a gains a third unattended route,
   beside `compile lambda! !`; the D121 paragraph loses "under the flag it
   does again"; D115, D120 and D121 gain notes.
2. **Gate it.** That is a deviation from the reference, as D119 was and as
   D120 and D121 were not, and whether the stub is on the word or on its
   evaluating half is part of the question.

Either way the sentence "D120 and D121 are that choice for Bund2's two" is
true and no longer the end of the matter. Criterion 10 cannot notice this, as
it says of itself.

## Should fix

**S1 — `--noio` has a third name that exists only under the flag, and one
that exists only without it. The count is 62, and one of the "551 the flag
does not touch" is removed by it.**

The seventh review's S1 found `stdin` and `stdin.`; the answer added those
two and the method note, and stopped. One file over, the reference registers
`fs.is_file.` as a stub under the flag and `fs_is_file.` — underscore —
without it (`reference/Bund/src/stdlib/functions/filesystem/filesystem.rs:71-75`).
Bund2 reproduces both halves and says so in a comment citing F150
(`crates/bund2-stdlib/src/host.rs`, the `stub!("fs.is_file.", …)` line).
Measured on bundles built `--noio`:

| program | answer |
|---|---|
| `"/etc/hosts" fs.is_file. println` | `bund FILESYSTEM functions disabled with --noio` |
| `"/etc/hosts" fs_is_file. println` | `fs_is_file. not registered` |

`bund2 words` lists `fs.is_file` and `fs_is_file.`, and not `fs.is_file.`.
The re-taken measurement, three-way: 610 names, **59 stubs**, and **one that
is not registered under the flag though it is a word without it** —
`fs_is_file.`. So:

- the by-name list is short by `fs.is_file.`; "61 names answer with the stub"
  is 62;
- "the method above finds every one that is also a word without the flag" is
  true, and the method's two outcomes hid a third: a word the flag *removes*;
- "Of the 551 names the flag does not touch" counts `fs_is_file.`, which it
  touches.

The error is on the safe side again. It is the same list D78 asks for, short
by the same kind of name, one review later, with the defect entry that
describes it already in the register.

**S2 — Under `--noeval` alone, `bootstrap` reads scripts from a file and runs
them, and §B3a does not name it.** The reference's `bootstrap` reads every
stored script and `bund_compile_and_eval`s each
(`reference/Bund/src/stdlib/functions/bund/bund_load.rs:42-50`), and its only
gate is `cli.noio` (`:192-197`). Bund2 does the same through `eval_source`
(`crates/bund2-stdlib/src/world.rs`, `bootstrap`). Measured: a world file
holding the script `40 2 + println`, and a bundle of `"<file>" bootstrap`:

| built | result |
|---|---|
| `--noeval` | prints `42` |
| `--noeval --noio` | `bund LOAD functions disabled with --noio` |

§B3a lists `bootstrap` under "the world file" among `--noio`'s stubs, and
says of `--noeval` alone only that "`url` fetches and the three words above
evaluate the result". `bootstrap` needs no `compile lambda! !`: it is
`bund.eval-file` for a world file, outside the group. The reference's
boundary, by D79 — and a name D78 requires. `load` and `load.lambdas` bring
callable lambdas in from the same file and belong in the same sentence.

**S3 — A breakpoint condition runs in a VM that has neither restriction. A
bundle is spared only by D115, and the RFC's general statement is false of a
`script` run.** `debug.break.if` hands its condition, a STRING, to a child VM
built by `Runtime::new()` (`crates/bund2-cli/src/debugger.rs`,
`evaluate_in_child`), and `Runtime::new` is
`with_options(&HostOptions::default())` (`crates/bund2-runtime/src/lib.rs`).
Measured, `bund2 script --noio --noeval`, standard input closed, no
`--debugger`:

    :w { 1 drop } register
    "w" "fs.cwd println :q bund.eval true" debug.break.if
    w "after" println

prints the working directory — `fs.cwd` under `--noio` — and then
"the condition did not stop: … q not registered", which is `bund.eval`
having evaluated `q` under `--noeval`. The same source as a bundle built
`--noio --noeval` prints `after` and nothing else, because D115 makes the
arming words do nothing.

For this RFC:

- §B3a: "A typed `"1" bund.eval` is refused, because the stub holds wherever
  the word is typed." D120 and D121: the stub holds "in a bundle and in a
  `script` run alike". Not in a condition.
- **D115 is carrying a property nobody assigned it.** It was ruled so that a
  shipped program does not wait at a prompt. It is also the only reason a
  bundle's floor is not bypassed by a child VM, and
  `a_bundles_debugger_words_do_nothing` does not test that. If D115 were ever
  relaxed for one word, D78's floor would go with it, silently.

The defect is in `script` mode and belongs to RFC-0008 and `defects.md`. It
is recorded here because this RFC's sentences cover it and because the next
route of this kind will be found the same way: by listing every place a VM is
built and every place a string is parsed, not by reading the words one at a
time.

**S4 — "The trailer records Bund2's own version" records `0.0.0`, for every
build.** `--inspect` on every artefact made today prints
`built by bund2 0.0.0`; the field is `CARGO_PKG_VERSION`

remark on it. The preservation row "Bund2's own version — Recorded in the
