## Should fix

### S1. "A fact `smysl.kb` loaded stands for its units whatever scope it came from" is false for a ground or dependency the library does not hold

**Location.** §S7, "What a fact stands for", the paragraph after the
per-shape list ("These are the facts `smysl.kb` loads for a scope holding
those units, so a fact `smysl.kb` loaded stands for its units whatever
scope it came from"). The Preservation row "A fact a proof uses" ("so a
fact `smysl.kb` loaded always stands for its units"). D244's note on R8
reads the same way.

**What the RFC says.**

- The table loads `[ grounds U G ]` "one per ground" and `[ deps U D ]`
  "one per dependency". Neither row asks that `G` or `D` be held, unlike
  the `rel` row, which asks that both ends be in scope.
- The stand-for test asks that "every uid position names a unit the
  library holds", and names `G` and `D` as uid positions.

**Evidence.** A unit can ground on, or depend on, a uid the library does
not hold.

- `Store::append` checks only for refused record kinds and duplicates
  before writing (`smysl-graph/src/store/mod.rs:414-450`). A reference to
  an absent unit is reported later, by `report_dangling` as `SMY-E060`
  (`:1019-1029`), not refused.
- SMYSL's own readers treat such a store as ordinary. `effective_status`
  counts only the grounds the store holds
  (`smysl-graph/src/merge/retraction.rs:103-108`), and rule M's pass skips
  a unit whose grounds are all absent, as "`SMY-E060`'s business"
  (`smysl-check/src/passes/epistemics.rs:38-43`).
- Bund2 can write one. §S2 takes a `grounds` or `deps` STRING as a uid
  whenever `Uid::parse` accepts it, and resolves only labels against the
  library (§S2, "Labels in `grounds` or `deps`"). §S8's SM03 row refuses
  "a label MAP whose `uid` names no unit", but has no such case for a
  ground. Copying a unit from one library to another with `smysl.get`
  and `smysl.unit` is the plain way to do it: its grounds keep naming
  units in the first library.

**The consequence.** Take `smysl.kb` over a scope selecting `U`, where `U`
grounds on a uid `G` the library does not hold.

- The KB holds `[ grounds U G ]`, by the table.
- A proof using it reaches `smysl.prove`. The test fails at "every uid
  position names a unit the library holds", so the fact is a program fact,
  and is written as a `speculative` claim.
- So a fact `smysl.kb` itself loaded does not stand for `U`, against the
  sentence above and the Preservation row's "always". The same holds for
  `[ deps U D ]`.
- No criterion distinguishes the two readings. Criterion 18's
  superseded-ground case has `G` held.

The fact stands for `U` alone (the table's last column), and "`G` is among
`U`'s grounds" is a property of `U`'s own record, fixed in its identity.
Requiring `G` to be held adds nothing the per-shape condition does not
already establish about `U`.

**Needed.** One of:

- **(a)** Require held only the positions a fact stands for: `U` in each
  shape, and `From` and `To` in `rel`. `G` and `D` need only be among
  `U`'s grounds or deps. Then the sentence and the Preservation row are
  true. Add a criterion 18 case in M9: `[ grounds U G ]` from `smysl.kb`,
  where `G` is a uid the library does not hold, writes nothing for that
  fact.
- **(b)** Keep the test, and correct the claim: "a fact `smysl.kb` loaded
  stands for its units, but for a `grounds` or `deps` fact naming a uid the
  library does not hold". Say so in the Preservation row, and add the same
  case with the opposite outcome (a `speculative` claim).
- **(c)** Have `smysl.kb` load no `grounds` or `deps` fact naming a uid
  the library does not hold. That changes §S7's table, which is D244 R7 A,
  so it would go to the owner.

(a) is the smallest change and keeps R7's table as it is. Whichever is
chosen, D244's note on R8 ("each uid held") should get a further dated
note, since the register is append-only.

## Notes

- **N1. "Whatever scope it came from" is true of scope, not of time.**
  (§S7, the paragraph after the per-shape list; the Preservation row
  "A fact a proof uses".) The test is judged at write time, and a `rel`
  fact `smysl.kb` loaded can be withdrawn before then. Bund2 itself
  cannot withdraw an edge: §S4 has no such word, and `smysl.parse` skips
  every withdrawal record. But SMYSL's API, or `smysl lib import` with
  `--accept` in another process, can (§Current, "Relations"). The other
  shapes are stable: a unit's schema, status, gist, grounds and deps are
  in its identity, a label binding is never removed
  (`smysl-graph/src/labels.rs:3-8`), and `effective_status` only ever
  moves a unit to `Unfounded` (`smysl-graph/src/merge/retraction.rs:84-86,115-116`),
  so a loaded `effective` fact stays borne out under later retractions.
  Suggest: "stands for its units at write time, unless its edge was
  withdrawn since it was loaded", and the same qualifier on "always" in
  the Preservation row. Nothing in the design changes.
- **N2. The Preservation row and D244's note misstate revision 16.** The
  row says that for a fact whose "schema, status, gist, ground,
  dependency, label or edge the library does not hold … revision 16 let
  it stand for its units". D244's note says "Before revision 17 a fact
  stood for its units whenever its uids were held"
  (`docs/registers/decisions.md:16674-16675`). Revision 16's rule already
  required a `rel` fact's relation to be held, of that kind, and not
  withdrawn (`git show ec81948:docs/rfc/RFC-0014-smysl-corpora.md`, lines
  1432-1438). Drop "or edge" from the row's list, and add a dated
  correction note to D244 (not an edit of the existing one).
- **N3. The `effective` row does not say it is filtered by the scope,
  though the `count` bullet depends on it.** (§S7's table, the
  `effective` row; the "A `count` answer" bullet; criterion 11.) The row
  says the statuses are "computed over the whole library", which answers
  half of the sixteenth review's assumption 2. That the facts are then
  loaded only for units in scope is stated nowhere, yet criterion 11's
  "a scope whose answer is a `count` gives only the six `rank` facts" is
  false on the other reading, for a library holding any retraction.
  Revision 18's answer table says "2 is stated in §S7's table"; it is
  stated only by implication. Add "for a unit in scope" to the row (and,
  for symmetry, to the `unit`, `gist`, `grounds`, `deps` and `label`
  rows, whose "one per unit" carries the same implication).
- **N4. A `ranked` answer is not ranked in a library that holds any
  supersession.** (§S6's answer table; criterion 9; §S7's "A `ranked`
  answer" bullet.) `supersede` returns the answer unchanged only when the
  store has no supersession heads and no forks
  (`smysl-query/src/exec.rs:480-482`). Otherwise it turns a `Ranked`
  answer into a `Scope`, deliberately: "A ranked answer loses its ranking
  here, and has to" (`:497-508`). So a program's ranked query answers
  `kind: "scope"`, with no scores, once the library holds one
  `supersedes` edge. §S7's bullet stays true of the uids, and nothing in
  the design is wrong, but §S6 should say it, with the citation, and
  criterion 9's `Ranked` query needs a fixture with no `supersedes` edge.
- **N5. Which SMYSL call resolves `smysl.kb`'s scope is left to the
  citation.** (§S7, "The scope".) The text says the scope is "parsed,
  planned and run" and cites `scope::resolve`, which also builds the
  saved-query unit (`smysl-measure/src/scope.rs:104-105`) and can fail
  there with `SMY-E460` when that unit does not build
  (`smysl-query/src/saved.rs:417-420`); a bare `plan` then `run` cannot.
  Name the call. If it is `resolve`, say that its refusal is SM04, as
  §S8's "`sq/1` refused the query" would read it. Separately, criterion
  18's `[ unit U S "cited" ]` case should say that `S` is `U`'s schema,
  so that the case turns on the status alone.

## Assumptions the RFC makes but does not state

1. **Every ground and dependency of a unit names a unit the library
   holds** (S1). SMYSL's store does not enforce it, and neither does
   §S2.
2. **Nothing withdraws an edge between `smysl.kb` and `smysl.prove`'s
   write** (N1). Bund2 cannot; SMYSL's API and `smysl lib import` can.
3. **`effective` facts are loaded only for units in scope** (N3).
   Criterion 11's `count` case depends on it.
4. **A ranked query answers `Ranked`** (N4). It does only in a library
   with no supersession.
5. **Every uid a scope's answer names is a unit the store holds.** §S7's
   table builds a `unit` fact for each. This review did not establish
   what a `from texts` scope's answer names; if it can name a manifest or
   part id, `smysl.kb` needs a rule for it. Worth a line in M8's first
   step.
