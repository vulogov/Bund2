RFC and SMYSL were read first, and the earlier reviews only afterwards, to

## Blocking

### B1. Five SMYSL commands append to a library without any lock, so §S9's guarantee and Q57's narrowing rest on a false premise

§S9 says: "Every SMYSL writer takes the library lock first
(`smysl-text/src/lock.rs:30`), so once Bund2 holds it, no honest writer
can add a shard." Q57's revision-6 note repeats it. §A says SMYSL's
commands "hold the same locks around" `append_records`.

At 4f5ecb9, these commands call `Library::append_records` on a library
they opened with `Library::open`, and never call `acquire_all`:

| Command | Open | Append |
|---|---|---|
| `q --library --save` | `smysl:src/main.rs:6297` | `:6324` |
| `ask --save` | `Corpus::open`, `:13824-13829` | `:6702` |
| `measure --save` | `:7348` | `:7579` |
| `assess` | `:7780` | `:8094` |
| `same-as` | `Corpus::open` | `:14019`, `:14162` |

The only `acquire_all` calls in `src/main.rs` are `:8628` (`with_library`)
and the five `text` subcommands at `:12656,12790,12914,13033,13104`.
SMYSL's own comment assumes otherwise: "every library-wide writer holds
the library lock first" (`smysl-text/src/library.rs:765-769`). Its CLI
breaks that assumption.

These are the commands a user is most likely to run against a library a
Bund program also writes: query, ask, measure. What follows:

- **The re-open (§S9 step 4) does not see them.** They write at any time,
  including between Bund2's second open and its append. So Bund2's
  de-duplication, its "already attested" rule, its clock's `prev` and its
  "already retracted" test can all rest on a stale library.
- **A Bund2 write can destroy a record an unlocked writer is appending.**
  `ShardLog::read` counts any undecodable tail as `torn`
  (`smysl-text/src/shards.rs:239-251`). Before its next append,
  `ShardLog::append` cuts the file back to the decoded length
  (`:376-379`). If Bund2 opens while `smysl measure --save` is part way
  through a record, it reads that partial record as a torn tail and
  truncates it. The other process then writes the rest at the new end.
  Neither side reports anything, and no SM07 is raised.
- **Q57 was narrowed on this premise.** Its register entry now reads
  "what remains is a writer that does not [take the lock]". In fact
  SMYSL's own CLI is that writer.

**Needed:**
1. Withdraw the claim in §A, §Current, §S9 and Q57, and cite what is
   true.
2. Say what Bund2 can promise. It can promise serialisation against
   writers that lock: Bund2 itself and SMYSL's `text` and `lib`
   commands. It cannot promise it against `q`, `ask`, `measure`,
   `assess` or `same-as`.
3. Re-open Q57, or file a new question, with the truncation hazard named.
4. Ask SMYSL to lock those five commands, as a new upstream item, U9.
5. Add a Preservation row. Running SMYSL's saving commands on a library
   a Bund program writes is not safe at 4f5ecb9, and Bund2 makes it no
   safer.

Whether Phase 1 ships before U9 lands is the owner's decision. The RFC
must not record it as a non-issue.

### B2. The implementation plan assigns criteria to milestones that come before the words those criteria exercise

"Every milestone ends with its criteria passing." Several cannot:

- **M1** adds the five CI steps, among them `cargo nextest run -p
  bund2-cli --features smysl --test smysl_demo` (§S1). `smysl_demo.rs`
  arrives in M10. Until then nextest finds no such test target, so CI
  fails from M1 through M9.
- **M2** claims criterion 4. Criterion 4 compares the uid that
  `smysl.unit` answers, and `smysl.unit` is built in M4.
- **M2** registers `smysl.create`, which §S4 marks as a write (W). §S9's
  locks arrive in M3, whose stated reason is that "it comes before any
  writing word, so that no word ever writes without §S9's locks". The
  plan contradicts its own reason.
- **M3** claims criterion 15's lock, thread, panic, failed-append and
  re-open cases. Every one of them appends units:
  - "a write is SM07";
  - "each append 250 units";
  - "a write that panics";
  - "an append that fails";
  - "a unit appended by another process".

  The appending words arrive in M4.
- **M4** claims criterion 6, which finds every unit "by `smysl.get` and
  by `smysl.query`". `smysl.get` arrives in M5 and `smysl.query` in M7.
- **M4** claims "15's attestation case". That case ends with "that
  handle may then retract it", and `smysl.retract` arrives in M5.

**Needed:** one of two fixes.
- Move each criterion to the first milestone where every word it uses
  exists. Criterion 4 and 15's write cases would go to M4, criterion 6 to
  M7, and 15's attestation case to M5.
- Or merge M3 into M4, and move `smysl.create` to it.

Add the `smysl_demo` CI step in M10, not M1.

### B3. Criterion 15's failed-append and re-open cases name a mechanism the design does not have and cannot reach

§S9 defines `smysl-panic-probe` as one thing. It "makes a write panic
after its mutex and SMYSL's locks are taken, and before it appends."
Criterion 15 then uses the same probe for two more things:

- "an injected I/O error after the first shard is written";
- to "pause the write" between its first open and its locks while a
  second process appends.

The first cannot be done from Bund2. The shard writes happen inside
`Library::append_records`'s loop (`smysl-text/src/library.rs:1364-1376`),
which Bund2 calls once and cannot enter. No Bund2 hook exists between
the first shard and the second. The second needs a pause point and a
second process. The RFC designs neither, and states no agent for the
other process (see N9).

The failed-append case is R20's only test of its "failed append" half.
As written, it cannot be built.

**Needed:** name a mechanism that exists. For example:
- make the second shard's log path unwritable before the append, so
  that `ShardLog::append`'s `OpenOptions::open` fails
  (`smysl-text/src/shards.rs:371-375`);
- give the probe a defined pause, released by a file the test creates,
  and name the helper binary that appends as the second process.

The batch also has to span two shards. Routing puts a unit citing a
part into its alias's shard (`smysl-text/src/shards.rs:456-466`), so the
fixture needs a text added first and a unit citing one of its parts.

## Should fix

### S1. SMYSL's lock is a hard link, not a `create_new` file

§Current ("The locks") and Q50's register answer say a lock is "a file
created with `create_new`" (`smysl-graph/src/lock.rs:3-5`). The code
works differently (`:150-158`):

1. it writes `.<name>.<pid>.<n>` beside the lock;
2. it `hard_link`s that file to the lock path;
3. it removes the staged file.

Only `AlreadyExists` becomes `SMY-E445` (`:165`). Any other error is
`LibError::Io` (`:177`). On a filesystem without hard links, every write
therefore fails with an I/O error, not SM07. The fifth review's
assumption 3 accepted the `create_new` reading, and so did the revision 2
answer.

**Needed:** correct the description. Say which code an `Io` from
`Lock::acquire` becomes; SM02 is the natural one. State the assumption
that the library sits on a filesystem with hard links.

### S2. `lang` is required in practice, but the spec table says it may be absent

The `smysl.text.add` spec table says `lang`: "no — the reader's own
answer". `Library::add` refuses when neither the caller nor the reader
names a language. It returns `LibError::BadParam` with "neither the
source nor the caller named a language"
(`smysl-text/src/library.rs:1193-1203`).

Neither enabled reader names one:
- `ReadOutput.lang` starts `None` (`smysl-text/src/readers/mod.rs:253`);
- it is set only through `with_lang` (`:268-269`);
- `txt.rs` and `md.rs` never call it;
- language detection is `detect`, which §S1 leaves off.

So every `smysl.text.add` without `lang` is refused.

**Needed:** make `lang` required for `txt/1` and `md/1`, with SM03 when
it is missing, or name the SM02 that follows. Criterion 6 should then
pass `lang`.

### S3. R20's guard is unspecified for `smysl.text.add`, and as written a missing `lang` would lock the library for good

R20 keeps the locks "after a failed append", meaning an error that
`append_records` returns after `check_loggable`. `smysl.text.add` does
not call `append_records`. It calls `Library::add`, and inside that call
the order is:

1. refusals that write nothing, such as S2's `BadParam`;
2. objects written (`smysl-text/src/library.rs:1278-1281`);
3. `append_records` for the manifest (`:1317`).

Bund2 cannot run `check_loggable` first, because the manifest is built
inside `add`. The RFC does not say what the guard does on an `Err` from
`add`:

- if it keeps the locks on every error, then S2's refusal leaves the
  library locked until an operator runs `bund2 smysl-unlock`;
- if it drops them on every error, then an `add` that failed inside
  `append_records` releases a half-written library, which R20 rejects.

**Needed:** a rule the guard can apply. For example, compare
`Library::stamp()` (`smysl-text/src/library.rs:993-995`) before and
after the failed call. If it grew, keep the locks; if not, drop them.
This rule would also cover `append_records` without relying on
`check_loggable`. Add a test that a refused `add` leaves no lock.

### S4. `smysl.rel` and `smysl.append` can write a `retracts` edge, bypassing `smysl.retract`

`effective_status` retracts the `to` of **any** `retracts` relation
whose target is present (`smysl-graph/src/merge/retraction.rs:83-88`).
Neither `from = to` nor authority is checked; only `plan_retraction`
checks authority (`:181-209`). §S4 lets `smysl.rel` and `smysl.append`
write any relation, and criterion 5 requires all fourteen kernel kinds,
so `retracts` is included.

A program can therefore retract any unit, without claiming another
agent's id, and with no "already retracted" check. The edge it writes
also carries Bund2's attestation, unlike the unattested edge `smysl.retract`
writes, so the same retraction can exist as two different records.

R21 states that authority is advisory because agent ids are
self-asserted. That is a different, narrower hole, and this one is not
covered by the ruling.

**Needed:** a decision, taken to `docs/registers/decisions.md` as
CLAUDE.md requires for an unplanned point. Either:
- refuse `retracts` in `smysl.rel` and `smysl.append` with SM03, naming
  `smysl.retract`;
- or state the bypass beside R21, with a Preservation row.

Criterion 5's documents follow whichever is chosen.

### S5. "A variant Bund2 has no arm for cannot occur at the pinned revision" is false

§S2 maps a variant with no arm to `Error::internal`, which says the
defect is Bund2's (D37). These variants exist at 4f5ecb9 and are reached
by **data**, from libraries a later SMYSL wrote:

- **`SourceKind::Unknown`.** The raw code is kept on `SourceRef` and
  reported as `SMY-W409` (`smysl-core/src/types/epistemics.rs:180-191,432-439`).
- **`RelKind::Extension(String)`** (`smysl-core/src/types/relation.rs:34`).
  §S8's SM05 "unknown relation kind" does not say whether an extension
  kind is accepted when written, or how one reads back.
- **`ProfileEstimator::Unknown`** (`smysl-core/src/types/estimate.rs:228-230`).
  §S7 handles this one.

**Needed:**
- Give `SourceKind::Unknown` an arm: `opaque = true`, with the kind read
  back as its code.
- Give extension relation kinds an arm, and decide whether `smysl.rel`
  accepts them.
- Keep `Error::internal` for a variant added after 4f5ecb9, and only for
  that.

### S6. The query and dossier environment is part of the design and is left to Q55

§S5 and §S6 do not say which ports Bund2's `Env` binds. Two things
depend on it:

- **`ask` needs entities.** It returns `AskError::NoEntities` without
  `env.entities` (`smysl-query/src/dossier/mod.rs:829-830`), so
  `smysl.dossier` fails unless Bund2 binds entities.
- **Time stages need times.** Without `times`, the time stages "are then
  refused by name" (`smysl-query/src/plan.rs:54-57`).

SMYSL's own `q --library` binds both, through
`Env::new(...).with_times(&scope).with_entities(&scope)`
(`smysl:src/main.rs:6313-6315`).

Two other inputs are also unstated, and criterion 10's "what the direct
calls give" depends on all of them:
- the `PlanOptions`;
- `measure::run`'s `base: &Recipe` (`smysl-measure/src/lib.rs:246`).

Only Q55's answer mentions `with_times` and `with_entities_of`.

**Needed:** state the `Env`, the `PlanOptions` and the base `Recipe` in
§S5 and §S6. Criterion 10 should name them.

### S7. Some things the RFC builds have no criterion, and one criterion is impractical

These are built, and no criterion checks them:
- `smysl.salience` and `smysl.pack`;
- `smysl.rel` and `smysl.label` as standalone words, which criterion 5
  reaches only through `smysl.append`;
- the `bund2 check` arms for the `smysl` conditional and for
  `smysl.prove`'s 4 → LIST. M7 and M9 build them, and criteria 9, 12 and
  16 do not test them;
- `features_built_in` recording `smysl`;
- `smysl.parse` and `smysl.agent` working under `--noio`;
- a run's `warnings` reported as `Warning` (D36);
- an `observed` above `i64::MAX` round-tripping as a STRING.

Criterion 14's "over-cap `text`" needs a STRING over
`Caps::default().input_bytes`, which is 1 GiB
(`smysl-text/src/limits.rs:79`). That is 1 GiB of memory in a nextest
run with a time bound (F141). The `path` form checks the length before
reading the file (§S4), so a sparse file made with `set_len` tests the
same refusal at no cost.

### S8. The retraction edge's reason cites a CLI path that cannot write to a library

§S4 keeps the retraction edge unattested "so that a Bund2 retraction and
a CLI retraction are the same records". SMYSL's `retract` cannot write
to a library:

- it writes through `persist`, which calls `std::fs::read(path)` on the
  `--store` argument itself (`smysl:src/main.rs:4500,4537`);
- that argument is a library's root directory, which `fs::read` cannot
  read;
- no SMYSL test retracts in a library: `tests/cmd_retract.rs` has none.

So within a library there is no CLI retraction to match. The design may
still choose no attestation, but this reason does not support it.

**Needed:** restate the reason, for example as matching the record shape
`plan_retraction` simulates (`smysl-graph/src/merge/retraction.rs:218`).

## Notes

- **N1. `Library::open` writes.** Each open runs `enforce_z`, which
  unlinks the objects of redacted parts
  (`smysl-text/src/library.rs:370,676-698`), and takes no lock to do it.
  "None of these writes" (§S5) and "reads are not locked" (§S9) are
  therefore true of the logs, not of the library. Add a Preservation
  row.
- **N2. A write can raise a library's layout.** When a write creates a
  shard in a layout-1 library, `append_records` rewrites the `LIBRARY`
  marker to `smysl/library/2` (`smysl-text/src/library.rs:1355-1361`).
  Layout 2 dates from 1.10.0 (`smysl:CHANGELOG.md:1323-1325`), so a
  Bund2 write can make a library unreadable to SMYSL releases before
  1.10. Add a Preservation row.
- **N3. `append_records` can create a shard no lock covers.** Routing
  sends a unit citing a part to its alias's shard
  (`smysl-text/src/shards.rs:456-466`), and the append creates that log
  if it is new (`smysl-text/src/library.rs:1364-1369`). SMYSL relies on
  the library lock for this (`:765-769`). §S9's "every write is made
  under the shard locks" overstates; the library lock is what protects
  such a write.
- **N4. Q51 can be narrowed from the source.**
  - Shards written before the failure keep their records.
  - The failing shard may hold a torn tail. Reading tolerates it, and the
    next append cuts it (`smysl-text/src/shards.rs:239-251,376-379`).
  - So after `bund2 smysl-unlock`, the next write silently discards the
    partial record.
- **N5. Primary shards.** A library whose shards `lib migrate --primary`
  moved into the unit store cannot be opened without `store-redb`, which
  §S1 leaves off. `read_primary` returns `Io`
  (`smysl-text/src/shards.rs:305-321`). Name the refusal (SM02), and
  state the assumption.
- **N6. Relation read-back.** `note` is a uid, not text
  (`smysl-core/src/types/relation.rs:182-183`), so §S2's row should say
  STRING uid. A relation's `extra` (`:185`) is dropped without setting
  `opaque`, unlike a unit's.
- **N7. "An empty gist".** SMYSL refuses a gist that is empty *after
  `trim`* (`smysl-core/src/types/unit.rs:148`), so a gist of spaces is
  refused too.
- **N8. A different `Op` from SMYSL's tools.** SMYSL's own computed units
  are attested `Op::Transformed` (`smysl:src/main.rs:7568-7574,8086-8092`).
  §S4 attests proof conclusions `Authored`. Rule T reads only the rung
  (`smysl-check/src/passes/trust.rs:33-38`), so nothing fails. Say why
  `Authored` is used.
- **N9. Criterion 15's re-open clock.** `prev` is this agent's newest
  clock (§S4). "Its clock is later than the other process's" therefore
  holds only if the other process attests as the same agent. Say so in
  the criterion.
- **N10. §S7.1's uid shortening.** The RFC does not say how a STRING is
  recognised as a uid to shorten. A `b3:` prefix that parses as a
  `UidPrefix` would do; an atom such as `"b3:x"` should be left alone.
- **N11. RFC-0013 conventions.**
  - Under RFC-0013 §S11, a missing `lambda` slot means an empty lambda.
    For the `smysl` conditional, a missing slot is SM03. State the
    difference.
  - RFC-0013 §S12 leaves E00 and E40 unprefixed, but §S7 says
    `smysl.prove`'s refusals carry `SMYSL.PROVE: `. Say that E00 and E40
    keep their house texts.
- **N12. SM06's text.** `bund_models.rs:125` reads
  `bund SAVE.MODEL functions disabled with --noio`
  (`reference/Bund/src/stdlib/functions/bund/bund_models.rs:125`).
  SM06's text follows that pattern; it is not the same house text, and
  "as `bund_models.rs:125` writes it" overstates.

## Preservation: what is missing

- Concurrent use with SMYSL's saving commands (B1).
- Read words can unlink redacted objects (N1).
- A write can raise a layout-1 library to layout 2 (N2).
- A lock cannot be taken on a filesystem without hard links (S1).
- A `retracts` edge written by `smysl.rel` or `smysl.append` (S4).

## Consistency

- **RFC-0013.** §S7's node table matches RFC-0013 §S15 and D230: `call`
  transparent, `once` rule-shaped, markers read back as STRING. §S6's
  `eval_lambda` runner matches §S11. The two differences are in N11.
- **ERRATA.** `docs/research/ERRATA.md` does not mention SMYSL or
  RFC-0014.
- **Registers.** Q50's answer says the lock is a `create_new` file (S1).
  Q57's revision-6 note rests on the claim B1 withdraws. Both need dated
  notes.

## Assumptions the RFC makes but does not state

1. **No SMYSL process writes the library without its lock** (B1).
2. **The library sits on a filesystem with hard links** (S1).
3. **The enabled readers supply a language** (S2).
4. **No `Err` from `Library::add` comes after a log has grown**, or the
   guard can tell when one did (S3).
5. **No library holds data from a SMYSL later than 4f5ecb9** (S5).
6. **The library has no primary shards** (N5).
7. **A prefix of an NFC string, followed by `…`, is still NFC.** This is
   true. §S7's claim that SMYSL's normalisation leaves the fitted gist
   unchanged depends on it, and the RFC should say so.
