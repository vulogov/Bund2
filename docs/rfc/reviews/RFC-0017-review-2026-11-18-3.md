## Should fix

### SF1. The q 0.0 rule is tested on the one word that makes no NONE, and not on the two that do

**What the RFC says.** S2 makes every NONE a frame word *makes* q 0.0, and names the makers: "a CSV `na` field, a `"left"` join's unmatched cell" (RFC:262-265).

**Where the test sits.** The only criterion clause is "every NONE the word makes has q 0.0". It sits in criterion 5's `frame.aggregate` bullet (RFC:900-901). But `frame.aggregate` makes no NONE:
- its NONE group key is "the first of its rows' cells in row order, keeping its type" (RFC:476-478), a cell it was given;
- a statistic over an empty group refuses (RFC:456-459);
- `.dropped` is INTEGERs.

So that clause can never fail.

**What goes unchecked.** The two words that do make NONE have no q check:
- the `frame.join` bullet (RFC:902-906);
- criterion 6 (RFC:915-948), for both the `na`-string field and the one-column empty line.

`frame_eq` ignores q (RFC:304), so every frame comparison passes whether these NONEs carry 0.0 or `BundValue::none()`'s 100.0. An implementer who writes `BundValue::none()`, the obvious constructor, passes every criterion.

**A looser sentence elsewhere.** S1 still says cells a word makes, "a parsed field" among them, "carry q as their constructor gives it" (RFC:235-237). Read beside S2, it leaves the constructor open.

**Fix.**
- Move the clause to the `frame.join` bullet: under `"left"`, an unmatched row's NONE has q 0.0.
- Add to criterion 6: an `NA` field's NONE and a one-column empty line's NONE have q 0.0.
- In S1, say "a NONE as S2 says; other cells as their constructor gives them".

### SF2. Several operand faults outside the frame check have no listed text, and `frame.with`'s name fault gets a numbered one

D256 S3 asks that "every refusal [be] listed with its text" (RFC:209-210). S8 lists texts for a missing column name, a bad index (row 753) and a bad `levels` or `list`. It has no row for a non-frame operand of the wrong *type*:
- `frame.select`'s or `frame.complete`'s `names`, `frame.take`'s `rows`, `frame.aggregate`'s or `frame.join`'s `by`, or `frame.new`'s `names`, given as an INTEGER rather than a LIST;
- `frame.column`'s or `frame.factor`'s `name` given as a non-STRING;
- `stats` not a LIST at all. Row 760 covers a malformed *entry*, not the operand.

**`frame.new`'s two operands.** SF3's mapping makes `frame.new`'s name faults use row 742. Row 742's texts (`column name 3 is <summary>`, `a repeated name "x"`) say nothing about `names` itself not being a LIST, or `columns` not being a LIST of LISTs. Row 744's `column "x" is <summary>` needs a name to put in the text.

**`frame.with`'s new name.** Row 742 renders its fault as `name is outside frame.with's domain: column name <k> is <summary>`. The RFC never says what `k` is for a name that is not yet a column: ncol + 1, or the position it replaces? Two implementers would number it differently.

**Fix.** Add one row:

| Rule | Code | Text |
|---|---|---|
| an operand of the wrong type (a `names`, `by`, `rows`, `stats` or `columns` not a LIST; a `name` not a STRING; `frame.new`'s `columns` holding a non-LIST) | E101 | `<operand> is outside <w>'s domain: <summary>` |

Also say that `frame.with`'s `name` is checked by this row, plus an `empty name` text, before the frame check of the answer. That avoids the numbered form.

## Notes

**N1. Step 1 does not name its "control character" class** (RFC:711-714). Rust's `char::is_control` is the general category Cc: U+0000–U+001F and U+007F–U+009F, NEL U+0085 included. `escape_debug`, the obvious shortcut, differs in two ways:
- it writes `\0` and `\'`;
- it also escapes non-printables outside Cc: U+2028 and U+2029, the line and paragraph separators, and bidi controls.

Some renderers treat U+2028 and U+2029 as line breaks. Say "a character for which `char::is_control` holds", and say whether U+2028 and U+2029 are escaped too.

**N2. The options rows' `<value>` is unstated for a non-STRING value** (RFC:774, :776: "the key and a STRING value rendered as the preamble says").
- `na`, `factors` and `descending` take LISTs. A wrong one, such as `{ na: [ 1 ] }` or a `descending` LIST holding a STRING with a line break, needs a rule. Presumably `<summary>`, but then RFC:723-724's "no interpolated value … breaks a line" excludes it. Say so.
- The new reader leaves two choices open:
  - which keys count as "known", for `an unknown key` against `a key "k" <w> does not take`: the union of the six frame keys (`header`, `na`, `factors`, `sep`, `descending`, `how`), or something else;
  - which fault wins when several keys are faulty. `opts.rs` takes the MAP's sorted key order.

  Two implementers can differ on both. One sentence each settles them.

**N3. The wrong-value text has a different shape from every existing options word's.**
- `opts.rs` puts the key in the operand slot: `mu is outside stat.test.t1.opts's domain: <value>` (`domain(word, k, …)`).
- RFC:776 and :774 put `opts` there and the key in the detail: `opts is outside <w>'s domain: sep is <value>`.

Both satisfy "E101 naming the key" (RFC-0016 `:198-200`), so this is not a contradiction. But a program or a TUI matching refusal texts sees two shapes for one rule. Either adopt `opts.rs`'s shape, or add the difference to the `[author]` list.

**N4. No criterion checks any options text.** Criterion 6's `sep` cases (RFC:937-938) check the code only. No criterion exercises `an unknown key`, `a key … does not take` or `<key> is <value>`, so row 776, the text revision 9 wrote, can drift. Add one case of each to criterion 6, for example `{ how: "inner" }` to `frame.csv.parse`.

**N5. Criterion 6's first bullet now mixes a refusal into a fixture that must parse.** "a quoted `"007"` (in a numeric column E103 …)" (RFC:917-918) sits in the one text whose other assertions read each column's kind and cell type. An E103 refuses the whole parse, so that text cannot also answer a frame. Say that the `"007"` case is its own text (for example `x\n1\n"007"\n`), and keep a quoted `"007"` in a string column in the fixture.

**N6. S4's D108 citation could add the code.** RFC:380-381 cites the ruling. `crates/bund2-stdlib/src/sort.rs`, `float_order` (`partial_cmp`), is where "`-0.0` and `0.0` compare equal" is observable today. Citing it grounds the claim in what Bund2 does, not only in what D108 says. Optional.

## What the RFC assumes and does not state

- **The options reader's key universe and its fault order** (N2).
- **The control-character class** step 1 escapes (N1).
- **That a wrong-typed non-frame operand is E101 with `<summary>`** (SF2).
- **What E112 says when `frame.filter`'s lambda leaves nothing.** `ask` answers `None` for an empty scratch stack (`bridge.rs`, `ask`), and `dynamics.rs`'s `call` writes `left nothing`; RFC:371-375 says only "a result other than a BOOL" (carried).
- **That a final line without a terminator is a record** (carried; RFC:549-551 speaks of terminators only).
- **That an `na` string matches by exact bytes**, case-sensitive and untrimmed (carried).
- **That `frame.text` of a frame with columns and no rows prints its header row alone** (carried).
- **That a row MAP per row in `frame.filter` and `frame.rows` is affordable at Tier 0** (carried).
