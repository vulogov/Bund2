## Blocking

### B1. `mva.pca` with `scale` true and `center` false does not divide by the sd (§S3, RFC:447-448)

§S3 says the columns are scaled "by the column sds on n − 1, the function
behind `stat.sd`", and offers `center` and `scale` independently. R does
not do that.
- `prcomp.default` calls `scale(x, center = center, scale = scale.)`
  (`prcomp.R:27`).
- Base R's `scale` divides an uncentred column by its root mean square,
  √(Σx²/(n − 1)), and not by its sd.
- On the owner's R 4.6.2, for `cbind(c(1,2,4), c(3,5,9))`, the scales
  are:

  | Call | Answer |
  |---|---|
  | `prcomp(x, center = FALSE, scale. = TRUE)$scale` | 3.240370 7.582875 |
  | `apply(x, 2, sd)` | 1.527525 3.055050 |
  | `sqrt(colSums(x^2)/2)` | 3.240370 7.582875 |

So a port that follows §S3 answers different `sdev`, `rotation` and `x`
from R's whenever `center` is false and `scale` is true. Criterion 3
would not catch it, because it tests `USArrests` only with centring.

The zero-column refusal also differs between the two cases:
- R stops on `sc == 0` (`:30-31`);
- uncentred, that happens only for an all-zero column, not for any
  constant column, while §S3 says "a column whose sd is 0".

**Fix:**
- State R's rule: the sd when centred, √(Σx²/(n − 1)) when not.
- Make the refusal condition match R's in both cases.
- Add the uncentred, scaled case to criterion 3.

### B2. `cluster.dist` misstates R's Canberra and binary distances (§S5, RFC:493-496)

§S5 makes two claims about R's `dist` that are wrong.

**First claim:** "With no missing values, R's rescaling for dropped
coordinates never applies."
- Canberra skips a coordinate where both values are zero
  (`distance.c:122`).
- It then counts only the coordinates it kept, and rescales by
  `dist /= count/nc` (`distance.c:135-136`).
- So the rescaling applies with no missing value at all. On R 4.6.2,
  `dist(rbind(c(0,1), c(0,3)), "canberra")` is **1**, where an
  unrescaled sum gives 0.5.

**Second claim:** "a pair with no coordinate counted, where R answers NA,
is E101".
- That holds for Canberra: two all-zero rows answer NA
  (`distance.c:135`).
- It does not hold for binary. With no missing value, `total > 0`, and
  `count == 0` returns **0** (`distance.c:166-167`). On R 4.6.2,
  `dist(rbind(c(0,0), c(0,0)), "binary")` is 0.
- So a port that refuses binary's empty case refuses where R answers 0,
  which §S5 does not list as a departure.

**Fix:**
- State Canberra's rescaling as part of the algorithm.
- Restrict the E101 to Canberra's all-zero pair, or record it as a
  departure.
- Make criterion 4 include zero coordinates, for Canberra and binary.

**Fix:**

- Or name the committed fixture script that will hold each one, and the
  generator and seed behind "1000 values".

### B4. MANOVA admits inputs whose F has zero or negative degrees of freedom (§S7, RFC:583-586)

§S7 admits any input with N − g ≥ p and a full-rank E, and takes each
statistic's F "line for line" from `mlm.R:363-406`. Under that rule:
- Hotelling–Lawley's denominator df is `2(s·n + 1)`, with n = ½(N − g −
  p − 1) (`mlm.R:392-396`).
- At N − g = p this is 2 − s, which is 0 for s = 2 and negative for
  s > 2.
- On R 4.6.2, for 5 rows, p = 2 and three groups,
  `summary(manova(y ~ g), test = "Hotelling-Lawley")` answers:
  - approx F **0**, on 4 and **0** degrees of freedom;
  - `Pr(>F)` **NA**, because `ok` fails (`manova.R:117-119`).

Bund2 cannot answer that (B12: no NaN from finite operands, and D272
says an F test answers its df), and §S7 does not say what it does
instead. Pillai's F divides by s − V (`mlm.R:372`), which needs the same
statement for the numerically saturated case. Criterion 11's "answers or
refuses" would then be met only by an unspecified behaviour.

**Fix:**
- State the refusal: E101 when a statistic's df1 or df2 is not
  positive.
- Or tighten the admissibility condition.
- Add the case to criterion 6.

## Should fix

### SF1. D278's first choice rests on a false claim about `frame.factor` (§S1, RFC:418-421)

§S1 orders groups "as `frame.factor` orders levels: INTEGERs ascending,
STRINGs by bytes (D253 P7)". That does not match the code:
- `frame.factor` refuses a numeric column: `factorable` answers E101 for
  `Kind::Numeric` or `Kind::Logical` (`frame/reshape.rs`, `factorable`).
- A factor's levels are STRINGs only (`make_factor`), so INTEGER
  ordering has no `frame.factor` precedent.
- A factor made by `frame.factor.levels` keeps the user's level order
  (`frame_factor_levels`). A LIST of that column's labels loses that
  order, and `mva.lda`'s `levels` would then disagree with the frame's.

V2's ruling and D278 are being asked on this premise. Before D278 is
ruled, the RFC should:
- restate the INTEGER rule as its own choice;
- say what happens to a factor column's declared level order, for
  example "lost; pass labels in the order wanted", or an option
  `levels`.

### SF2. MANOVA's rank test is not "the same 10⁻⁷" as R's (§S7, RFC:580-582)

**The tolerance is not on the same scale.**
- `qr(…, tol = 1e-7)` is LINPACK's `dqrdc2`, whose tolerance compares
  column *norms* (lengths).
- A Cholesky pivot is a squared quantity, if the pivot is L_jj², or a
  length, if it is L_jj. §S7 does not say which.
- With the pivot as L_jj², the equivalent threshold is about 10⁻¹⁴, not
  10⁻⁷.

**The scaling is also misdescribed.**
- §What R does (RFC:294-295) says R floors "a scale below 10⁻⁶ of the
  total sum of squares".
- R compares `sc = √diag(E)` with `√sss · 10⁻⁶`, where `sss` is each
  variable's E_jj + Σ H_jj (`manova.R:98-101`). The floor is per
  variable, and on the square root.

**Fix:**
- State R's condition exactly.
- Define the pivot quantity.
- Say plainly in D278's sixth choice that the threshold is not R's, or
  choose one that corresponds.

### SF3. `cluster.hclust`'s distance operand is unchecked, and the port has a sentinel and an index hazard (§S5; §S11)

§S4 says how `mva.mds` checks D (as `taxa`). §S5 says nothing about
`cluster.hclust`'s D beyond the cap. R's Fortran makes that a problem:
- **The sentinel.** It uses `INF = 1.D+300` as its sentinel
  (`hclust.f:47`).
- **The stale index.** It initialises `JM = 0` (`:53`), and keeps the
  nearest neighbour only on a strict `DMIN .GT. DISS(IND)` (`:80`).
- **The failure.** A row whose distances are all ≥ 10³⁰⁰ leaves
  `NN(I) = 0`. A later step can then merge index 0, out of range in a
  1-based port, and a panic or a wrong merge in Rust.

The ports also overflow from finite input:
- `cluster.dist` can answer +∞ from finite cells. For example, the
  Euclidean distance between rows holding ±10²⁰⁰ overflows.
- Ward's update (`hclust.f:134-136`) can overflow too.

B12 forbids either. `Refusal::Overflow` (E114) exists, and §S1's "no new
code" is compatible with using it.

**Fix:**
- Specify `cluster.hclust`'s D checks: square, symmetric, zero
  diagonal, non-negative, and finite below the sentinel.
- Specify E114, or E101, for an overflowing distance or update.

### SF4. `cutree`'s k path does check its argument (RFC:257-258)

"A cut into k groups performs the first n − k merges and checks nothing
(`:35-40`)". `cutree.R:37-39` stops unless 1 ≤ k ≤ n. The design
(§S5, k in 1 … n) matches R, so only §What R does is wrong.

### SF5. The Preservation analysis misses the shared helpers the design reuses (RFC:720-737)

The design reuses existing private functions. Each needs extracting or
generalising, which can change an existing word's refusal order or text,
and the Preservation table has no row for any of them:
- **`taxa`** (`phylo.rs`) takes `v: &[BundValue]` and reads a names
  operand at `v[1]`. It caps at `TAXA_CAP` = 2000. §S4 wants its checks
  with no names and §S11's cap of 5000, so `taxa` must be split.
- **`linalg_eigen_sym`'s body**, "`linalg.eigen.sym`'s function" (§S4),
  is today the native itself.
- **`describe.rs`'s `quantile`** answers a `BundValue`, not an f64
  (§S9's "type-7 function").
- **`optim.rs`'s `zeroin`** (§S9).

§Current behaviour also says `taxa` refuses with "E101, E107". A
non-square MATRIX is `Refusal::Disagree`, which is E102
(`refuse.rs`, `Refusal::code`).

**Fix:**
- Add a row: "helpers extracted from `phylo.rs`, `linalg.rs`,
  `describe.rs` and `optim.rs`: preserved exactly, each existing word's
  tests unchanged".
- Correct the code list.

### SF6. `stat.hist` and `stat.ecdf` depart from R in ways the RFC does not state (§S10)

The departures:
- **Non-finite values.** R drops them silently (`hist.R:36`), and
  `ecdf` drops NA by `sort` (`ecdf.R:25`). §S10 does not say whether
  Bund2 refuses, which B12 and §S9's precedent suggest.
- **Unsorted breaks.** R sorts a user's breaks (`hist.R:48`). §S10
  refuses breaks that are not increasing.
- **`include.lowest` false with a rule or count.** R forces it to true
  with a warning (`hist.R:50-53`). §S10 does not say what Bund2 does.
- **Large class counts.** R caps a count above 10⁶ at 10⁶ with a warning
  (`hist.R:77-81`). §S11 gives `stat.hist` no cap at all, so an INTEGER
  of 10¹² reaches `pretty` and allocates a breaks vector of that size.
  D39 asks for an E111 before the work.

**Fix:** state each departure and add `stat.hist`'s cap to §S11.

### SF7. `mva.lda.predict`'s departures and dependencies are unstated (§S8)

- **`dimen`:** R clamps it silently, `min(dimen, length(object$svd))`
  (`lda.R:260`). §S8's "INTEGER, 1 … r" reads as a refusal above r, a
  departure the RFC does not list.
- **The scores:** they are centred on the prior-weighted mean, under the
  *prediction's* prior (`lda.R:255-258`). So `x` changes when `prior`
  is given. §S8 calls them "the discriminant scores" without saying so.
- **A prior of 0:** it is admitted ("non-negative"). The plug-in then
  takes log 0 = −∞ (`lda.R:264`), and the posterior is 0 only through
  exp(−∞). §S8 should say that the zero is answered as 0, not through an
  infinite intermediate the family's rules forbid.

### SF8. Criterion 3 contradicts V14's ruling (RFC:813-819, :918)

V14 A, ruled by D277, puts `mva.pca`, `mva.mds` and `cluster.dist`
under "definitions … with R as a second check". Criterion 3 checks
`mva.pca` and `mva.mds` against R alone, and criterion 4's last bullet
does the same for `cluster.dist`.

**Fix:** either add the definitional fixtures (mpmath SVD and
eigenvalues) as the primary check, or record that R is the check for
these words, which amends a ruled question.

### SF9. No ERRATA entry is planned for research 07 §3.7

Research 07 §3.7 asks for less than this RFC builds:

| Research 07 says | RFC-0020 builds |
|---|---|
| hierarchical clustering by "single, complete, average (UPGMA, already in `phylo.`) and Ward linkage" (`07-statistical-research.md:188-189`) | eight methods, with average linkage as a separate port, not `phylo.upgma` |
| "a Silverman or Sheather–Jones bandwidth" (`:191-192`) | Scott's rule as well |
| "classical MDS from `linalg.eigen.sym`" (`:187`) | MDS plus Cailliez's constant, which needs a non-symmetric eigensolver |

RFC-0016 to RFC-0019 each recorded their departures in `ERRATA.md` at
acceptance (`ERRATA.md:234`, `:249`, `:261`, `:282`). RFC-0020 does not
mention ERRATA.

D260 C5 also gives a new prefix for "a new kind of thing" as an
*operand* (`decisions.md:17660-17661`). §S1 justifies `cluster.` by "a
new kind of answer", which reads C5 more widely than it is written. V1
is ruled, but the RFC's wording of C5 should be accurate.

### SF10. "Every file not so marked … is byte-identical" is not true (RFC:185-186)

Two cited files differ between R 4.4.2 and 4.6.2 and are not marked:
- **`stem.c`** (cited `:165-194`) differs in `stem()`, and in
  `C_bincount`, which gains an `if (nb1)` guard before its `memset`.
- **`calc.R`** (cited `:94-114`) differs at `:134-139`, outside the
  `nclass.*` functions.

Neither change touches behaviour the RFC uses, but the sentence is a
grounding claim and should list them.

### SF11. Cailliez's constant cannot come from `linalg.eigenvalues` (§S4, RFC:464-466)

§S4 takes the additive constant "by `linalg.eigenvalues`'s Schur path".
That cannot work as written:
- `linalg.eigenvalues` refuses a complex eigenvalue (`linalg.rs`,
  `linalg_eigenvalues`, `complex(*z).error(W)`).
- R takes `max(Re(e))` over every eigenvalue, complex ones included
  (`cmdscale.R:62-63`).
- Cailliez's 2n × 2n matrix often has complex eigenvalues. Its R
  construction on a 5-point Manhattan matrix gives the pair −3.28 ±
  0.52i.

A port through `linalg.eigenvalues` would therefore refuse
criterion 3's own `add` case. §What R does (RFC:217-218) also calls the
constant "the largest real eigenvalue", where R takes the largest real
*part*.

**Fix:** name `linalg.eigenvalues.complex`'s path, or the shared Schur
function, and state R's `max(Re(·))`.

### SF12. The fixtures assume host-independent last digits (criteria 8 and 9)

Criterion 8 asks for `stat.hist` "exactly", and criterion 9 asks for
10⁻¹² relative on bw.SJ.
- **`pretty`'s exactness.** `pretty` relies on an exact
  `pow(10, ⌊log₁₀ cell⌋)` (`pretty.c:153-155`).
- **bw.SJ's sums.** bw.SJ's φ₄ and φ₆ sums go through `exp`.
- **The platform's maths library.** Both depend on it. D276 is the
  precedent: a 3-ulp glibc/macOS difference broke CI.

The R fixtures come from the owner's arm64 macOS. CI is Linux.

**Fix:** say which comparisons are exact and why that is host-safe, or
give them a tolerance, or plan per-host fixtures as D276 did.

## Notes

- **N1.** RFC:346 quotes bw.SJ at `tol = 1e-13` as 1.6620992508857800.
  R 4.6.2 prints 1.6620992508857797.
- **N2.** RFC:325-326 says R's density differs from the exact kernel sum
  "up to 1.6·10⁻³ relative in the tails". Over R's default 512-point
  output for the 10-point sample, the largest relative difference is
  2.3·10⁻³; the absolute one is 1.25·10⁻⁵, which agrees.
- **N3.** §S6 keeps R's key names "as D275's 3A kept R's". §S8 answers
  `levels` and `n`, where MASS answers `lev` and `N` (`lda.R:207-209`).
  Either convention can stand, but the RFC applies both without saying
  why.
- **N4.** "summing to 1 within 10⁻⁵, as R checks" (RFC:605). R checks
  `round(sum(prior), 5) != 1` (`lda.R:90`), which is within 5·10⁻⁶.
- **N5.** §What R does (RFC:361-362) gives `hist`'s fuzz as "10⁻⁷ of the
  median width". It is the median width only when nB > 5, the range of x
  when nB ≤ 3, and otherwise the least positive width (`hist.R:118-120`).
  §S10 states it correctly.
- **N6.** RFC:248 says two singletons appear "smaller first". In R's
  `merge` the pair is written (−1, −2), so "the smaller index first" is
  clearer than "smaller".
- **N7.** `bw.nrd0`'s last fallbacks use |x₁| (`bandwidths.R:28`), the
  first value *in the order given*. §S9 should say Bund2 uses the
  operand's first element, not the sorted one.
- **N8.** `stat.density` with a numeric `bw` needs no second point in R:
  only a rule needs two (`density.R:121-123`). §S9 states fewer than two
  values as E101 for `stat.bw` only, and is silent for `stat.density`
  with a numeric `bw`, with one value or with none.
- **N9.** §What R does on `cmdscale` omits R's own cap, n > 46340
  (`cmdscale.R:48-49`). §S11's 5000 is below it, so this is only for
  completeness.

## Assumed but not stated

1. **Floating-point contraction.** R's Fortran and C on arm64 may fuse
   a·b + c into an FMA under GCC's default `-ffp-contract=fast`. Rust
   never contracts. Criterion 4's "equal R's exactly" for `merge` on tied
   inputs, and criterion 5's tie behaviour, assume R's arithmetic rounds
   as an unfused port's does. **[UNGROUNDED:** R's build flags on the
   owner's machine were not read.]
2. **`pow`.** The `pretty` port calls the platform `pow` (Rust's `powf`),
   not `powi`, because `pretty.c:153-155` relies on `pow` being exact.
3. **`uniroot` and `zeroin`.** `optim.root`'s `zeroin` reproduces
   `uniroot`'s call sequence: f at both ends first, then `R_zeroin2`
   with `maxiter` 1000. Bund2 reproduces that sequence, not only its
   arithmetic.
4. **Factor columns.** A frame's factor column, taken as a LIST,
   carries STRING labels. INTEGER groups therefore come only from user
   LISTs (SF1).
5. **nalgebra's wide SVD.** `SVD::try_new` on a wide matrix (n < p)
   answers the thin u (n × r) and vᵀ (r × p) that §S2 states. Only
   `try_new` was read, not `try_new_unordered`'s shapes.
6. **Hartigan–Wong's constants.** `BIG` is 1.E30, a REAL constant
   widened to double (`kmns.f:30`). Its exact double value,
   1.0000000150474662e30, is what "R's single-precision 10³⁰" means, and
   the port must use that value.
7. **`k = 1`.** It answers "directly", with `iter` 1 (§S6). R forces
   MacQueen (`kmeans.R:118`), whose `iter` for k = 1 depends on its
   loop. The RFC assumes the two agree on `iter`, and criterion 5 does
   not test k = 1.
