## Should fix

### S1. `smysl lib import` puts a document's withdrawals in a library, so §S4's "neither … SMYSL's CLI withdraws an edge in a library" is false, and contradicts §Current

**Location.** §S4, "Re-writing a relation SMYSL already holds", the SM03
bullet's last sentence. §Current, "A withdrawn relation", last two
sentences.

**What the RFC says.**

- §Current: "A library gains withdrawals through SMYSL's API, or through
  a command that opens the library itself; which of SMYSL's commands do
  is not established here".
- §S4, a few hundred lines later: "So withdrawing an edge withdraws
  every weight it was given, and neither Bund2 nor SMYSL's CLI withdraws
  an edge in a library."

The second sentence asserts what the first says is not established.

**Evidence.**

- `smysl lib import` opens the library through `with_library`
  (`smysl:src/main.rs:8785-8787`), which takes `acquire_all`
  (`:8618-8628`).
- `smysl_lib::import` decodes a surface-syntax file with `parse_surface`
  and keeps all its records (`smysl-lib/src/import/decode.rs:143-150`).
  The parser turns `@withdraw` into `Record::Withdrawal`
  (`smysl-core/src/surface/parse.rs:2674-2679`).
- `classify` has an arm for `Record::Withdrawal`: it waits on the rid it
  names and on its reason (`smysl-lib/src/import/classify.rs:95-99`).
- Records classed accepted are appended to the library
  (`smysl-lib/src/import/mod.rs:754`, `lib.append(&accepted)`), through
  `append_records` (`smysl-lib/src/access.rs:176-193`). With `--accept`
  that is at once (`accepted_state`, `:467`). Without it they are staged,
  and `smysl lib accept` (`smysl:src/main.rs:8968`) appends them later.

So a `.smysl` document holding `@withdraw a --rebuts--> b`, imported into
a library, withdraws that edge there. That includes a text `smysl.write`
wrote, which carries every withdrawal with a surface form (§S4).

**Consequences.**

- The design is unaffected. No rule depends on how a library came to hold
  a withdrawal. The criteria build theirs through the API (criteria 11
  and 18), which stays valid.
- The sentence is a factual claim about SMYSL with no ground, and it is
  wrong. It also undoes the hedge revision 16 wrote into §Current to
  answer the fourteenth review's N3.
- The rationale it supports, that a program cannot change an edge's
  weight, does not need it. That follows from the rid leaving the weight
  out (`smysl-core/src/types/relation.rs:231-238`) and from withdrawal
  being by rid, both already cited.

**Needed.**

- Delete "and neither Bund2 nor SMYSL's CLI withdraws an edge in a
  library" from §S4, or replace it with "and Bund2 has no word that
  withdraws one".
- In §Current, replace "which of SMYSL's commands do is not established
  here" with the command that does: `smysl lib import` of a document
  holding `@withdraw`, accepted at once or by `smysl lib accept`. Cite the
  lines above. This also settles the fourteenth review's N3, which
  revision 16 left open.

## Notes

- **N1. "Its edge reads back live" holds only when no other withdrawal of
  that rid has a surface form, and only for an edge `is_withdrawn`
  reports.** (§S4, `smysl.write`: "A withdrawal with no surface form … is
  left out, and its edge … reads back live. The `Warning` for left-out
  records names each such edge"; the Preservation row "A withdrawn
  edge".)
  - A rid may be named by several withdrawals. SMYSL's own `withdraw`
    writes one per `--as` agent (`smysl:src/main.rs:4928,4978-4987`), and
    `interp.withdrawals` holds a set per rid
    (`smysl-graph/src/store/interp.rs:31-32`). If one has a surface form
    and another does not, the written one keeps the edge withdrawn in the
    text. The `Warning` would name an edge as reading back live when it
    does not.
  - A withdrawal of a `supersedes` or `retracts` edge with no surface
    form leaves out a withdrawal that withdrew nothing (§Current). Its
    edge was live before and is live after. Naming it in this `Warning`
    says something changed when nothing did.
  - A withdrawal whose rid names no relation the library holds has no
    edge to name.
  - Fix: name an edge when `is_withdrawn` reports it and none of the
    withdrawals naming its rid has a surface form. Count the rest only in
    the per-kind `Warning` for withdrawals. Criterion 18's
    other-clock-agent case is unaffected if its fixture holds one
    withdrawal; say that it does.
- **N2. §S4's withdrawn-edge bullet gives the wrong cause, sits under the
  wrong heading, and does not name its words.**
  - "A held edge stays withdrawn, as in SMYSL, since the same bytes
    de-duplicate (`smysl-text/src/shards.rs:516-522`)". The bullet above
    it says Bund2 appends nothing for the relation in this case, so the
    de-duplication is never reached. An edge stays withdrawn because
    withdrawals are keyed by rid and `is_withdrawn` tests only the rid
    and the kind (`smysl-graph/src/store/interp.rs:31-32`;
    `smysl-graph/src/store/mod.rs:1500-1504`). This would hold even if a
    second record were appended. Cite those lines.
  - The bullet is listed under "A relation whose rid the library holds
    … or which an earlier MAP in the same `smysl.append` LIST gives".
    But its second sentence is about "a new edge", which that heading
    excludes. Move it out to its own paragraph.
  - "The word" is not named. Criterion 18 tests `smysl.rel` only. Say
    whether `smysl.append` draws the `Warning` for a relation MAP, as
    the heading's mention of `smysl.append` suggests.
- **N3. Criterion 14's relative-root case is placed in M2, but uses
  `smysl.texts`, which arrives in M4.** Criterion 14 now reads "a
  hand-built handle with a relative root, given to `smysl.agent` and to
  `smysl.texts`". The M2 row claims "14's relative-root SM00 case", but
  `smysl.texts` is in M4's Builds column. The milestone rule says "Each
  criterion is claimed by the first milestone at which every word it
  uses exists". Either split the case (`smysl.agent` in M2,
  `smysl.texts` in M4) or claim it in M4.
- **N4. Revision 16 checks a `rel` fact against the library, but not the
  other shapes, and the reason given covers them too.** §S7 now requires
  a `rel` fact's relation to be held and not withdrawn. The stated reason
  is "so no conclusion is written as resting on an edge SMYSL does not
  follow". A `[ grounds U G ]` or `[ deps U D ]` fact from a hand-built KB
  still stands for `U` whenever both uids are in the library, whether
  or not `U` has that ground or dependency. The same holds for
  `[ label L U ]` with a label the library does not bind, and for
  `[ unit U Schema Status ]` with a status `U` does not have. Rule M
  still holds in each case, because what a conclusion rests on is `U`,
  and `U`'s declared status is read from the library. The fourteenth
  review's N10 raised only `rel`. Either say why `rel` alone is checked
  (an edge is a record of its own, and a ground is part of `U`'s
  identity), or apply the same test to each shape. In either case, D244
  R8 A's "provenance by shape and library" covers it.
- **N5. The granularity of `smysl.parse`'s `SMY-W056` `Warning` is not
  stated.** SMYSL's check raises one diagnostic per withdrawal, naming
  its agent and the edge's kind (`smysl-check/src/passes/integrity.rs:46-56`).
  §S4 says `smysl.parse` "reports a `Warning` carrying `SMY-W056`'s
  meaning", and criterion 18 says "reports the `SMY-W056` `Warning`".
  Neither says whether that is one per withdrawal, as SMYSL does, one per
  edge, or one count, which the other `smysl.parse` `Warning`s give.
  Say which, so the criterion fixes it.

## Assumptions the RFC makes but does not state

1. **No SMYSL command puts a withdrawal in a library** (S1).
   `smysl lib import` does.
2. **An edge has at most one withdrawal, or all or none of its
   withdrawals have a surface form** (N1). SMYSL's `withdraw` writes one
   per agent, and the API may mix clocks.
3. **Only a `rel` fact can claim more than the library holds** (N4).
   `grounds`, `deps`, `label` and `unit` facts are checked only for their
   uids.
4. **A re-written edge stays withdrawn because its bytes de-duplicate**
   (N2). It stays withdrawn because withdrawals are keyed by rid.
5. **`smysl.parse`'s `SMY-W056` `Warning` has one obvious granularity**
   (N5). SMYSL's check gives one per withdrawal, and `smysl.parse`'s
   other `Warning`s give counts.
