## 1. Blocking

### B1 — `status_of` discards a native's own error once an exit is recorded, and `?try` keeps the text

**What §S5 specifies.** "On `Some` it parks `exit_gate`'s error in the error
slot and answers the error status, **whatever the helper's own `Result` was**"
(lines 804–806). Lines 840–841 then conclude that "`status_of` gives exactly
what Tier 0 gives". Line 797 counts it as cover: "`status_of` at the adapter
that wraps it would cover it in any case".

**What Tier 0 does.** Tier 0 never replaces an error. It makes its refusal only
at its next step, or where `run_to` returns (F112). Every native between that
point and the top wraps the refusal in its own context on the way up:
- `map_base` wraps with `MAP: lambda execution returns error: `;
- `times_base` wraps with `TIMES: lambda execution returns error: `;
- `eval_source` wraps with `Attempt to evaluate value … returned error: `;
- `Vm::eval_lambda` wraps with `Lambda content evaluation returned error: `.

`run_tryexcept` catches the result (`crates/bund2-stdlib/src/conditional.rs`),
builds an `error` CONDITIONAL whose `context` slot holds `e.0`, and pushes it.
Its `except` body is then refused, so the CONDITIONAL stays. Assumption 25
states this part correctly.

**Run at Tier 0 in this session.** Each program is
`?try :try <body> set :except { "EXCEPT" println } set :recovery { "RECOVERY" println } set !`.
Each exits 7, prints nothing, and leaves an `error` CONDITIONAL on the stack.
That CONDITIONAL's `context` slot reads:

| try body | `context` left on the final stack, Tier 0 |
|---|---|
| `{ 7 exit }` (the control) | `Lambda content evaluation returned error: the program asked to exit with code 7` |
| `{ [ 1 ] { 7 exit } map }` | `Lambda content evaluation returned error: MAP: lambda execution returns error: Lambda content evaluation returned error: the program asked to exit with code 7` |
| `{ 1 { 7 exit } times }` | `… TIMES: lambda execution returns error: Lambda content evaluation returned error: …` |
| `{ "7 exit" bund.eval }` | `… Attempt to evaluate value <the rendered CALL> returned error: the program asked to exit with code 7` |

**What compiled code leaves**, following §S5 as written. Take the second row at
threshold 1, with the try body compiled:
1. The compiled try body calls `map` through its thunk and adapter.
2. `map` runs the inner body, which is refused.
3. `map` returns its wrapped `Err`.
4. The adapter's `status_of` sees the recorded exit. It parks `exit_gate`'s bare
   error in place of `map`'s.
5. The compiled body syncs and returns the error status. The entry trampoline
   returns `Err`, and `Vm::eval_lambda` wraps it once.

So the `context` slot reads the control's string, and the final stacks differ.
The `times` and `bund.eval` rows differ in the same way, through the same
adapter.

The same substitution happens at the other three helpers. A drained body or a
residual-path value that reaches `exit` through a native returns that native's
wrapped `Err` to the drain helper or to the residual path's `apply`, and
`status_of` replaces it there too.

**Why no criterion sees it.** Criterion 30's `?try` mirror case is "a `?try`
whose `try` body ends in `exit`" (line 3088). That is the control row, where
the two strings agree. Criterion 2 cannot see it, because nothing a golden
captures runs after an exit. Row 2311 promises that "both prefixes come from
the same code whichever tier ran". That holds for the wrappers outside the
compiled body. It does not hold for the wrappers inside the natives the body
calls, which `status_of` drops.

**The Ok path is not affected.** When a helper returns `Ok` with an exit
recorded, the Ok path is at issue: `bund_exit` itself, `#` (which discards the
refusal: `let _ = crate::values::execute_top(vm)`, `object_execute_base`,
`crates/bund2-stdlib/src/oop.rs`), or a dispatch to it. There Tier 0's
refusal is the bare one, made at the next step. Because the frame loop is flat,
that step runs inside the same `run_to`, and so under the same `eval_lambda`
wrapper as the compiled refusal. The two strings agree.

**Required.** This is the RFC's own mechanism, and criterion 2's invariant
already decides the answer, so it needs no owner decision:
- **`status_of` substitutes only for `Ok`.** When the helper's `Result` is
  `Err`, it parks that `Err` unchanged. It still answers the error status, and
  still clears the request cell. That is exactly Tier 0: an error passes
  through, and a refusal is made only where Tier 0 would take its next step.
- Correct lines 804–806, 797 and 840–841.
- Extend criterion 30's `?try` case with a try body that reaches `exit` through
  `map`, `times` and `bund.eval`, compared on the CONDITIONAL's `context`
  slot. Also add a drained-body case and a residual-path case that reach `exit`
  through a native.
- Add a Preservation row: the error value a Rust caller receives after an exit
  whose helper returned `Err`.
- Give the table above a Tier 0 test, as F112 gave `map` one. It is also S1's
  missing test.

## 2. Significant

### S1 — two of F112's three gates have no test, and change only text

F112's test covers the `Vm::eval_lambda` gate alone.
- **The `Interp::apply` gate.** No native in `bund2-stdlib` does anything in
  Rust after `vm.apply` returns `Ok` at the end of a run: `eval_source` returns,
  `execute_value` returns, and `apply` and `text` return. `#` discards the
  result.
- **The `Vm::scoped_call` gate.** `run_context` returns straight after
  `scoped_call`.

So neither gate changes what a program does. What each changes is the text of
the error that propagates. Before F112, `eval_source` returned `Ok` after an
`exit` in last position, and the refusal came later, from `eval_lambda`'s gate,
without the `Attempt to evaluate value …` wrapper. This is derived from the
code at `2363e94^`, not run. The fourth row of B1's table is what it gives now.

That makes the two gates visible only through `?try`'s `context` slot. F112's
table lists `map` and `input*`, and not this change. "No golden moves" is true.

**Required:** add this text change to F112, as a further note. Pin both gates
with the Tier 0 test B1 asks for: a `bund.eval` body and a `context` body
ending in `exit`, each under `?try`. If either gate is deleted, some test
should fail. None does today.

### S2 — criterion 30's mirror cases: what checks them

- **`input*`: "which must consume one"** (line 3089) names no mechanism. With
  piped input, `rustyline` may buffer past the first line. The thirteenth
  review measured the case by holding the second line back and timing the
  exit. The criterion should name its harness: write one line, hold the pipe
  open, and assert that the process exits before the second line is written.
- **Only the `map` cases have a Tier 0 half** (lines 3093–3096). The `?try` and
  `input*` cases have none. B1's table supplies `?try`'s.
- **Comparing a final stack that holds an `error` CONDITIONAL** means the
  comparison has to normalise its id and stamp (F14). It must still compare
  the `context` slot, which is where B1 is.

**Required:** name the `input*` harness, add the Tier 0 halves, and say what
the `?try` case compares.

### S3 — smaller items

- **D52's dated note overstates.** Its heading says "'nothing more' includes
  the native" (`docs/registers/decisions.md`, D52). But `?try` still runs Rust
  after an exit: it pushes its CONDITIONAL, and the owner's ruling in the same
  note makes that state meaning. F112 and assumption 25 say so. D52 does not.
  The register is append-only, so this needs a further dated note.
- **The scan has one limit the RFC does not state.** It cuts each file at the
  first `#[cfg(test)]\nmod `, so shipped code after an inline test module would
  go unscanned. That is not the case today: in every file, the first
  `#[cfg(test)]` opens a module with no top-level function after it (checked
  this session). Lines 1986–1988 say "Within those limits the set cannot go
  stale", so the limit belongs among them.
- **Line 786, "runs only its error path".** Of the call sites that re-enter
  evaluation in shipped `bund2-stdlib` code, the only one that catches the
  result is `run_tryexcept`'s `if let Err` (found by `grep` this session). Say
  that `?try` is the only such native today, and that the claim covers
  `bund2-stdlib` alone.

## 7. What the RFC assumes and does not state

1. **A native's error text is not meaning, or `status_of` preserves it.** The
   RFC states neither. Criterion 30 and D52's note make the final stack
   meaning, and `?try` puts the text on it (B1).
2. **On the Ok path, Tier 0's deferred refusal is made under the same wrappers
   as the compiled one.** That holds because the frame loop is flat, so the
   next step runs inside the same `run_to`. It also holds because a native that
   swallows the refusal, such as `#`, returns `Ok` to the same frame. It is
   why B1's fix is to leave the Ok path alone, and it is unstated.
3. **`?try` is the only native that catches the refusal.** An embedder's
   native that catches it and then does host work runs that work in both
   tiers. D52's "nothing more" is kept only by natives that pass the error up.
4. **Every source file's test module comes last.** The scan relies on this
   (S3).

## 8. Recommendation

**Stay Draft.** The answer to the thirteenth review is complete as far as it
goes. Tier 0 now refuses where a synchronous run returns to Rust. Every
citation, figure and test named is right today, and the scan's stated limits
match its code.

The blocker is the value that travels with that status. `status_of` was
written to turn a helper's `Ok` into an error, and it also overwrites a
helper's `Err`. Tier 0 never does that. `?try` shows the difference, on a
final stack that D52's note has just made meaning. The fix is one condition in
`status_of`, and it needs no owner decision.

In order:

1. **B1.** `status_of` substitutes only for `Ok`. Correct lines 797, 804–806
   and 840–841. Extend criterion 30 with `?try` through `map`, `times` and
   `bund.eval`, and add a Preservation row.
2. **S1.** Record F112's text change, and pin its two untested gates with a
   Tier 0 test.
3. **S2.** Name criterion 30's `input*` harness, add the Tier 0 halves, and say
   what the `?try` case compares.
4. **S3.** Add a dated note to D52, state the scan's test-module limit, and
   scope line 786.
