## Should fix

### SF1. `pnt.c:75` is cited as one of R's failures, but it is a correct shortcut (line 224)

The new bullet says "R answers 0 outright for one tail when ncp > 40
(`:75`)", listed with the underflow as a reason R "is not a check beyond
ncp ≈ 38 to 40".
- `:75` is inside the `t < 0` branch (`:71-76`), whose comment says
  `pt(q, df, ncp) <= pt(0, df, ncp) = \Phi(-ncp)`.
- With ncp > 40, Φ(−ncp) is below 10⁻³⁴⁸, and a double's smallest
  subnormal is about 4.9·10⁻³²⁴. So 0 for the lower tail, and
  `R_DT_0` (which is 1 for the upper tail) are the right doubles.

The failure is the underflow at `:101`, `:105-110`, which answers 0 for
any t once ncp exceeds about 38.6 (exp(−λ/2) underflows at λ/2 ≈ 745).
The guard just before it, `:78-79`, names this threshold ("if del >
37.62, then p=0 below").

**Fix:** drop `:75` from the list of failures, or say it is a correct
shortcut, and cite `:78-79` for the threshold.

### SF2. Two of R's guards are claimed but not cited where they are (lines 229-232, 247, 487)

- **`qtukey`'s df guard.** Line 229 says "Both answer NaN with a warning
  for df < 2" and cites only `ptukey.c:321`. `qtukey`'s guard is
  `qtukey.c:136`, the same condition. Cite it.
- **The generalised CMH.** Lines 247 and 487 say any dimension above 2
  is the generalised I×J×K test, and cite `:28` for it. `:28` only
  refuses a dimension below 2. The split is at `:57` (`## 2 x 2 x K
  case`), and the generalised test at `:256` (`## Generalized
  Cochran-Mantel-Haenszel I x J x K test`). Cite those.

### SF3. `optim.root`'s E101 text cannot be rendered by E101's template (line 506)

§S6 gives the same-sign refusal as "E101, `f has the same sign at both
ends`". E101 has one variant, `Refusal::Domain`, rendered as
`<operand> is outside <function>'s domain: <value>` (`refuse.rs`,
`Refusal::text`). There is no free-text E101, so the stated text is not
one the family can produce. Criterion 8 checks "each refusal gives its
text", so the test would be written from a text that cannot exist.

**Fix:** choose one.
- State the Domain rendering, for example `lower is outside
  optim.root's domain: f has the same sign at both ends`.
- Or add an E101 variant with its own template, as §S11 adds one to E106,
  and list it in §S1's "one new E106 text" and in Preservation.

The same applies to every "E101 naming the key/group/stratum" in §S4,
§S5 and §S9. Those fit `Domain` with the key as `operand`, but the RFC
should say so once in §S1.

### SF4. The power words' defaults are stated for `power.t` only (lines 405-418)

The §S4 table gives defaults for `power.t`: `sd` 1.0, `sig.level`
0.05, `type`, `sides` and `strict`. It gives none for `power.prop`,
`power.anova` or `power.chisq`. The "Defaults" rule then decides what
is solved for by whether a key has a default. So for those three words
it is not stated whether an absent `sig.level` defaults or is the
parameter to solve. R's `power.prop.test` defaults `sig.level=0.05`
(`power.R:84`), and so does `power.anova.test` (`power.anova.test.R:21`).

**Fix:** give each key's default, or "none", in every row. Then the
rule "exactly one left out" is checkable for all four words.

### SF5. `boot.sample`'s `bias`, `se` and normal interval have no definition or check (lines 541, 563, 835-841)

- **`bias` and `se` are answered but not defined.** §S8 defines them for
  `boot.jackknife` only. `boot`'s are bias = mean(t*) − t₀, and se² =
  `var(t)`, on R − 1 (`bootfuns.q:1107`, `:1112`). The RFC should state
  these, the denominator included.
- **The normal interval is outside criterion 10's fixture.** The
  criterion lists `norm.inter`, `basic.ci`, `perc.ci` and `bca.ci`.
  `"normal"` is `norm.ci`'s t₀ − bias ∓ z·se (`bootfuns.q:1080-1117`,
  the interval at `:1114-1115`), which none of the four computes. Add
  `norm.ci` to the fixture's list and cite it in §S8.
- **"its own … jackknife values"** (criterion 10, line 840).
  `boot.sample`'s answer does not include the jackknife values, so the
  test cannot read them from it. It must compute them with
  `boot.jackknife`. That holds only if `boot.sample`'s internal jackknife
  is `boot.jackknife`'s, which §S8 does not say. Say it, and add the
  jackknife values to `boot.sample`'s answer when `"bca"` is asked for,
  or state the equality as a clause of criterion 10.

## Notes

- **N1. The noncentral t is not a plain Poisson mixture** (§S2, lines
  354-362). P(T ≤ t) = Φ(−δ) + ½Σⱼ[pⱼ·I_x(j + ½, ν/2) + qⱼ·I_x(j + 1, ν/2)].
  The pⱼ are Poisson(δ²/2) weights, and the qⱼ have Γ(j + 3/2) in place
  of j!. The Φ(−δ) term belongs to no mixture. The upper tail can be
  summed directly with complementary betas, since Σqⱼ = 2Φ(δ) − 1 cancels
  Φ(δ), but §S2 should say how, because "1 minus something close to 1"
  is exactly what the naive upper tail does. The 50-digit fixture
  catches an error, so this is a note.
- **N2. Shapiro–Wilk's rescale.** `shapiro.test.R:29` divides x by its
  range when the range is below 10⁻¹⁰, "to avoid ifault=6". §S5 ports
  `swilk.c` only. Criterion 6 matches R at 10⁻⁹, so either the port
  rescales too, or no input in `fixtures/shapiro.R` has a range below
  10⁻¹⁰. State which.
- **N3. Criterion 12's indefinite-Hessian clause has no named input.**
  BFGS rarely stops at a saddle. The natural test is a log-likelihood
  constant in one parameter, which gives a zero pivot. But a
  central-difference Hessian gives a pivot of rounding size, maybe
  10⁻¹⁰ positive, which passes as positive definite and answers a huge
  but finite `se`. Name the input, and say whether a pivot below some
  tolerance counts as not positive.
- **N4. `every_code_renders_its_template`** (`refuse.rs`'s tests) has
  one case per variant. The new E106 variant joins it. The Preservation
  row on refusals (line 719) should name the test, as the counting
  tests are named.
- **N5. How a program writes NONE into a `power.` options MAP.** RFC-0017
  added `na` (`-- x`, NONE with q 0.0, its §S2 table at line 399), and
  RFC-0017 A5 notes that a LIST literal cannot hold NONE. §S1's new rule
  should name `na` as the way: `dict "sd" na set`.
- **N6. "No root in the extended interval" as E110** (§S4, lines
  431-432). E110's template is `<method> did not converge within <cap>
  iterations`. Running out of interval doublings is not running out of
  iterations, and the cap the text would name, the 60 doublings or
  1000 iterations, is not stated. Say which.
- **N7. `stat.test.tukey` with N − k < 2.** §S3 now refuses df < 2 as
  E104 with `dist.tukey`'s text. `stat.test.tukey` reaches it with df =
  N − k. A program would see `invalid tukey parameters` from a test word
  that took no distribution. State whether `stat.test.tukey` refuses
  first, as E101 naming `groups`.
- **N8. The first review's N1–N8 and U1–U6 are still open.** D268
  says so, and the RFC's status line says so. Some of this review's
  findings are close to them: N3 to N4's NONE operand, and SF5 to U2's
  draw order.

## What the RFC assumes and does not state

- **U1. The bracket for d's ncp roots.** §S6's `optim.root` needs a
  bracket with a sign change. §S12 does not give one, nor an `extend`
  setting. Both ncps lie between t − c and t + c for some c, so a
  bracket exists, but the word's refusal on failure (E110? E101?) depends
  on which bracket is chosen.
- **U2. One options reader for `power.`.** The NONE rule applies "for
  `power.` only". That assumes `power.` reads its options with a reader of
  its own, or a flag on RFC-0016's reader, and that no other word's
  reader starts accepting NONE. §S13 should say where the reader lives.
- **U3. The jackknife inside `boot.sample` is run only for `"bca"`.**
  §S8 says BCa "costs n more statistic calls", implying the jackknife is
  skipped otherwise. SF5 needs it stated.
