# RFC-0014 review: Draft revision 14, 2026-11-03 (thirteenth review)

Adversarial review, independent of the twelve before it. The RFC and the
sources were read first, and the earlier reviews only afterwards, to drop
findings already raised and answered. Nothing was edited or built, apart
from running `cargo xtask cite`. Read against Bund2's working tree at
c6afa82, the `reference/` submodules (whose `git status` is empty), and
SMYSL at 4f5ecb9 ("Merge 1.14.0"), opened file by file. SMYSL citations
are relative to its crate directory, as the RFC writes them.

Revisions 13 and 14 were checked hardest
(`git diff b163a68 d33e7ef` and `git diff d33e7ef c6afa82` on the RFC):

- the relation-identity paragraph in §Current, and §S4's new rule for
  re-writing a relation;
- `smysl.write`'s rewritten row: what it passes, its label context, and
  its per-kind `Warning`s;
- retraction step 1 and `is_retracted`;
- `smysl.measure`'s `value`;
- the handle's `root`, the empty payload, the relation read-back note,
  and M2's primary marker.

The relation claims were followed past `Relation::uid` into
`absorb_hot`, `attach`, `relation_by_id`, `relations_of_kind`, the
store's `derive` and `encode_by_shard`. `smysl.write` was followed into
`write_surface`, `has_surface_form`, `write_unit`, `write_relation` and
`refs`, and into the parser's `lookup`, to confirm that a bare uid
reference re-parses. Retraction was followed into `effective_status`
and `plan_retraction`.

**Verdict: Ready once the should-fix items are answered. 0 blocking,
2 should-fix, 11 notes.** D244 and D245 are not re-argued. Revision 14's
answers to the twelfth review's S1–S3 hold against the source. The
should-fix items are both about **withdrawn edges and the other records
the RFC never mentions**:

- `smysl.write` passes only units, relations and labels. It drops every
  other record, with no `Warning`. That includes the manifests Bund2's
  own `smysl.text.add` writes, and withdrawals. A withdrawn edge is
  written as a live `@rel`, so the text means something the library
  does not (S1).
- `smysl.kb`'s `[ rel Kind From To ]` facts do not say whether a
  withdrawn relation is loaded. Every interpreting read in SMYSL leaves
  withdrawn edges out. The RFC's own example rule would then count a
  withdrawn rebuttal as live (S2).

## Should fix

### S1. `smysl.write` drops every record it does not pass, with no `Warning`, and a withdrawn edge comes back live

Revision 14's `smysl.write` row (§S4) says:

> **What it passes:** the store's units …, its relations one per rid as
> the store resolves them …, and the label bindings the context below
> admits. No attestation, view or other record is passed.

The same row then promises that what is lost is "said": one `Warning`
per kind of loss. It lists units with no surface form, unwritten labels,
and dropped `extra`. The Preservation rows "Units with no surface form",
"An omitted unit's references" and "A relation's and a label binding's
`extra`" say the same.

**Evidence.**

- **SMYSL's writer can write far more than units and relations.**
  `write_surface` writes, when given them:
  - schema declarations and manifests (`write.rs:129-144`);
  - threads (`:162`);
  - withdrawals, resolutions, commitments, redactions and datings
    (`:167-188`).

  `has_surface_form` covers each (`:205-221`). SMYSL's `merge` passes
  `store.iter()`, every record (`smysl:src/main.rs:4327`).
- **Bund2's own words write one of these kinds.** `Library::add`
  appends a `Record::Manifest` (`smysl-text/src/library.rs:1317`). So
  after `smysl.text.add`, `smysl.write` leaves out the library's
  manifests, and no `Warning` says so.
- Criterion 18 asserts that "a library whose only records Bund2 wrote,
  attestations included, draws no `Warning`". It passes over such a
  library, which has lost its manifests, so it tests the opposite of the
  row's promise.
- **A withdrawal changes meaning.**
  - "A relation is withdrawn in a store iff the store holds at least one
    withdrawal naming its rid … nothing interpreting the graph follows
    it" (`smysl-core/src/types/lifecycle.rs:18-22`).
  - `Store::relations` still yields a withdrawn relation
    (`smysl-graph/src/store/mod.rs:554-556`). Only `is_withdrawn`
    (`:1502-1504`) and the readers that call it leave it out.
  - So `smysl.write` writes a withdrawn edge as a plain `@rel` and
    leaves out the `@withdraw`, which `withdrawal_has_surface_form`
    admits (`write.rs:238-240`). A rebuttal the library has withdrawn
    reads back as live.
  - SMYSL names this exact failure where it selects records to send
    elsewhere: "A withdrawal travels with its edge, or the recipient
    would follow an edge the sender does not"
    (`smysl-graph/src/store/mod.rs:933-937`).
- A library can hold withdrawals. SMYSL's CLI writes them
  (`smysl:src/main.rs:170,4896`), and §S2 already designs for data
  "a later SMYSL may write" and for labels bound by a merge.

**Needed.** State which records `smysl.write` passes, and account for
the rest, in one of two ways:

- **(a)** Pass every record `has_surface_form` admits, with relations
  one per rid and the label context as stated. A `Warning` per record
  kind then covers what is left out.
- **(b)** Keep units, relations and labels only. Then:
  - report one `Warning` per record kind not passed, with its count;
  - leave out, or name in a `Warning`, every relation `is_withdrawn`
    reports, so that no withdrawn edge is written live.

Then:

- correct criterion 18's "draws no `Warning`" case, which as written
  includes a library with texts;
- add a case where a library holds a withdrawn relation, built through
  SMYSL's API, and assert what `smysl.write` gives;
- add a Preservation row: "Records other than units, relations and
  labels through `smysl.write`".

### S2. `smysl.kb` does not say whether a withdrawn relation becomes a `rel` fact

§S7's table gives `[ rel Kind From To ]`, "one per relation with both
ends in scope". The example rule beneath it asks for "which findings rest
on a rebutted claim" through `[ rel "rebuts" _ C ]`. Criterion 11 counts
"each kind … against the library".

**Evidence.** Every interpreting read in SMYSL leaves withdrawn edges
out:

- the store's `derive` builds "the adjacency every traversal reads …
  without it" (`smysl-graph/src/store/mod.rs:1276-1286`);
- `relations_of_kind` leaves "out withdrawn ones (1.4)" (`:1573-1580`),
  and that is how `effective_status` finds retractions
  (`smysl-graph/src/merge/retraction.rs:83`);
- `is_live_rebuttal` requires `!self.is_withdrawn(rel)` (`:1508-1513`);
- `proposition.rs` filters `store.relations()` by scope **and**
  `is_withdrawn` (`smysl-graph/src/proposition.rs:140-153`), which is
  the same filter §S7 describes.

`Store::relations` does not apply it (`smysl-graph/src/store/mod.rs:554-556`).
An implementer who loads `rel` facts from `Store::relations` filtered by
scope therefore hands RFC-0013's rules edges SMYSL says nothing should
follow. `smysl.trace`, `smysl.status` and `smysl.query` honour the
withdrawal, since they read the adjacency, but `smysl.kb` would not. A
program's rules would then disagree with SMYSL's own reading of the same
library. Criterion 11 cannot tell the two readings apart, because "counted
against the library" names no read.

**Needed.**

- State in §S7 that a `rel` fact is loaded for a relation that is not
  withdrawn (`is_withdrawn`), or else state that withdrawn edges are
  loaded and say how a rule can tell them apart.
- Give criterion 11 a fixture with a withdrawn `rebuts` edge, built
  through SMYSL's API, and assert the count.
- If withdrawn edges are left out, a Preservation row is not needed,
  since that is SMYSL's own reading. If they are loaded, one is.

  record hashes, and SMYSL's `merge` and export write from those
  (`smysl:src/main.rs:4327`). Say "no interpreting read": not
  `relation_by_id`, `relations`, or the adjacency. §S4's refusal still
  holds. It is the stronger for it, because SMYSL's own surface writers
  would emit both variants.
- **N3. SM03's row in §S8 does not list the new case.** §S4 makes "rid
  <rid> is held with another weight or note" SM03. §S8's SM03 "When"
  column (RFC line 1493) still lists only shape, type and key errors.
  Criterion 14 tests "§S8's text". Add the case to the row. Consider
  also whether this is SM03 at all. It is a conflict with what the
  library holds, which is how SM08 is framed at bind time ("`label
  <label> is bound to <uid>, not <uid>`"). That choice is the RFC's to
  make, but it should be made in §S8.
- **N4. Re-asserting a withdrawn edge, and the same-weight criterion's
  agent.**
  - With the same weight and note, §S4 appends nothing and answers the
    rid. If that rid is withdrawn, the edge stays withdrawn
    (`lifecycle.rs:20-22`), and the program has no sign of it. SMYSL
    behaves the same, since the bytes de-duplicate. Say so beside the
    rule.
  - Criterion 18's "`smysl.rel` of an edge the library holds, with the
    same weight, writes nothing" holds only when the handle's agent has
    already attested the rid. Otherwise the unit rule writes an
    attestation. Name the agent in the case.
- **N5. Cite the ground for "no way to change an edge's weight".** It is
  the rid (`relation.rs:231-238`). SMYSL's `withdraw` withdraws by rid
  (`smysl:src/main.rs:170,4896`), so it removes every weight at once.
  The sentence as written cites nothing.
- **N6. The handle's `root`, R3, and `save.model`.**
  - Revision 14 changes §S2's handle to `root: <STRING, a path>`, and
    says R3's "canonical root" holds "wherever it matters".
  - R3 as ruled reads "a MAP `{type:"smysl", root, agent}` with a
    canonical root" (`docs/registers/decisions.md:16627-16628`). The
    RFC's own rulings table still says "with a canonical root"
    (R3, RFC line 2470).
  - §S2 still says, unconditionally, "A handle saved by `save.model`
    names the same library from any working directory" (RFC lines
    884-885). That is false for a hand-built handle with a relative
    root, which revision 14 now admits, because each word canonicalises
    it against the current directory.
  - Either refuse a relative `root` as SM00, which keeps R3's wording
    true, or qualify the `save.model` sentence. In both cases add a dated
    note to D244's R3. The revision says "no ruling changes", but it
    narrows what R3's words mean.
- **N7. A Preservation row contradicts §S4.** "Units with no surface
  form" (RFC line 1920) still says `smysl.write` "reports a `Warning`
  per kind, as SMYSL's CLI does". Revision 14 corrected §S4: the CLI
  prints one total, and per-kind counting is `SMY-W428`'s. Change the
  row to match.
- **N8. Two places keep the wording S3 replaced.**
  - §Current's account of SMYSL's `retract` (RFC lines 507-509) says it
    "does nothing … when `effective_status` already reads the target as
    retracted".
  - Criterion 8's "Retracting a unit already read as retracted" says
    the same.

  Both should say "retracted directly (`is_retracted`)", as §S4 step 1
  now does. Otherwise they read as the status test revision 14 rejected.
- **N9. A measure's `value` without a headline, and no criterion pins
  `value`.**
  - `gist` is `"<id> over <scope>"` when the value has no headline
    (`smysl-measure/src/outcome.rs:286-288`). §S5 describes it as "the
    measure's id, its headline and the scope". Say "and its headline,
    when it has one".
  - Revision 14 says `value` is uncut and can differ from the unit's
    gist. Criterion 10 compares with "what the direct calls give" and
    does not say what `value` is compared to. State that it equals
    `smysl_measure::gist(&recipe, &value)`. Add a measure over a scope
    long enough that `fit` cuts the unit's gist, so the two are told
    apart.
- **N10. Criterion 18's no-`Warning` case and the empty payload.**
  - Apart from S1, Bund2 can write a unit with no surface form (a
    `status` payload key, §S2) and a unit's second label
    (`smysl.label`). Both draw a `Warning`. "A library whose only
    records Bund2 wrote" should name its fixture: units with surface
    forms, one label each, no texts.
  - Revision 14 states that `payload: {}` is no payload, but no

- **N11. The label bindings `smysl.write` "passes" are never written as

## Assumptions the RFC makes but does not state

1. **A library holds nothing that `smysl.write` needs besides units,
   relations and labels** (S1). Bund2's own `smysl.text.add` writes
   manifests, and SMYSL writes withdrawals.
2. **Every relation `Store::relations` yields is live** (S2). A withdrawn
   one is yielded too.
3. **The record the store resolves for a rid is the same on every
   open.** It is "whichever variant arrived first"
   (`smysl-graph/src/store/mod.rs:1110-1113`). In a library that order
   depends on the order in which the open reads the shard logs. Bund2
   never writes a second variant, but a SMYSL-written library can hold
   two. Then §S4's "held with another weight" test, and the record
   `smysl.write` writes, rest on that order.
4. **Re-asserting a withdrawn edge revives it** (N4). It does not.
5. **A hand-built handle's root is absolute** (N6). Nothing checks it.
6. **Every measure value has a headline** (N9). `gist` omits it when
   none is set.
