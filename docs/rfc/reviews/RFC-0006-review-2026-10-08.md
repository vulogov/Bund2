## Blocking

**B1 — The `--noeval` group is six words in the reference and in Bund2, and
the RFC says four, three times, citing the function that lists six.**

§B3a: "The group is `bund.eval`, `bund.eval.`, `use` and `use.`
(`crates/bund2-stdlib/src/host.rs`, `register_noeval_stubs`)". The
preservation table repeats the four; criterion 10 names three.

The reference stubs `bund.eval`, `bund.eval.`, **`bund.eval-file` and
`bund.eval-file.`**
(`reference/Bund/src/stdlib/functions/bund/bund_eval.rs:117-121`) and `use`,
`use.` (`reference/Bund/src/stdlib/functions/bund/bund_use.rs:74-76`).
`register_noeval_stubs` stubs the same six
(`crates/bund2-stdlib/src/host.rs:882-900`). Measured on a bundle built
`--noeval` whose program is `"p.bund" bund.eval-file`: refused, "bund EVAL
functions disabled with --noeval".

The behaviour is right and the document is wrong. It is blocking because D78
requires the list by name, the list is what a runner reads, and the two
omitted words are the ones that read a *file* and run it. D79 carries the same
four and needs an appended note.

**B2 — §B3a's "`--noio` leaves ungated" is one module's doc comment, not the
flag's surface.** The three names — `args`, `sleep.seconds`, `io.graph` — are
the ungated words *of `host.rs`*, which is what the cited module documentation
says. The RFC presents them as what the flag leaves ungated.

Measured on a bundle built `--noio --noeval`:

| program | result |
|---|---|
| `system.ip println` | the machine's LAN address |
| `sysinfo.hostname println` | the machine's host name |
| `system.locale println` | `en-US` |
| `"q> " input println` | reads a line from standard input and prints it |
| `debug.shell`, one typed line | **writes `bund2/bund_debug_shell_history.txt` under the user's configuration directory** |

The first four are the reference's and it registers each with no gate
(`reference/Bund/src/stdlib/functions/system/ip.rs:34-35`,
`sysinfo/host.rs:66`, `system/locale.rs:27`, `io/input.rs:142-145`), so these
are D79's kind of boundary and not defects. The fifth is a filesystem write
under `--noio`. The reference writes the same file, into the working
directory (`debug_shell.rs:20`, `:52`); Bund2 moved it
(`crates/bund2-stdlib/src/terminal.rs`, `history_path`) and nothing gates it
in either.

D78: "RFC-0006 states what each flag leaves ungated, by name." It names three
of at least a dozen, and none of the ones that disclose the host or write to
it. The acceptance review's B4 found the same shape for `--noeval` and it was
fixed by adding two names; this is the other flag.

**B3 — `bund2 build` has no `--emit` and no `--features`, and accepts both
silently.** The RFC specifies `bund2 build --emit=bundle` throughout, has
`--emit=native` withdrawn, and in §B4 says "`--emit=bundle --features` selects
among the runtimes it has" and "`--features jit` asks for the other one".

The binary's usage is `bund2 build --file <src> --output <path> [--noio]
[--noeval]` (`crates/bund2-cli/src/main.rs:548`), its module documentation
says "no `--emit`" (`main.rs:14`), and unknown arguments are not read at all.
Measured:

    $ bund2 build --emit=native --features jit --file p.bund --output n1
    bund2: wrote n1 — 13 of 1048576 bytes used        # exit 0
    $ bund2 build --inspect n1
      built by       bund2 0.0.0, default features

So the withdrawn mode is accepted and produces a bundle, and a request for a
JIT runtime is accepted and produces one without. Both are the silent failure
this RFC argues against at length in §B3a. A second `--file` is ignored the
same way, where §B3 says "exactly one source file". No criterion covers any
of it.

**B4 — "A prebuilt runtime per target" is not what was built, and the status
line says the mode is "built and reviewed".** §B1: "`bund2 build` ships or
locates a prebuilt runtime per target it can bundle for, including targets
Cranelift does not support." §B6: an unsupported target "needs a prebuilt
runtime for that target rather than a compiler on the build host." D80's
fourth condition doubles that matrix.

`bund2 build` copies `std::env::current_exe()` (`main.rs:598-632`). The
artefact is always the builder's own target and the builder's own feature
set. Three things follow that the document does not say:

- **A bundle for another target cannot be produced.** That is the case §B6
  calls the reason the mode is "mandatory rather than convenient".
- **"A builder and a prebuilt runtime can be different Bund2 builds" cannot
  occur**, so §B1's version-skew paragraph describes nothing. The version is
  recorded and shown by `--inspect`; `carried()` reads `format`, `state`,
  `len`, the payload, `source_name` and `flags` and never the version
  (`crates/bund2-cli/src/bundle.rs:227-269`), so "the runtime can refuse or
  warn on one it does not recognise" is unbuilt.
- **A JIT bundle is made by building `bund2` with `jit` and running that
  binary's `build`.** That is how `a_jit_bundle_enters_compiled_code` gets
  one.

The built form may well be the right one. The RFC needs to say which is the
design and which is deferred, with a criterion or an open question for the
part that is not built.

## Should fix

**S1 — `RFC-0005:6548-6561` is stale.** The exclusion and its trigger are at
`RFC-0005:6725-6739`. `cargo xtask cite` reports every citation resolving, so
it does not check an RFC-to-RFC line citation, and this is the only kind in
the document it cannot protect.

**S2 — D31 is RESOLVED, and the RFC says it is OPEN.** "whether anything
outside Bund2 reads that file is **D31**, which is OPEN. D11's answer is
therefore not independent of D31". D31 was resolved by the owner on
2026-09-11 — "no external readers; D27 holds unconditionally" — eighteen days
before this paragraph and D11's second amendment were written. The RFC does
not rest on it, as it says, but it reports an open decision that is not open
and draws a dependency from it. D11's amendment carries the same error.

**S3 — `"1 2 +" compile encode.base64` does not yield "exactly the bytes
`compile_to_binary` would write".** The Bund word `compile` is not
`compile_to_binary`'s front half. It appends a newline before parsing
(`bund_interpreter.rs:29`) and stops at the first `EXIT` (`:34-36`), where
`bund_vec_to_list` copies every token (`compile.rs:8-10`). And a `Value`
serialises its `id` and `stamp` (`reference/rust_dynamic/src/value.rs:15-25`),
minted per construction (`:35-36`), so no two parses produce the same bytes at
all. The sound claim is that it is the same *format*: a LIST through
`to_binary`. D11's first amendment has the sentence verbatim.

**S4 — The feature record cannot express the feature §B4 uses as its
example.** §B4: a program calling `string.grok` "works under a `grok` build
and fails in a default-feature bundle … `bund2 build` therefore records in the
trailer which features its runtime carries." `features_built_in` tests `jit`,
`aot` and `async` (`main.rs:35-47`). `grok` is a feature of `bund2-stdlib`
(`crates/bund2-stdlib/Cargo.toml:244`) that `bund2-cli` does not declare, so a
runtime carrying `string.grok` would inspect as "default features". Read from
the code; a `grok` build was not made, since it compiles C.

**S5 — The source path is not recorded "verbatim" past 256 bytes.** `padded`
truncates silently (`bundle.rs:209-215`) into `source_name: [u8; 256]`.
Measured with a 310-byte path and the program `1 nosuch`: the bundle's
`Location` line ends mid-directory and never names `prog.bund`; a `script` run
of the same path does. §B3 says the recorded path is what makes "a bundle's
stderr match a `script` run of the same program from the same path". The build
neither refuses nor warns.

**S6 — §B1 still specifies the appended form's failure cases, and "the
trailer" appears 21 times after the design that removed it.** Carried from
the acceptance review's S3 and S4, unanswered. §B1 lists no trailer, a
truncated trailer, a length "beyond the file, or overlapping the trailer", and
unreadable text. The code's cases are `State`, `Format`, `Length` and
`NotText` (`bundle.rs:166-175`). A truncated trailer cannot occur in a fixed
region; a bad state byte and an unknown container version are in neither
§B1's list nor criterion 12's. `Damaged::Format` is driven through the binary
by no test.

**S7 — The quoted comment in §B3 is no longer in the code, and the file
named is not where the call is.** "criterion 2 would then pass with no
compiled code having run at all" occurs nowhere under `crates/`. The comment
at `main.rs:88-93` reads differently and names criterion 18. The thread is
sized by `EVAL_STACK` and the share declared by `declare_region`, both in
`crates/bund2-runtime/src/lib.rs` (`:87`, `:106-112`), not in `main.rs`.

**S8 — The header's decision lists do not match the body.** "Decisions
consumed" lists **D44**, which the body never mentions, and omits D82, D83,
D115 and D116, all of which the body rests on, and D37, D45 and D113, which
it cites. "Touched but not consumed: D1 … see the preservation table" — the
table has no `.id` row (P1 below).

**S9 — Three environment variables the bundle reads are not in the list §B3
says is "part of this design".** `BUND2_NOIO`, `BUND2_NOEVAL` and
`BUND2_NOCOLOR` (`main.rs:501-503`). The first two are the only way to
exercise D78's floor at run time and appear in the RFC only inside criterion
10's evidence. `env_set`'s rule — set, and neither empty nor `0`
(`main.rs:541-546`) — is stated nowhere.

**S10 — RFC-0005 still contradicts itself about its criterion 4, and this
RFC's status leans on it.** `RFC-0005:93` reads "Not met — 4's reachable
remainder alone … belongs to RFC-0006's AOT path"; `RFC-0005:4192` reads "Met,
2026-09-30, by inspection rather than by a product — D83". The acceptance
review's S1, unanswered. It is RFC-0005's to fix.

**S11 — `--inspect` reports "default features" for a binary it has no record
for.** An unbuilt runtime's feature field is empty, and an empty field prints
as ", default features" beside "(unrecorded)" — measured on a `jit` build of
`bund2` that contains 423 lines matching `cranelift`. `main.rs:33-34` says an
empty string "is not the same as 'unknown'"; for a runtime nobody built from,
it is exactly unknown.

**S12 — Small.** "Four things the artefact's front end must settle" is
followed by six bullets. §B3, §B3a and the preservation table name the CLI
flag as `--dump-stack` in the list of flags a bundle loses; the flag a user
would reach for is `--no-dump-stack`, as the same paragraph says two lines
later. `bundle.rs:241` names a test, `a_release_bundle_runs_its_program`, that
does not exist as a function; the check is `cargo xtask bundle`.

## Preservation analysis — what it does not enumerate

**P1 — `.id`.** The header says D1 is touched and points at the table. The
table has `.timestamp` and no `.id`. The encoded stream would have fixed
identities at build exactly as it fixed stamps — §"What the wire codec does"
says encoding "materialises the identity and the stamp" — and criterion 9
checks the stamp alone.

**P2 — The debugger words, D115.** "Program meaning under a bundle —
**Preserved exactly**, because the artefact parses and evaluates the same
source through the same entry points." Since this morning that is false by
ruling: `"a" println debug.step "b" println` stops at a console under `script`
and does not in a bundle. The row needs an exception and D115 needs a row. It
is the one place the same source means two things, and the table is where a
reader looks for that.

**P3 — `--noio`'s ungated surface**, B2. The row says "§B3a names what each
leaves ungated", which it does not.

**P4 — A program larger than 1 MiB.** Runs under `script`, cannot be bundled.
The table mentions the region under signing and has no row for the limit as a
change in which programs the mode accepts.

**P5 — A source path longer than 256 bytes**, S5. The "Diagnostic file name —
Preserved" row is unconditional.

**P6 — The history file.** A bundle that calls `debug` or `debug.shell` writes
session history under the configuration directory of whoever runs it. For a
`script` run that is RFC-0008's business; for a shipped artefact on someone
else's machine it is this RFC's, and it is not mentioned.

**P7 — `bund2` itself.** Every `bund2`, bundle or not, now asks its own image
whether it carries a program before it reads argv (`main.rs:108-125`), and a
damaged region stops the plain interpreter too. That is a change to the
interpreter's start-up, not only to artefacts. It also carries the 1 MiB
region in every build.

**P8 — The `--noeval` row lists four words**, B1.

## What the RFC assumes and does not state

1. **The builder is the runtime.** Same binary, same target, same features,
   same parser (B4). §B3's "the artefact re-parses at start-up, which is what
   keeps §B2's preservation exact" is only safe because of it: with a separate
   prebuilt runtime, a program could parse at build and fail at start.
2. **The compiler does not fold reads of the region.** The runtime reads an
   immutable `static` through `std::hint::black_box`, which the code calls "a
   hint and not a guarantee" (`bundle.rs:239-245`). The status paragraph
   mentions the bug; the design section does not state the reliance, and the
   only check is `cargo xtask bundle`.
3. **macOS on arm64 stands for every platform.** ELF and PE are "reasoning
   from the formats". CI is Linux and would run `bundle_build` there; the RFC
   cites no such run.
4. **`/usr/bin/codesign` is present and is not a Command Line Tools stub.**
   D81 records it; the RFC's criteria do not.
5. **The builder can read its own executable** and the output directory is
   writable. A `bund2` installed without read permission cannot build.
6. **The program is UTF-8 and one file.** `read_to_string` refuses anything
   else at build; whether `script` accepts a source that is not UTF-8 is not
   compared.
7. **1 MiB is enough**, and nobody needs to know the limit before hitting it.
8. **Unknown `build` arguments are harmless** (B3).
9. **A restriction's users read `--inspect`'s closing line** — "What a bundle
   does not restrict, it permits" — as covering B2's list.
