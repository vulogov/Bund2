## Blocking

### B1. The gist bound does depend on the library's profile, so §S7's 100-byte cut can draw `SMY-E022`

§S4 says that the gist bound does not depend on the profile, "since every
preset sets it at 30 tokens". §S7 cuts a gist at 100 bytes. Revision 4's
answer to S2, and R19, rest on both. Under R19 A, `smysl.check` takes the
profile of the library's own view (`smysl-check/src/lib.rs:172-175`), and
that profile is not limited to the presets.

1. **A view may set any `l0_max`.** The surface parser takes a preset by
   name and then overwrites its bound:
   `g.l0_max = n.max(0) as u32` (`smysl-core/src/surface/parse.rs:907-908`).
   The CBOR decoder does the same (`smysl-core/src/cbor/envelope.rs:1084`).
   - Take a library whose view says
     `granularity: { profile: default, l0_max: 20 }`.
   - Under the default estimator, a 100-byte gist plus `…` is 26 tokens
     (`tokens = ceil(len/4)`, `smysl-core/src/types/mod.rs:42-44`).
   - That is `SMY-E022`, an error, so the library is not clean, and
     criterion 12's "no `SMY-E022`" fails.
2. **A view may name another estimator.** `smysl/content/1` weighs a CJK
   character at 931 milli-tokens and a space at 456
   (`smysl-core/src/types/estimate.rs:50-58`).
   - 100 bytes of CJK text is 33 characters, about 30.7 tokens before the
     ellipsis.
   - That breaches even the preset bound of 30.
   - The estimator is carried in the profile's CBOR key 5
     (`estimate.rs:228`).
3. **A library with several views is checked against their widest
   envelope** (`smysl-check/src/lib.rs:255-268` and the lines after).
   §S4 says "the library's own view's", in the singular.

**SMYSL already has the operation the RFC needs.**
`GranularityProfile::fit_gist_with(text, suffix)` gives the longest prefix
that fits `l0_max` under the profile's own estimator, leaving room for an
ellipsis "whose own cost depends on the estimator and so cannot be
reserved in bytes" (`smysl-core/src/types/view.rs:204-212`). It answers
`None` for an estimator the build does not have, in which case
`SMY-W025` applies and the bound cannot be evaluated (`view.rs:189-195`).

**Needed:**
- Cut the gist with the profile `smysl.check` will use, by
  `fit_gist_with`, against the library as it is under the locks.
- Say what happens when the estimator is unknown: refuse the write, or
  fall back with a stated warning.
- Restate §S4's sentence and R19's rationale.
- Add to criterion 12 a library with `l0_max` under 26.

The detail-carries-the-goal design is unaffected.

## Should fix

### S1. A library de-duplicates in its shard encoder, not in `Store::append`

§Current ("Records and de-duplication") and §S4 ("Re-writing a unit
SMYSL already holds") cite `smysl-graph/src/store/mod.rs:434-446`. That is
the bare store's `append`. Through a library, the write path is
`Library::append_records`:

- The shard logs are written first, from
  `crate::shards::encode_by_shard` (`smysl-text/src/library.rs:1355-1372`).
- Only after that does the in-memory store's `append` run, and it "writes
  nothing, having no path" (`:1376-1378`).

The de-duplication that keeps a duplicate out of a **log** is
`encode_by_shard`'s:
`if store.contains_record(&hash) || !seen.insert(hash) { continue; }`
(`smysl-text/src/shards.rs:510-522`).

The claim is true, and criterion 12's "every shard log's length
unchanged" depends on it, but it is cited to code that cannot make it
true for a library. Cite `shards.rs:516-522`.

### S2. A panic mid-write erases SMYSL's crash notice, and criterion 15 then writes again

- §S9 says a panic "unwinds through `catch_panic`. That drops the locks,
  which releases them."
- `Lock`'s `Drop` removes the lock file (`smysl-graph/src/lock.rs:225-228`).
- SMYSL keeps a lock on a crash on purpose: "The stale lock *is* the crash
  notice … A lock that cleaned itself up would make the common case
  quieter and the interesting case invisible" (`:20-23`).

Under D49, Bund2 turns exactly that case into a released lock and a
running program. Criterion 15 then requires that "the next write to that
root succeeds". That write lands on a library which, by Q51's own note
(`library.rs:1364-1379`), may have some shards written and others not.
Nothing records that this happened, beyond D49's report.

This is a change in the guarantee SMYSL's lock gives, and Preservation
does not list it. Either rule it (for example: after a panic in a write,
refuse further writes to that root in this process with a new code,
until an operator acts), or state it as accepted and say why. It may
need a new R point.

### S3. The agent is self-asserted, so `Origin` authority is not a protection inside Bund2

- `smysl.agent` sets any agent that matches the grammar (§S4).
- SMYSL says agent ids are "Self-asserted until COSE signing lands (N9).
  Corroboration is gameable by fabricated attestations until then"
  (`smysl-core/src/ids.rs:523-524`).
- So a program refused SM09 as `tool:bund2` can call
  `"tool:other" smysl.agent` and retract the same unit. It can equally
  write attestations under any human's id.

Criterion 8 tests a refusal that one word bypasses. §S4 says `Origin`
"lets this agent retract a unit it has also vouched for", which reads as
a safeguard.

**Needed:** state that authority is advisory while ids are self-asserted,
as SMYSL states it. Optionally, restrict `smysl.agent` to the `tool:`
kind, which is a ruling.

### S4. `smysl.text.add`'s spec omits fields SMYSL requires, and the defaults Bund2 would supply

`Library::add` takes an `AddSpec` and `Caps` (`library.rs:1008-1013`).
`AddSpec` has these fields (`:86-104`):

- `reader`, `params` and `alias`;
- `lang` and `licence`;
- `carry` and `policy`;
- `title`;
- a pseudonym key.

SMYSL's comment says "`reader` and `policy` are not optional and have no
defaults here … A default in this struct would put the decision back
where the format took it away from" (`:80-85`). The field is
`Option<Policy>`, all the same.

§S4's spec names `path` or `text`, `reader`, `alias`, `licence` and
`lang`. It is silent on four things:

- **`carry`.** `Carry::None` is the type's `Default`
  (`smysl-core/src/types/library.rs:32-36`), and it is recorded in the
  manifest.
- **`policy`.** `None`, or which policy.
- **`params`.**
- **`Caps`.** The defaults are SMYSL-2.4 §3.9.1's
  (`smysl-text/src/limits.rs:27-33`).

An implementation would choose each one silently. Name each default, or
make it a spec key.

Separately, `Input` holds bytes only. "A reader that could open a path
would be a reader the purity gate cannot describe"
(`smysl-text/src/readers/mod.rs:45-53`). So `spec.path` is read by Bund2,
whole, before `Caps.input_bytes` can apply. Say so, and say whether
Bund2 bounds the read.

### S5. "Pins that must agree" is uncited, and one of its three is wrong

§S1 says that SMYSL pins `unicode-segmentation`, `libm` and
`rand_chacha` exactly.

- `unicode-segmentation = "=1.13.3"` is at `smysl:Cargo.toml:68`.
- `libm = "=0.2.16"` is at `smysl-measure/Cargo.toml:42`.
- **`rand_chacha` is `"0.9"`, not exact** (`smysl-measure/Cargo.toml:45`).
  Bund2's lock carries 0.2.2, 0.3.1 and 0.9.0.
- **Omitted:** exact pins in crates Phase 1 links:
  - `caseless = "=0.2.2"` (`smysl:Cargo.toml:73`), a `smysl-text`
    dependency (`smysl-text/Cargo.toml:116`);
  - `pulldown-cmark = "=0.13.4"` (`smysl:Cargo.toml:80`), which
    `reader-md` turns on.

  Neither is in Bund2's lock today, so neither conflicts yet. Both
  constrain any later Bund2 dependency on them.

Cite each pin and correct the list.

### S6. The attestation's clock, hop and parents are unstated

§S4 gives an attestation four fields: agent, `Authored`, "the wall
clock", and the rung.

- **The clock.** `Hlc::now(prev, agent)` advances from a previous clock
  (`smysl-core/src/types/provenance.rs:55-57`). `advance` keeps
  `prev.wall_ms` and increments the counter when the wall has not moved
  past it (`:61-76`). The RFC does not say what `prev` is: `Hlc::zero`,
  or this agent's newest clock in the library. With `Hlc::zero`, an agent
  whose wall clock steps back writes a clock older than its last.
- **`hop` and `parents`.** An attestation also carries `hop` and
  `parents` (`:252-254`), and `trace`'s `parents` kind follows attestation
  parents (`smysl-graph/src/lineage.rs:30`).
  - `Attestation::new` leaves `hop` at 0 and `parents` empty (`:269-282`).
  - So `smysl.trace … "parents"` over an exported conclusion finds
    nothing, though its premises are known.

Say what each field holds. The answer bears on R15. Q55 is in part
settled here: `Attestation::new` and `Hlc::new` are public (`:33`, `:269`).

### S7. Retraction differs from SMYSL's own command in two ways the RFC does not state

SMYSL's `retract` (`smysl:src/main.rs:4486-4505`):

1. returns "already retracted; nothing to do" when `effective_status`
   already reads the target as retracted, **before** it checks authority;
2. writes the self-edge with **no attestation**.

§S4 does neither, yet says it "follows SMYSL's own sequence".

- Under §S4's rule, "every unit and relation Bund2 writes is followed by
  one attestation", the edge gets one. If another agent's retraction
  already wrote the same content-addressed edge, Bund2 attests that
  agent's edge.
- A target already read as retracted through a non-self `retracts` edge
  gains a second, self-edge retraction.

Neither is wrong, but each is a difference from SMYSL. Either follow
SMYSL in both, or state the differences. Criterion 8 should then cover
the already-retracted case.

### S8. `"rests-on"` is SMYSL's own trace kind, but `smysl.trace` calls it unknown

- `TraceKind` has four kinds, the fourth spelled `"rests-on"`
  (`smysl-graph/src/lineage.rs:37-39,54`), and §Current lists it.
- §S5 offers `parents`, `grounds` and `both`, plus Bund2's own
  `"dependents"`. "Any other `kind` is SM05", whose text is
  `unknown trace kind: rests-on`.

That message is false: SMYSL knows the kind. Either map `"rests-on"`, or
refuse it with a text that says Phase 1 does not offer it. Say why it is
left out.

## Preservation: what is missing

- **SMYSL's crash notice** (S2). A panic in a write releases the lock,
  which a killed SMYSL process would not do, and the program writes on.
- **Authority** (S3). `Origin` holds against SMYSL's CLI used honestly,
  and against nothing inside a Bund program.
- **The manifest's carry mode and part policy** (S4). They are recorded
  in every manifest Bund2 writes, so their defaults are part of what
  Bund2 produces.

The other rows hold. The `UNVARIED` and `FEATURE_GATED` rows were checked
against the audit's code, and the `REENTERING` row against its list,
which already has `kb/query.rs: run_query` for RFC-0013's runner.

## Assumptions the RFC makes but does not state

1. **The library's views are trustworthy inputs to a write.** Under B1's
   fix, a view decides how long an exported gist may be. A view another
   agent appends can therefore change what Bund2 writes next.
2. **The process's wall clock is monotonic enough for an HLC** (S6).
3. **A panic in a write leaves the library fit for the next write** (S2).
4. **`spec.path` is read whole into memory** before SMYSL's caps apply
   (S4).
5. **A surface document's labels are last-wins within the document**
   (`smysl-graph/src/labels.rs:10`). So `smysl.parse` followed by
   `smysl.append` keeps only the last binding of a label the document
   rebinds. Criterion 5's documents should say whether any label is
   rebound.
6. **The agent a handle names is the program's own** (S3).
