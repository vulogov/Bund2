## Blocking

**B1 — The commit carrying this RFC's answers failed the gate it declared,
on the first push, and three dated notes now say the opposite of the
workflow record. Read L5095–5098, L7024, L7050–7051, L9426–9428, and `gh
run view 38432025619`.** `9f997dd` says in its title "a gate on this
branch" and in criterion 2's note that `ci` "has not run as edited". It ran
on that push. Its `conformance` job passed all three configurations; its
`check` job **failed** at `cargo test --workspace --features
jit,relocation-test`: `error: field `text` is never read`, in `bund2-jit`
(lib test), because the `Probe` field the new aarch64 test reads is unused
on x86-64 and `ci` denies warnings. `linux-reading` 38432025727 at the same
commit failed its `reading` job at `clippy` on the same error. So at the
RFC's own commit the tier's test binary did not build on the one other host
it has, and the test added to answer B3 is what broke it. The fix is
`126e518`, ten lines, which the RFC does not mention; six `ci` runs since
have passed every job.

What the document now says that the record contradicts:

- L5097–5098, criterion 2: "the workflow has run once, on `main` on
  2026-09-11, and failed; it has not run as edited." Eight runs on this
  branch since; the `conformance` job passed in all eight, including at
  `9f997dd`. Criterion 2 **is** held by `ci` now, and the note lists `ci`
  as one of "two things it is not held by".
- L9426–9428, the amendment: the same sentence.
- L7024, criterion 15: the `cargo tree` step "has not run on a GitHub
  runner." It is in the `check` job, which has passed six times.
- L7050–7051, criterion 15's note of 2026-10-11: `ci.yml` "has not yet run
  with these steps." It has.
- The status block (L117–137) names `linux-reading` run 38355924002 and
  does not name `ci`, which D150's note of this date makes the gate and
  which has the only Linux run of the tree with D152's changes in it.

Every one of these is a dated note and was true when written. The RFC's own
practice, applied at every earlier review, is that a note overtaken by the
record gets a dated correction beneath it. The one fact that is not merely
stale — the RFC's commit could not build its tests on Linux, and a test
written to close a blocker is why — belongs in the amendment, because "B3
answered by a test" is a claim about a test that, at that commit, no CI
host could compile.

**B2 — The test that answers B3 compares code emitted under an
instruction-set configuration that is not the shipped one, and the RFC
calls it "the shipped settings" three times. Read `lower.rs:3734-3750`,
`:2565-2569`, `cranelift-native` `src/lib.rs:111-138`, and L4800–4802,
L5995–5999, L9459–9463.** The shipped module is built from
`cranelift_native::builder()` (`new_module`, `lower.rs:2565`), which calls
`infer_native_flags` and, on aarch64, enables `has_lse`, `has_pauth`,
`has_fp16`, `has_dotprod` and `has_i8mm` as the CPU reports them, and on
macOS unconditionally enables `sign_return_address` and
`sign_return_address_with_bkey` (`lib.rs:111-138`). The probe is built from
`lookup_by_name("aarch64-apple-darwin")` with the shared flags it is passed
and **no ISA flags** (`lower.rs:3734-3750`). So on the host every figure was
taken on, every function the tier ships is emitted with return-address
signing in its prologue and epilogue, and every function the test compares
is not. The test shows that `preserve_frame_pointers` changes no instruction
of a body emitted without pointer authentication; the shipped bodies are
emitted with it. Whether the frame-pointer setting interacts with a signed
prologue is a question about Cranelift's aarch64 ABI code that nothing here
reads, and it is the same question B3 asked. The likely answer is "no
change"; the criterion does not get to assume it, which is what the
twenty-fifth review said of the comment this test replaced.

Two smaller things about the same test. It is named at L4800, L5995 and
L9460 as a test "in `crates/bund2-jit/src/lower.rs`", and no mention says
it needs `--features relocation-test`: `cargo test -p bund2-jit --features
jit the_shipped_settings` runs zero tests (the module is
`cfg(all(test, feature = "relocation-test"))`, `lower.rs:3694`). And it is
`cfg(target_arch = "aarch64")` (`:3944`) while both workflows run on
`ubuntu-latest`, so no CI host runs it; it has run on the author's machine
and in this review. Both belong in the sentence that names it.

The fix is either a sentence — the comparison is under the triple's default
ISA flags, not the host's inferred ones, and the claim is scoped to that —
or a probe built from `cranelift_native::builder()` so that "the shipped
settings" is true as written. The second also makes the test's
frame-record count mean what its comment says.

   2026-10-12 that is not emitted code (S4).

   on x86-64 is "the tier's own tests" for CI purposes; the one test that
