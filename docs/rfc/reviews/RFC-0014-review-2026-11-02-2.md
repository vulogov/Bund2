## Blocking

### B1. Criterion 12 cannot pass as written

- **Gists exceed SMYSL's bound.** `smysl.check` with SMYSL's default
  profile uses `standard()`: `l0_max: 30` tokens, with estimator `Unset`,
  which is `Utf8Div4` (`smysl-core/src/types/view.rs:122-131`;
  `estimate.rs:237`).
  - So a gist over about 120 bytes is `SMY-E022`, an error
    (`check/passes/shape.rs:42-48`).
  - A uid is `b3:` plus 52 characters (`ids.rs:34-36`), quoted by §S7.1.
  - Any goal rendered with two uids, such as `[ grounds "b3:…" "b3:…" ]`,
    is about 128 bytes.
- **Bodies fall short of SMYSL's minimum.** A body made of a few premise
  gists falls under `l1_min: 40` tokens and gets `SMY-W041`
  (`granularity.rs:53-68`). So the library is never "clean", and `check`'s
  LIST is never empty (§S4).
- **"Proving the same goal twice writes nothing the second time" is false
  under R15.** The store dedups by the hash of the *whole record*,
  attestations included (`store/mod.rs:437-444`). A wall-clock attestation
  makes every re-write new bytes. SMYSL says so itself: "a rerun adds an
  attestation" (`smysl-measure/src/lib.rs:28-29`).

**Fix:**

- Name the `CheckOptions` and profile `smysl.check` uses.
- Define "clean" as "no `E`-severity code", or render long gists by label
  or truncation, as a rule of its own.
- Restate the second-run clause as "no new unit uid", or supply a fixed
  `Hlc` per proof.

### B2. `smysl.merge` has no SMYSL operation under it

- `smysl_graph::merge(store: &mut Store, …)` appends to a bare `Store`
  (`merge/mod.rs:100-108`).
- A library's store has no path, so its `append` "writes nothing, having
  no path" (`library.rs:1377-1378`). Merging into `library.store`
  persists nothing.
- SMYSL's CLI merges store *files* only (`cmd_merge`, `src/main.rs:4181`:
  `load_store`, then `merge`).
- Nothing says how texts, manifests, or the second library's locks are
  handled.

**Fix:** design it over `append_records` plus `contention::detect`, with
the second library read under its own locks, and add a question for the
text objects. Or drop the word from Phase 1.

### B3. `smysl.retract` bypasses SMYSL's retraction authority, and its edge shape differs from SMYSL's

- `effective_status` retracts every target of a `retracts` edge, whoever
  wrote the edge (`retraction.rs:83-88`).
- `Origin` authority is enforced only by `plan_retraction` (`:181-209`),
  which the CLI calls and obeys before writing (`main.rs:4437,4485-4490`).
  §S4's word "appends a `retracts` edge" with no authority check.
- So revision 2's answer to S9 ("authority stays SMYSL's default") is not
  implemented: any Bund program can retract any unit.
- SMYSL writes a retraction as `Relation::new(Retracts, target, target)`
  everywhere (`retraction.rs:218`, `main.rs:4496`, `compact.rs:260`,
  `integrity.rs:170`). §S4 writes "from `by` to `uid`".

**Fix:** make `smysl.retract handle uid → rid` write the self-edge after
`plan_retraction`, with the handle's agent and `Origin` authority. Give a
refusal with its own SM code, and add a criterion that retracting a unit
another agent attested is refused.

### B4. The proof-node table misreads RFC-0013 §S15 and contradicts itself

- **`once` is not transparent.** It is `[ goal ← p ]` (RFC-0013 §S15's
  table, and D230's note). By shape it cannot be told from a one-premise
  rule, so criterion 12's "`call` and `once`" test asks for a distinction
  the tree does not carry.
- **`rank` facts are classified two ways.** The fact table says they
  "stand for nothing", but the provenance rule says "every other fact node
  is a program fact", which becomes a `speculative` claim. So any rule that
  compares ranks is capped at `speculative`, and no row of the node table
  says otherwise.
- **§S7.1 renders terms, but `kb.prove` gives values read back.** RFC-0013
  §S15 gives "the goal, read back as the answer instantiated it", and its
  §S1 read-back table maps `true` and `false` to BOOL, and an improper tail
  to `|` followed by the value. §S7.1 has no BOOL row and no row for an
  improper list.

**Fix:** treat `once` as a rule, or say it is indistinguishable from one.
Add a node row "a fact standing for nothing → no ground" and route `rank`
there. Define §S7.1 over RFC-0013 §S1's read-back values, with BOOL and
improper-list rows, and extend criterion 13 to match.

## Should-fix

**S1. `REENTERING` cannot simply "list `smysl.prove`".** The audit is an
exact-set source scan of direct callers (`lib.rs:1609-1693`).

- If `smysl.prove` calls the engine directly, its own function never
  calls eval, the scan does not find it, and naming it fails the
  `assert_eq!`. `kb.prove` itself is not listed; `kb/bridge.rs: run` is.
- The scan reads sources whatever the features, so "CI runs `--features
  smysl` so the audits see the words" is wrong for this audit.

*Fix:* state the call path. Name the runner function as `"<file>: <fn>"`,
and name `smysl.prove` only if it goes through `Vm::apply`. Reword
criterion 16.

**S2. §S5's advice for keeping a measure is refused by §S2, and leaves a
dangling ground.**

- The result's `unit` is "§S2's MAP", which carries `uid`, and §S2
  refuses a MAP carrying `uid` with SM03.
- A measure unit is grounded on a `Basis` (a saved scope unit plus edges)
  that is "to be appended with the result"
  (`smysl-measure/src/scope.rs:52-60`; `lib.rs:8,421-436`). Under R17 A,
  neither is appended.

*Fix:* either give `smysl.measure` a way to save the result with its
`Basis`, or say exactly what to append. Strip `uid` from the result's
`unit`.

**S3. `smysl.trace`'s kinds do not exist.**

- `TraceKind` is `parents | grounds | both | rests-on`, and `grounds`
  already covers both `grounds` and `deps` (`lineage.rs:29-55`).
- "Dependents" is a separate function (`dependents_trace`, `:389`;
  `dependents`, `:296`).

*Fix:* map the kinds to SMYSL's, and name the call for dependents.

**S4. Criterion 5's corpus.**

- 17 of the 60 `.smy` files carry `status: measured`, including
  `fixtures/corpus/F1,F2,F4,F5,F7,F8a,F8b,F9`. §S4 refuses `measured`
  (SM03), and the criterion's filter does not exclude it.
- "`smysl.parse` again gives the same ids" is undefined, since `parse`
  returns MAPs without ids.

*Fix:* filter out `measured`, `@x` and `@doc` records, and compare the
uid LISTs `smysl.append` answers on each pass.

**S5. Criterion 4 is tautological.** Hashing "the same core" in the test
checks `canonical_uid` against itself. *Fix:* compare against the uids
SMYSL computes from an equivalent `.smy` text through `parse_surface`, or
against uids recorded in SMYSL's fixtures.

**S6. R13's mutex.**

- A panic inside a write, caught by D49, poisons the root's
  `std::sync::Mutex`. Every later attempt to lock it returns
  `PoisonError`, and D37 forbids `unwrap`.
- `smysl.prove` re-enters evaluation through bridges. If it holds the
  root's mutex or SMYSL's locks while solving, a bridge that calls
  `smysl.unit` on the same root deadlocks on itself, or meets SM07.

*Fix:* solve every answer first, then lock and write. State the policy for
a poisoned mutex: recover with `into_inner` and report, or give it an SM
code.

**S7. The §S2 view loses more than it says.**

- `SourceRef.observed`, `published` and the part range are hashed
  (`epistemics.rs:349,371-375`), but they are absent from the `source`
  MAP and do not set `opaque`.
- `Subject::Store` has no mapping, and `Span` is a byte range, not
  `line:col` (`diag.rs:510-523`).

*Fix:* map them or flag `opaque`. Give `subject` all four cases.

**S8. D38 is not this precedent.**

- D38 covers "third-party crates the reference uses", whose output the
  goldens capture.
- `deny.toml:72` justifies `algos` as "the revision the oracle links
  (D38)". SMYSL is neither.

*Fix:* cite D38 for the mechanism only. Make the `allow-git` entry R2's
own ruling, with its own comment in `deny.toml`.

**S9. The registers have drifted from revision 2.**

- Q52 still says "D51's rule … turns on it", which the fix to the first
  review's N11 withdrew.
- Q54 still describes "a stamp-checked cache" and "measure before the cache
  is built".
- Q51 still says "RFC-0014's R5 B, a batch word", but R5 B is now
  single-record.
- D244's heading still says "R1–R12".
- D244's *Depends on* omits D38, D18 and D168, which the RFC consumes.

*Fix:* append dated notes; do not edit history.

**S10. Refusals still have gaps.**

- There is no text for stack underflow. RFC-0013 §S12 uses the house E00.
- There is no code for an operand of the wrong type that is not a MAP or
  a handle: `root`, `text`, `depth`, `uid`.
- The `smysl` conditional's runner has no codes for a missing or
  wrong-typed slot, or for an error raised in `lambda` (RFC-0013's E08,
  E25).
- An unknown `opts.facts` status could be either SM03 or SM05.
- For the E-codes `smysl.prove` re-raises, it is unsaid whether the prefix
  is `KB.PROVE:` or `SMYSL.PROVE:`.
- A hand-built handle with a malformed `agent` passes SM00, since only
  `smysl.agent` validates the agent.

*Fix:* add the rows, and validate `agent` as part of SM00.

**S11. The order of opening and locking is unstated.**

- SMYSL opens the library, reads `library.shards()`, then locks
  (`main.rs:8618-8628`). Another process can append between the open and
  the lock.
- U2 omits `Library::shards`.

*Fix:* specify the order (lock the library, open it, lock the shards), or
record the race as SMYSL's and add a question.

**S12. CI and features.**

- Criterion 17's example test lives in `bund2-cli`, but CI is given only
  `cargo test -p bund2-stdlib --features smysl`.
- The CI `feature matrix` step runs `cargo check` (`ci.yml:54-59`), not
  the tests.
- The `deny` job runs without features (`ci.yml:107-112`), so criterion 2
  is never gated.
- `features_built_in` needs a `SMYSL_BUILT_IN` arm, as it has for
  `GROK_BUILT_IN` (`main.rs:54`).
- `bund2-runtime` has no feature to forward.

*Fix:* name each CI step, and the new constant.

## Notes

- **N1.** `catalog` maps aliases to heads, so criterion 6 holds only when
  each alias has one text. Say so.
- **N2.** Reword the `check` sentence as: the `csv | sqlite | query` arm;
  other types it does not list are abandoned.
- **N3.** §A's "Every write is made with the library's locks held" reads
  as a guarantee SMYSL makes. In fact the *caller* must hold them
  (`library.rs:1004-1007`).
- **N4.** Salience and packing are uncited. They are at
  `smysl-graph/src/salience.rs:229` and `smysl-pack/src/solve.rs:242`, and
  rebuttals travelling with what they rebut is `smysl-pack/src/lib.rs:9`.
- **N5.** "`measured` … only by import" is uncited. It is
  `epistemics.rs:325-327` and `trust.rs:4-6`.
- **N6.** "The reference stubs only words that do I/O" generalises from one
  file. Cite the survey: 16 `cli.noio` sites, for example
  `io/banner.rs:82`.
- **N7.** §S2's status row lacks `unfounded`, which `smysl.status` and
  `[ effective … ]` can yield.
- **N8.** `AddSpec.licence` is a required `String` (`library.rs:95`), but
  §S4 calls it optional. Give the default.
- **N9.** `generate-words.sh` runs whatever `bund2` is on the PATH, not
  necessarily "the default build".
- **N10.** Criterion 3 is tagged [R2], but R2 rules the source, not the C
  compiler. Give it an R-point of its own or drop the tag.
- **N11.** The `smysl` conditional flattens `groups` and drops each group's
  key; say so, as the RFC does for `ranked`. State `smysl.prove`'s effect
  as `opaque(4)`.
- **N12.** The root is "made absolute", not canonicalised, so two
  spellings of one directory get two mutexes, and then SM07 between them.
  The first review's S12 is only partly answered.
- **N13.** "The weakest status in G": declared or effective? Rule M uses
  the declared status (`check/passes/epistemics.rs:63-69`); say so.

## Assumptions not stated

1. `smysl.check` runs with `CheckOptions::default()`, which is the
   `standard` profile (B1).
2. A wall-clock `Hlc` is acceptable, although SMYSL takes its clock as an
   input to keep outputs a function of inputs (`dossier/mod.rs:126-127`;
   `merge/mod.rs:47-50`).
3. Nothing writes between `Library::open` and `acquire_all` (S11).
4. Proof goals render identically after RFC-0013's read-back, with BOOL
   coercion applied and aliasing lost (B4).
5. `dossier::ask` works without the `stem` feature that rule 26 reads
   (`dossier/mod.rs:318-319`), and with a template set this build carries
   (`SMY-E477`, `:118-119`).
6. A whole library's facts fit in `smysl.kb`'s KB within RFC-0013 §S2's
   limits on wire depth and the memory guard.
7. A poisoned `Mutex`, and re-entry while a lock is held, are acceptable
   under R13 (S6).
