## Should fix

### SF1. `nstart` with a MATRIX of centres is a departure no decision covers (RFC:705-707)

§S6 makes `nstart` "E101 with a MATRIX of centres, where R ignores it".
- R's `kmeans` runs further starts only when `cn` is non-NULL
  (`kmeans.R:126`), and `cn` is NULL for a MATRIX (`:111`). So R ignores
  `nstart` silently.
- The refusal is a departure from R, but no **[V*n*]** or **[author]**
  marker covers it.
- D277's V6 rules only where R *warns* of a failure, and none of D278's
  fourteen choices names it.

CLAUDE.md asks that an unplanned deviation go to the register before
code.

**Fix:** take it to the owner as a small decision (refuse, as written,
or ignore it as R does), or follow R. RFC-0016 §S1's options-MAP rule
does not decide it, because `nstart` is a key the word does take.

### SF2. The order of a user's `prior` is not stated (RFC:771-777)

`mva.lda`'s `prior` is "a LIST of g non-negative numbers", and
`mva.lda.predict`'s `prior` defaults to the fit's. Neither says which
group each entry belongs to. In R a prior is matched to
`levels(grouping)` by position (`lda.R:89-92`).

**Fix:** state that a `prior` follows `lev`'s order, that is §S1's order
or `levels` when given. Then criterion 7's reversal test can check it
too.

### SF3. An editing slip moved half of §S1's "Data matrices" bullet into "Overflow" (RFC:520-523)

The "Overflow" bullet now reads "… naming the expression. A frame
reaches them through `frame.matrix`, whose `na` option decides missing
values (RFC-0017); no word here takes a frame or a NONE cell." The
"them" refers to data matrices, two bullets above.

**Fix:** move the sentence back to the end of "Data matrices".

### SF4. §S1's account of R's `density` is uncited and imprecise (RFC:512-513)

§S1 says `density` "drops them [non-finite values] too, keeping the
sub-density". R 4.4.2's `density.default` does not treat NA and ±∞
alike:
- it **stops** on NA unless `na.rm = TRUE`, "'x' contains missing
  values" (`density.R:57-69`);
- it **drops** ±∞ and keeps the mass nx/N (`:72-82`), which is the
  sub-density.

The refusal D278 ruled is unaffected, but the sentence is a claim about
R without a citation.

**Fix:** cite `density.R:57-82` and split NA from ±∞.

### SF5. The R-dependency rule covers x₁₀₀₀ but not the datasets (RFC:1018-1034)

§Acceptance criteria says that no test runs R, and that x₁₀₀₀'s values
are written into the fixture "since Bund2's generator is not R's". But
criteria 3, 6 and 7 use R's datasets `USArrests`, `eurodist` and `iris`,
and criterion 10 likely uses one too. Those values exist in Bund2 only
if a script writes them out.

The rule implies they are committed, but the RFC states it for x₁₀₀₀
alone.

**Fix:** state that each dataset a test uses is written by its `.R`
script into the committed fixture, as x₁₀₀₀ is, with its R version.

## Notes

- **N1.** Hotelling's and MANOVA's Cholesky floors apply to the same
  quantity but take different values.
  - The pivot `fit.mle` tests is d_j = L_jj², before the square root
    (`fit/mle.rs`, `inverse`, `PIVOT_FLOOR` = 1e-8).
  - So §S7's Hotelling floor is 10⁻⁸ on d_j, and MANOVA's is 10⁻¹⁴ on
    d_j.
  - The reasons differ: `fit.mle`'s precedent for Hotelling, and R's
    10⁻⁷ squared for MANOVA.

  Both are defensible, but §S7 should say that the quantity is the same
  and why the floors differ. A reader comparing the two otherwise sees
  an inconsistency.
- **N2.** Criterion 4's last bullet reads "…(E101), and under `ward.D2`
  the three-object input … (E101); `cluster.dist` an overflowing
  distance (E114)." The clause after the semicolon has no verb. It
  should read "and `cluster.dist` refuses …".
- **N3.** §S1 says "Group order changes no statistic". It does decide
  one answer: an exact posterior tie takes the first group in that order
  (§S8; D278 choice 7). Say "no statistic and no class except on an
  exact tie".
- **N4.** `stat.ecdf` and `stat.ecdf.at` on an empty series, and
  `stat.ecdf.at` with a non-finite `t`, are not specified. R stops on an
  empty `x` (`ecdf.R:27`), answers NaN for a NaN query, and gives 0 or 1
  at ∓∞. B12 decides NaN. Whether ±∞ is answered (0 or 1) or refused is
  the RFC's to state.
- **N5.** The ports of `hclust.f`, `kmns.f`, `kmeans.c`, `pretty.c`,
  `density.R`, `bandwidths.c` and MASS's `lda.R` are line for line, so
  Bund2's versions derive from GPL code. R is GPL-2 or later, and MASS
  is GPL-2 or GPL-3. Bund2's `LICENSE` is Apache-2.0.
  - D216 already allows GPL code in the build ("a binary distributed
    from this workspace carries GPL-3.0-or-later"), and RFC-0019's ports
    of `zeroin`, `nmmin` and `vmmin` took the same path.
  - So the RFC adds no new exposure, but it should cite D216 where it
    says "ported line for line", so the reason is on record.
- **N6.** Some criteria leave their inputs to the implementer, with R or
  a definition as the check:
  - criterion 2 (the SVD's matrices);
  - criterion 4 (the untied and inversion inputs);
  - criterion 5 (k-means' ties and transfer passes).

  That is acceptable where the check is computed from the input, but
  each milestone should commit the inputs it chose.
