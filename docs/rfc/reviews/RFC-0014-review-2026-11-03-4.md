# RFC-0014 review: Draft revision 12, 2026-11-03 (eleventh review)

Adversarial review, independent of the ten before it. The RFC and the
sources were read first, and the earlier reviews only afterwards, to drop
findings already raised and answered. Nothing was edited or built, apart
from running `cargo xtask cite`. Read against Bund2's working tree at
b163a68, the `reference/` submodules (whose `git status` is empty), and
SMYSL at 4f5ecb9 ("Merge 1.14.0"), opened file by file. SMYSL citations
are relative to its crate directory, as the RFC writes them.

Revision 12's changes were checked hardest:

- `smysl.parse`'s label source and its refusal of a document that did not
  parse whole;
- the rule that decides a MAP's kind;
- the uid-or-label rule for `grounds` and `deps`;
- the label MAP's `uid` check;

**Verdict: Ready once the should-fix items are answered. 0 blocking,
2 should-fix, 14 notes.** D244 and D245 are not re-argued. Revision 12's
answers to the tenth review's S1–S4 hold against the source. The
should-fix items:

- `smysl.write` does not write "every unit … the library holds".
  SMYSL's writer silently leaves out every unit that has no surface form,

## Citations checked

`cargo xtask cite` reports 0 DEFECTS, and none of its advisories is in
RFC-0014. The tool does not read SMYSL citations. Every SMYSL citation
below was opened by hand at 4f5ecb9.

These hold at their lines and say what the RFC says:

- **Labels in a parse.**
  - `smysl-core/src/surface/parse.rs:12-14` says labels are resolved to
    uids in a second pass.
  - `:2596-2606` emits one `Record::LabelBinding` per entry of the
    resolved map, after every `Record::Unit` (`:2585-2594`).
  - `:63` is `ParseOutcome.labels`, and `:2793` stores the same map.
  - Each binding is `LabelBinding::new(label, uid)`, with an empty
    `extra` (`smysl-core/src/types/annex.rs:488-501`).
  - The uid is the `canonical_uid` of the core the parser pushes
    (`parse.rs:2870-2873`).
  - So "reads labels from the records only" reads the whole set, once.
- **Recovery.**
  - `parse.rs:1-6` holds.
  - `:66-67` is `recovered`.
  - `:348-352` is `recover`, which counts one.
- **Severity.** Severity is binary: `Warn` or `Error`
  (`smysl-core/src/diag.rs:32-35`). It is fixed by the code's letter,
  which a test asserts (`:732-746`). So "any diagnostic of error
  severity" is SMYSL's own `ParseOutcome::has_errors`
  (`parse.rs:121-123`), and SMYSL's `fmt` refuses on exactly that
  (`smysl:src/main.rs:2635-2638`). That makes `smysl.parse`'s refusal
  SMYSL's own rule. Cite it.
- **`ParseError`'s `Display`.** It begins with the code
  (`smysl-core/src/error.rs:234-247`), so SM02's text column holds for
  the hard errors.
- **The second label.** `smysl-core/src/surface/write.rs:51-61`
  (`from_labels`) keeps the first label per uid in canonical order. The
  parser keeps the same one and warns `SMY-W054` for the rest
  (`parse.rs:2529-2550`).
- **The label grammar.** A uid begins with `Uid::PREFIX`, and `Uid::parse`
  rejects any shorter form (`smysl-core/src/ids.rs:69-90`). A label is
  `ident/ident` in lower case, with no `:` (`Label::new` through
  `label_shaped!`, `ids.rs:442-466`). So no STRING is both, as §S2 says.
- **The constructor.**
  - `query` is `StackEffect::fixed(0, 1).leaving(Leaves::Conditional("query"))`
    (`crates/bund2-stdlib/src/kb/query.rs:157`).
  - The checker's `"csv" | "sqlite" | "query"` arm reads `Slot::Absent`
    as an empty body (`crates/bund2-stdlib/src/check.rs`, the conditional
    match).
  - D181 (`docs/registers/decisions.md`, "D181 — a native declares what
    it leaves on top") is the rule the RFC now consumes.
- **The lock's command.** `acquire_all(library_root, shards, command)`
  (`smysl-text/src/lock.rs:24-43`) passes the command to each
  `Lock::acquire`. `Holder`'s `Display` is ``pid <n> on <host> running
  `<command>` `` (`smysl-graph/src/lock.rs:44-52`), so `bund2 <word>` is
  what SM07 prints.

These do not support the claim as written:

- **`parse.rs:2553-2562`** is cited for "an unresolved label is
  `SMY-E060`, which drops the reference". Those lines are `lookup`. It
  serves relations, threads, withdrawals, resolutions, commitments,
  redactions, datings and view roots, and each of those drops the
  **whole record** when a reference fails (for a relation, `:2608-2614`,
  `continue`).
  - The case criterion 5's eighth document tests, a label in `grounds`,
    goes through `resolve` instead (`:2836-2846`).
  - That function's doc comment says E060 and E061 "drop the offending
    reference and keep the unit" (`:2800-2804`), so the unit is kept
    with fewer grounds and a different uid.
  - Both halves support the refusal. Cite both, since they lose
    different things. See N1.
- **"SMYSL's one hard error (`:3-6`)".** `ParseError` has three
  variants: `SMY-E001` (an unparseable header), `SMY-E002` (a kernel
  major) and `SMY-E003` (a format version)
  (`smysl-core/src/error.rs:202-210`). All three are raised by
  `doc_header` (`parse.rs:823-870`). See N2.
- **`ids.rs:500-507`** is cited for the label syntax. Those lines are
  the `label_shaped!(Label, …)` invocation and its doc string. The
  grammar is in the macro's `new` and in `is_ident`
  (`ids.rs:442-466`). See N9.

## Should fix

### S1. `smysl.write` silently leaves out every unit SMYSL's writer cannot spell, and `smysl.unit` can write one

§S4's `smysl.write` row says:

> the surface syntax of every unit, relation and label the library holds.

**Evidence.**

- **The writer skips units with no surface form.** `write_surface` writes
  a unit only `if unit_has_surface_form(u)`
  (`smysl-core/src/surface/write.rs:158-164`). Every other unit is
  skipped with no diagnostic.
- **Which units have none** (`write.rs:267-295`):
  - a unit with a non-empty `extra`;
  - a unit whose source has a non-empty `extra`, or an unknown kind;
  - a unit with an undecodable payload;
  - a unit whose decoded payload has a key in `UNIT_HEADER_WORDS`,
    which is `status`, `deps`, `grounds`, `source` and `salience`
    (`:252`). For these the writer's comment says "a payload key named
    `status` cannot be spelled" (`:256-258`).
- **Labels go with the unit.** A label is written only as part of its
  unit's header (`write.rs:203-204,217`), so the unit's labels are lost
  with it.
- **SMYSL itself warns about this; the RFC does not.** SMYSL's CLI counts
  such records with the writer's own predicate, `has_surface_form`, and
  warns "N record(s) have no surface form and were omitted"
  (`warn_surface_omissions`, `smysl:src/main.rs:5702-5720`). It does
  this for `merge` and `bundle` (`:4169,4355`). The registry has a code
  for it: `SMY-W428`, "Records with no surface form were left out of a
  surface export; counted per type" (`smysl-core/src/diag.rs:431`). The
  RFC says neither what `smysl.write` does with such a unit nor that it
  reports anything.

Bund2 can write such a unit itself. §S2 requires `payload` to be a MAP
and refuses nothing about its keys. So `smysl.unit` of `{ schema:
"claim", gist: "…", payload: { status: "open" } }` succeeds, and
`smysl.write` then answers a text without that unit. A relation naming
it is still written, by uid, so the text parses cleanly. `smysl.parse`
and `smysl.append` of that text into a second library then give a
library short one unit, with no refusal and no `Warning`. That is the
outcome revision 12's new Preservation row ("A parsed document") was
written to rule out, reached through the other half of the round trip.

The read-back cases are the same set as §S2's `opaque` units (an `extra`,
a source `extra`, an unknown source kind, an undecodable payload),
plus header-word payloads, which `opaque` does not flag.

**Needed.**

- Say that `smysl.write` omits what SMYSL's writer omits. It should
  report one `Warning` counting the omitted records by kind through
  `has_surface_form`, as SMYSL's CLI does.
- Either refuse a payload key in `UNIT_HEADER_WORDS` on write (SM03),
  so every unit Bund2 writes can be written back, or add it to the
  Preservation table.
- Add a criterion 18 case: a library holding a unit whose payload has a
  `status` key, and one with an unknown source kind. `smysl.write` omits
  both and reports the `Warning`.
- Correct the row's "every unit".

### S2. "Every word canonicalises", with SM01 on failure, reaches `smysl.agent`, which R11 leaves unstubbed because it does no I/O

§S2 says:

> **Every word canonicalises the root it is given again**, before it
> takes §S9's mutex, …

and revision 12 adds that a failed `std::fs::canonicalize` is SM01. R11,
as ruled (`docs/registers/decisions.md`, D244 R11 A), stubs every word
that touches disk under `--noio`, "except `smysl.parse` and
`smysl.agent`". The Preservation `--noio` row gives the reason: they "do
no I/O". Criterion 18 says "Under `--noio`, `smysl.parse` and
`smysl.agent` work".

**Evidence.** `smysl.agent` is a word given a handle, so the rule as
written covers it. `std::fs::canonicalize` resolves the path through the
filesystem, and fails when the path does not exist. So, as written:

- `smysl.agent` reads the filesystem under `--noio`, which contradicts
  R11's premise;
- `smysl.agent` of a handle whose directory has not yet been created,
  or has been removed, is SM01. A program that builds a handle by hand
  for a library it will create on another host cannot set its agent;
- criterion 18's `--noio` case passes or fails depending on whether the
  test's handle names an existing directory.

The rule exists so that writers find the same mutex (§S2: "so a
hand-built handle with another spelling of the same directory still
finds the same mutex"). `smysl.agent` takes no mutex and opens nothing.

**Needed.** Say that `smysl.agent` validates the handle (SM00) and
neither canonicalises nor checks the root. Narrow "every word" to the
words that open the library or take the mutex. Have criterion 18's
`--noio` case use a handle whose root does not exist.

## Notes

- **N1. The two E060 paths.** Cite `parse.rs:2836-2846` and `:2800-2804`
  for an unresolved label in `grounds` or `deps`, which keeps the unit
  with fewer grounds, beside `:2553-2562` and `:2608-2614` for a

- **N2. Three hard errors, not one.** `SMY-E001`, `E002` and `E003`, all
  from the `@doc` header (`smysl-core/src/error.rs:202-210`;
  `parse.rs:823-870`). The design is unaffected, since every
  `ParseError` is SM02, but "one hard error" should read "a `ParseError`,
  which only the `@doc` header raises".
- **N3. SM02's parse text drops where the error is.** It joins
  `<code>: <message>`. SMYSL's `Diagnostic` `Display` also writes the
  subject, `(at <span>)`, and any suggestion, `[try: …]`
  (`smysl-core/src/diag.rs:605-619`). Without the span a program cannot
  find the malformed record in a long document. Use the `Display`.
  Separately, say whether a refused document's warnings are still each
  reported as a `Warning`.
- **N4. `smysl.parse` drops comments and authored salience without a
  word.**
  - Comments are counted in `ParseOutcome.comments` (`parse.rs:70-75`,
    `:370-373`), "so that a *writer* can say so instead of deleting a
    reviewer's notes in silence". SMYSL's `fmt` warns when there are any
    (`smysl:src/main.rs:2640-2649`).
  - Authored salience is kept off the records, in `ParseOutcome.salience`
    (`parse.rs:44-46,2587-2590`), and `fmt` writes it back (`:2657-2658`).
  - The "A parsed document" Preservation row's claim holds only for
    records. Name both losses in the row, and report a `Warning` for
    dropped comments, as `fmt` does.
- **N5. §S9 contradicts §S6 on the constructor.** §S9 still says "Every
  word but `smysl` and `smysl.prove` has a fixed effect". §S6 now
  declares `smysl` as `StackEffect::fixed(0, 1)`. What re-enters is the
  conditional's handler, not the constructor; say so.
- **N6. The kind rule leaves gaps.**
  - Unknown keys on a unit or relation MAP are not addressed. The label
    case says a stray key is SM03, but §S2 never says so for the other
    two kinds.
  - A relation MAP missing `to`, or a unit MAP missing `gist`, falls to
    step 4 and is told "record is not a unit, relation or label" rather
    than which key it lacks.
  - SM03's "When" column lists none of revision 12's four new cases: no
    kind; the wrong kind for the word; a label `uid` that names no unit;
    a `grounds` STRING that is neither a uid nor a label. Criterion 14
    asserts §S8's texts, so §S8 should index them.
- **N7. `smysl.write` over a label bound to several units is
  unspecified.** `WriteContext::from_labels` takes one uid per label

  declaration (`parse.rs:2503-2507`). Grounds then silently point at the

  that failed for want of permission on a directory that exists.
- **N9. Cite the label grammar where it is:** `ids.rs:442-466`, not the
  macro invocation at `:500-507`.
- **N10. The label row contradicts itself.** It says "It has no
  `opaque`", then that one read back with a non-empty `extra` is

- **N11. Q54's register row lags the RFC.** Revision 12 adds the third

- **N12. The `--noio` stubs are untested until M10.** Each stub now

## Assumptions the RFC makes but does not state

1. **`write_surface` writes every record it is given** (S1). It writes
   only those `has_surface_form` admits.
2. **A payload key may be any STRING** (S1). Five are unspellable.
3. **`smysl.agent` does not canonicalise** (S2), without which R11's
   exemption fails.
4. **`smysl.write` passes no view**, so its text has no `@doc` header,
   and declares the default format version. The parser accepts a
   document without a header (`parse.rs:362-374`), so criterion 5's
   round trip holds, but it is unstated.
5. **A unit or relation MAP with an unknown key is refused** (N6). Only
   the label case says so.
6. **A refused document's warnings are not reported** (N3), or are; it
   is unstated.
7. **A library's label is bound to at most one unit when `smysl.write`
   runs** (N7).
8. **A failed `create_dir_all` is SM02** (N8).
