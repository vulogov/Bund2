# Review — RFC-0005: Tier 1, the Cranelift backend

- Reviewed: `docs/rfc/RFC-0005-cranelift-tier.md` at `d469bf6` (6,803 lines),
  as an adversarial reader. The twenty-third review, and the full reading the
  twenty-second asked for: every section, the forty assumptions, the
  preservation table and all thirty criteria.
- Date: 2026-10-10.
- Reference SHAs: `git submodule status` matches the six in the RFC's header.
  `git status --short` is empty in the repository and in
  `reference/rust_multistackvm`, before this file was written.
- Nothing in the RFC, the registers, the goldens or ERRATA was edited.
- `cargo xtask conform`: **133/145, CEILING 133/145**, twelve approved
  deviations, and the same with `--features jit` and with
  `--features jit --jit-threshold 1`. `cargo xtask cite`: every citation
  resolves. `cargo xtask lint`: no contradictions.

**Verdict: not yet, and this time on the substance. No citation into
`reference/` is wrong. What is wrong is the other end: the document describes
a tier that is not the one in `crates/`, and a third of its "met" criteria are
held by differentials whose tiered arm never runs compiled code. Two findings
are behaviour — a word whose output differs by tier (B1), and a cap that does
not bound what §S3 and §S7 accept it for (B2). The rest is evidence that
does not reach the claim it is filed under.**

The pattern behind most of the blockers is one the RFC already named as F127
and F128: a test passes while testing nothing. It recurs here because
`compiled_bodies() > 0` is used as proof that compiled code ran. It is a
compile-time counter. A body compiled on an entry that then fails is counted
and never entered.

## Blocking

**B1 — `debug.backtrace` prints a different stack under the tier. Re-run.**
The Preservation section opens "Tier 1 preserves everything by construction".
`debug.backtrace` is registered `opaque(0)` (`crates/bund2-stdlib/src/terminal.rs`)
and prints `Interp::render_backtrace`, which walks `self.frames`. A compiled
body has no frame. So:

    :w { debug.backtrace } register  :v { w 1 drop } register  v v v

| threshold | output | `--stats` |
|---|---|---|
| 1024 | `#0 w at 1` / `#1 v at 1`, three times | 0 bodies |
| 1 | the pair once, then `#0 w at 1` alone, twice | 1 body, 2 entered |

Stdout differs by tier in a session with no debugger. No golden runs the
word, so criterion 2 cannot see it. RFC-0008's "a debugged session installs
no tier" does not cover the word called from a program. Nothing in this RFC,
the preservation table or the registers mentions a backtrace. By CLAUDE.md
this is an unplanned deviation: it goes to `decisions.md` before code
changes. It is also the general case of an unstated assumption — *no word's
output depends on Tier 0's frame list* — and `debug.backtrace` may not be the
only word that breaks it.

**B2 — The function cap does not bound code memory, and the recompile cap
is not wired. Read; the code is short.** §S3 accepts unreclaimed code "for
v1" because "the 1024-body cap bounds that … after 1024, Tier 1 is off for
the rest of the process". §S7 calls the cap "the only bound" and "a
correctness argument, not a benchmark".

- `Tiering::observe` and `insert` test `self.cache.len() >= self.caps.functions`
  (`crates/bund2-jit/src/cache.rs`). That is live cache entries.
- `sweep` retains only live entries in `cache`; `redefined` and `demote`
  call `cache.remove`. Each frees a slot. The function stays in the module.
- `Compiler::compile_word` pushes onto `self.words` with no bound.

A program that keeps making short-lived hot bodies fills 1024 slots, the
counter reaches 4096, `observe` sweeps, and another 1024 compile. Nothing
counts functions emitted. The REPL case §S3 describes is exactly this one.
`the_function_cap_leaves_the_body_past_it_interpreted` holds every body
alive, so it never meets a sweep.

Three more, same section:

- **`Tiering::redefined` has no caller outside its own unit test.** `JitTier`
  never calls it and `bund2_api::Tier` has no redefinition hook. §S7's
  "recompile cap, 4 per slot" row and criterion 6's "the caps are built"
  describe a knob the running tier does not have.
- **A third map is uncapped.** `demoted` grows by one for every hot body
  with no inlinable site (F133/F136), `demote` removes the counter entry,
  and `sweep` runs only when the counter fills. §S7's heap row covers two
  structures.
- **§S3's worked example no longer triggers**: `1000 { … } times` is under
  D74's 1024.

**B3 — Differentials listed as met whose tiered arm never enters compiled
code.** The mechanism is one the RFC states itself at L6676: at threshold 1
the first entry is `Decision::Compile`, which compiles and returns `None`,
so that entry is interpreted. A body that fails or exits on its first entry
is compiled, counted, and never run compiled. Re-run for one case:
`:w { 1 2 :s to_stack + } register w w w` at threshold 1 prints
`tier compiled 1 bodies (0 entered)`.

The wrong-stack sync the criterion exists for cannot be caught. *(one re-run, three read)* |

| 23, second half | `a_dropped_interps_code_does_not_serve_another` | Uses a runtime with an empty fragment table, so `{ 1 2 + }` has no site and `would_gain` demotes it. Nothing is compiled, so nothing is dropped. *(read)* |

`Runtime::compiled_entries()` exists and none of these asserts it. One

**B4 — Criterion 30's exclusion is wrong: the mirror case has a reachable
form, and it passes. Re-run.** The 2026-09-29 verdict excludes the
caller-is-a-native mirrors because "no writing of them reaches compiled
execution". This does:

    :drop :go alias
    :m { [ 1 ] { 1 2 + drop 7 go "in-body-after" println } map } register
    m m m "warm" println
    :exit :go alias  m "after" println

At threshold 1: `compiled 1 bodies (2 entered)`, exit 7, nothing after
`warm`; identical to threshold 1024. The lambda is warmed with `go` aliased
to `drop`, then re-aliased to `exit`, and reaches the exit on an entry the
cache answers. The criterion names "through the alias `exit`" itself. So the
cases are owed, not unreachable — and on this evidence the tier is right.
*That the last entry was the compiled one is inferred from `observe`'s logic
and the warm-up count; an entry that ends in an exit is not counted.* The
note also says "two" mirrors are excluded and then lists five.

  slice reader counted 7 of 58 suite programs and 2 of 90 probes compiling

The equality holds, 133/145 three times. What it is evidence of is nine
programs.

## Should fix

**S1 — Assumption 40 is not structural.** "`Stacks::order` is private … a
switch that does not bump cannot be written." `Stacks` and `Interp` share a
module; `Interp` reads `self.stacks.order` directly. Compiled code reads the
*cell*, which `Interp::publish_epoch` writes by hand at five sites.
`Interp.stacks` and `Stacks::to_stack` are both `pub`, so
`interp.stacks.to_stack("x")` from any crate moves the front and leaves the
cell stale. Assumptions 33 and 37 have scans; this one has one test.

**S2 — Assumption 27 no longer holds, and five scans depend on it.** "Every
`bund2-stdlib` file's inline test module comes last." `world.rs` has its
test module at line 257 of 889, with `load_lambdas`, `load_stacks`,
`bootstrap`, `save_script` and `load_script` after it; `console.rs` has
shipped `debug_dump` after its first. The scans cut at the first
`#[cfg(test)]\nmod`, so criteria 11 and 25 and D73's switch scan do not see
that code. `load_stacks` calls `ensure_stack`; `bootstrap` calls
`eval_source`.

**S3 — Assumption 35 and the preservation table name two readers of the
unbounded decode; there are more.** `wire::from_binary` has no depth or size
check. `decode.base64` hands it bytes from a program's own string, declared
`eff(1,1)`; `bus` `recv`, `load.lambdas` and `load.stacks` reach it too.
`PROMOTABLE.txt` lists `decode.base64` as not reached. Not executed: no deep
payload was built.

**S4 — `REPORTS_MID_BODY` is not the safety net §S5 says it is.** "The
exclusion is `alias` alone", made noisy by
`every_native_reporting_mid_body_is_named`. The list holds seven names. F157
and the list's own doc record that it "went stale silently … no test will
say so". Dormant while D75 stands; live the day crossing returns.

**S5 — `published`'s `Result` is discarded by its only shipped consumer.**
§S6 says it returns `Result` because a malformed fragment is a Bund2 defect
under D37. `bund2-runtime` calls it with `.unwrap_or_default()`, under a
comment warning that an empty table means "nothing would report why". A
malformed fragment silently disables all inlining.

**S6 — §S6's "cells outlive every compiled function" holds for `Cells` and
not for generation cells.** Those belong to `Registry`, and `Interp.registry`
is a `pub` field; D43's note says assigning it "replaces the cells
wholesale". The two shipped replacements are on untiered `Interp`s. Nothing
stops an embedder doing it under a tier, after which compiled code loads
from freed memory. No assumption covers it.

**S7 — One of three published fragments is unreachable as programs spell
it.** `dup` is an alias, and `inline_site` refuses an alias. 48 corpus and
probe files write `dup`; 2 write `dup_one`. §S6 says "aliases are rare on
arithmetic" and reports `dup drop` at 3.0×. The fact is recorded at L5253,
outside the section that claims the win.

**S8 — Criterion 4's statements exceed its test.** "The two permitted
relocations are the only direct calls emitted": bodies emit direct calls to
`jit_residual`, `jit_stack_moved` and the four int helpers, which the test
permits as imports. "Corroborated by asserting the CLIF text contains
`call_indirect` and no bare `call fn`": no such assertion exists.
`relocations_of_two_bodies` emits no inlined site, no crossed call, no tail
call and no guard path. The module is gated on `relocation-test`, which
`cargo test --features jit` does not enable, and the RFC names no command.

**S9 — §S10 against D83 and D134.** "`--features jit` and `--features aot`
are declared in five crates": the second is `relocation-test`. "`bund2
build --emit=native` may require a C toolchain" and "RFC-0006 states the AOT
counterpart": the mode is withdrawn and there is no counterpart. D10 is
still listed under decisions consumed; D59, D68, D71, D73, D74, D75 and D83
are not listed at all.

## What the RFC assumes and does not state

1. `compiled_bodies() > 0` means compiled code ran. (B3)
2. No word's output depends on Tier 0's frame list. (B1)
3. Cache entries never leave the map while their code is orphaned. (B2)
4. Compiled bodies never nest — true only because `push_frame` takes the
   tier out during `enter`. §S5's exit and request reasoning and all of
   §S8's `m` depend on it in opposite directions.
5. Every helper returns through `status_of`. `jit_stack_moved` and the int
   push and pop helpers park errors directly, so they do not clear a tail
   request on error.
6. The fragment decomposition has no fixed cost per iteration. (B9)
7. A per-entry bench figure can stand for a per-program stop rule. (B8)
8. Measurements of 2026-09-15 to 2026-09-29 describe a lowering that
   changed on 2026-09-16 (F136), 2026-09-28 (F142, D74, D75) and 2026-09-30
   (`autoadd` loads). `entry_anchored` and two of three `regimes` families
   no longer compile at all under `would_gain`.
9. `Interp.stacks` and `Interp.registry` are not mutated from outside
   `Interp`'s `Vm` impl, though both are `pub`. (S1, S6)
10. `times` reaches the tier seam once per iteration. (S10, criterion 20)
11. An `Interp` runs on the thread that built it.
12. Q27 — which target profile the caps are chosen for — is still open, and
    §S3 "accepts it for v1" regardless.
