## Blocking

### B1. Criterion 20 cannot be checked from this repository

Three of its items are defined only in the missing reviews: "the second
review's four-edge KB", "the third review's seven-edge KB", and "the third
review's `p`/`q` program". None of these files exists, so nobody
implementing M10 can write those tests, and nobody can check that they
test what B2 of the third review was about.

**Fix:** write the three KBs, the queries and the expected answers into
criterion 20.

## Should-fix

### S1. F231 is now fixed, and the RFC says it is not

Since this review began, `scoped_call` restores the stack it came from
when `push_frame` fails: it unwinds what was pushed and, if nothing ran the
exit action, switches back by hand. A test in
`crates/bund2-runtime/tests/oom_guard.rs` covers it, both directly and
through `context`. The RFC still describes F231 as live in three places:

- under Current behaviour, `scoped_call` and stack names;
- S5 step 3.4, the restore;
- Preservation analysis.

Criterion 7's wrapper, a `Vm` whose `scoped_call` returns `Err` with the
scratch stack current, still has a point: a `Vm` the bridge doesn't
control can fail that way. But step 3.4 should say it protects against a
`Vm` that breaks the contract, not against F231.

### S2. One stdlib audit does not look inside `src/kb/`

S6 says the family lives in `bund2-stdlib` because "the audits ... read
only `bund2-stdlib`". `REENTERING`, `SWITCHES`, `REPORTS_MID_BODY`'s scan
and `nothing_shipped_follows_a_test_module` walk subdirectories.
`no_native_reports_at_error_severity` (D36) does not: it calls
`read_dir(&src)` once and never descends.

`src/kb/` would be the crate's first subdirectory, so the whole family
would be invisible to the scan that keeps natives from reporting at
`Error` severity. Either the criteria add that scan's recursion, or the
RFC names this scan as one that must change.

### S3. A conjunction that starts with an atom is read as a compound

S3 says a query or a body is "one goal, or a LIST of goals". S1 decides
which by the first item:

- `[ [ p X ] [ q X ] ]` is a conjunction.
- `[ ready [ p X ] ]` is the compound `ready([p X])`, and so E12 (`ready/1`
  is not defined).

The same applies inside `if`, `or`, `findall` and `once` wherever `[ G… ]`
is written. The trap list under S1 doesn't name it. Every query or branch
that opens with a zero-arity goal hits it, and nothing warns.

**Fix:** list it as a trap and say how to write it (`[ [ ready ] [ p X ] ]`).
Better, reconsider whether a goal position should accept a compound whose
arguments are themselves all goals.

### S4. Criterion 4 names no probe for "the Rust stack depth"

"The Rust stack depth, sampled from `lambda` at the 10th and the
1,000,000th answer, is equal." A Bund lambda can't see the Rust stack.
The criterion has to name the mechanism, for example a test-only native
that pushes the address of a local, or `stacker::remaining_stack` if a
dependency is acceptable. Otherwise it can't be checked as written.

### S5. Criterion 1b's E40 test cannot live with the stdlib's unit tests

The memory guard's flag is process-wide. Its tests run "in a binary of
their own, and one test in it at a time" (the header of
`crates/bund2-runtime/tests/oom_guard.rs`). A trip set inside
`bund2-stdlib`'s parallel unit tests would be taken by whichever
interpreter reaches a call first.

**Fix:** place E40's test, and criterion 5 if it trips the guard, in
`oom_guard.rs` or a sibling binary.

### S6. Criterion 2a needs a dependency the RFC says it doesn't add

A "property test" needs `proptest` or `quickcheck`. Neither appears in any
`Cargo.toml` in the workspace. A dev-dependency isn't D28's concern, but it
is `cargo deny`'s, and S6's "adds no dependency" reads as covering the
tests too.

**Fix:** name the dependency, or replace the property test with an
enumerated table of term pairs.

### S7. Criterion 25 has no expected output

"Prints what this RFC describes" can't be checked. The examples carry
only comments, and Bund2-only words have no goldens: the oracle can't
produce one. Name the check, for example a checked-in
`bund_examples/logic_demo/expected.txt` compared by a test.

### S8. Criterion 12a leaves `REPORTS_MID_BODY` out

S10 says `kb.word` "is in `REPORTS_MID_BODY`", and S13 depends on it. The
list is a fixed-size array (`[&str; 8]`), checked by
`every_native_reporting_mid_body_is_named`. Criterion 12a lists
`SWITCHES`, `REENTERING`, `BUILT` and `PROMOTABLE.txt`, but not this
list.

### S9. The choicepoint table doesn't say which kinds carry the continuation

`Not` and `Else` hold "the continuation". `Collect` resumes after
rebuilding its results, and `Ask` "succeeds once" on a `true` reply, but
neither lists a continuation. Nor do `Clauses`, `Branches` or `Items`, and
every kind needs its trail and arena marks.

Either every kind implicitly carries the goal list and its marks (then say
so once), or `Collect` and `Ask` are under-specified.

### S10. Which code a guard trip raises inside a bridge or an `ask`

The guard trip text is E40. An error in λ is E24, and an error in `ask`
is E57. A trip taken by the interpreter's own poll inside λ (at
`push_frame_once`) surfaces from `scoped_call` as an error in λ, so by S5
it becomes `bridge lambda in <goal> returns: OOM GUARD …`. A trip taken by
the engine's per-inference poll is a bare E40.

Criterion 1b tests E40 "by its text", so the RFC has to say which form is
meant, or that both are acceptable.

### S11. Edge cases of the term mapping are unspecified

- Reading back an improper list (a tail bound to a non-list), such as
  after `[ = L [ :a | :b ] ]`. The read-back table covers only a *partial*
  list.
- `[ in X L ]` with L bound to a compound or atom. S5 gives E10 for
  unbound or partial, and nothing for "not a list".
- A goal that is the empty list (`nil`). E11 or E12?

### S12. The header contradicts itself and the repository

- "Bund2 read at `eb43ca3`" sits beside the landing note's "against Bund2
  at `0c145de`".
- "ERRATA had no logic entry before this RFC's" says an entry exists. It
  doesn't: `docs/research/ERRATA.md` has no "logic". The research document
  it would correct doesn't exist either.

Say there is none.

## Notes

- **N1. `∅` and `|` are CALLs inside a list literal.** So `[ parent ∅ X ]`
  is `parent('∅', X)`, not a fresh variable. S1's NODATA row applies only
  to a value built at run time. S10 says `∅` marks an unbound argument *at
  a call site*. The trap list should say the converse.
- **N2. RFC-0010 and D225 are not mentioned.** Class names (`Value`,
  `Integer`, `Boolean`, `Collection`, `List`, …) begin uppercase, so in a
  term they are variables. A KB about the class hierarchy must write them
  as STRINGs, as example 3 does for graph nodes. RFC-0010 belongs under
  "Bears on", and S14 needs a line.
- **N3. Atom read-back is lossy for `"true"` and `"false"`.** Atoms compare
  by text, so the STRING `"true"`, the CALL `true` and the BOOL `true` are
  one atom, and it reads back as BOOL. A fact stored with the STRING
  answers a BOOL. This consequence of L2 is unstated.
- **N4. S13's epoch count is right, but the attribution is off.** For a
  new name, `to_stack` returns through `add_as_current` without bumping
  again. The second bump is the exit action's `to_stack(prev)`.
  `drop_named` then bumps nothing. Checked: the ring order after the
  bridge is the order before it.
- **N5. A λ that drops its own scratch stack is harmless.** `pull_from` on
  the missing name answers nothing (E21, as S5 says), and the bridge's own
  `drop_named` of an absent name changes nothing and bumps nothing. The
  RFC asserts the first and is silent on the second; worth one line.
- **N6. `kb.consult*` "folds the stack from the bottom up ... stops at
  NODATA"** reads as two directions. Say that it scans down from the top
  to the first NODATA and then adds the items above it, oldest first.
- **N7. `limit` and `inferences` use opposite conventions.** For
  `inferences`, ≤ 0 means no cap. For `limit`, the table admits `0` and
  "stop after this many answers" makes it zero answers. Intentional or
  not, state it.
- **N8. Q44 stands, but narrower.** Every operand order the "third review"
  traced that this review could check holds: `var`, `set`, `get`, `format`,
  `graph!`, `graph.reachable`, `input`. The examples remain unrun because
  the words do not exist.

## Preservation analysis: what it omits

- **The F231 fix changes `context` on a trip.** It now comes back to the
  caller's stack. Bund2-only, and no golden reaches it.
- **`REPORTS_MID_BODY`, `REENTERING` and `SWITCHES` change size,** and
  `BUILT` grows. These are test-pinned lists, which matters to anyone
  bisecting.
- **New names can collide with a program's own words.** A program that
  `register`s `query` or a `kb.` name now redefines a native, with `watch
  redefine` firing. The corpus has none (checked), but the RFC should say
  so.
- **During a bridge, λ can see the scratch stack** through `stack_names`,
  `debug.display_stack` and `save.stacks`. A stack saved this way is
  exactly what makes S5 step 3.1's collision possible later. That is
  covered by criterion 7, but it is not named as a visible behaviour.

## Assumptions not stated

- `query`'s `lambda` runs by `eval_lambda` on the current stack, and
  nothing restores the stack after it, unlike a bridge. A `lambda` that
  switches stacks leaves the runner's next answer on the new stack.
  Presumably that is what `sqlite` does, but it isn't stated.
- E24 and E57 nest their prefixes for nested bridges. `summary` bounds
  values, but nothing bounds the prefix chain.
- `fresh_name` ids are 21-character nanoid-shaped strings, so a program
  collides with a pooled name only by reading it first.
- The per-inference guard poll costs "one relaxed load when nothing is
  pending" (`push_frame_once`'s comment). Criterion 16 should measure it
  alongside the occurs check.
