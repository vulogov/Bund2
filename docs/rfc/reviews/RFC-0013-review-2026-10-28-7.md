## Should-fix

### S1. The top level has no frame, so a trip set beforehand is not taken "at its first body"

Criterion 1b says a trip set before the program starts "is taken at its
first body, before any `kb.` word runs (`push_frame_once` polls first)",
and builds the E40 test around a second thread for that reason. The code
says otherwise:

- `eval_observed` runs the top-level stream itself, value by value,
  through `apply_step`, and pushes no frame.
- A CALL to a native goes through `dispatch` to `call_native` and
  `invoke`, also with no frame.
- The interpreter's only guard poll is the one in `push_frame_once`.

So in `:k var? [ loop ] kb.query` at the top level, nothing polls before
`kb.query` runs. A trip set before `eval_str` is taken by the engine's
first poll, and the answer is E40, deterministically. The existing test the
RFC cites trips before `rt.eval_str("f")`, and `f` is a `register`ed word,
which has a frame. That is why it fails at once; a native would not.

What this changes:

- **The E40 test needs no thread.** Trip, then evaluate a top-level query.
  The thread version still works, but its stated reason is false, and it
  adds a timing assumption (the 300 ms sleep) that the simpler form
  doesn't need.
- **The premise must go wherever it is reused.** The E24 path is
  unaffected: its trip is set inside λ, and the next poll is the
  registered word's frame. But a test that trips first and then runs a
  query whose first goal is a bridge gets E40, not E24, because the engine
  polls before the bridge starts.

**Fix:** state the real mechanism. A top-level `kb.` word is reached
without a frame, so its first poll is the engine's. Keep the thread only
if the criterion also wants to show that a running query stops.

### S2. E40's text is "the guard's text alone" in S5, and prefixed by S12's rule

- **S5** (Errors): "The engine's own poll (S4) raises E40, the guard's
  text alone."
- **S12:** "Every text except E00 begins `<W>: `". E40's row reads "the
  memory guard's own text (`Trip::error`)", with no exception made.

So S12 says `KB.QUERY: ` + the guard's text, and S5 says the guard's text
with nothing before it. Criterion 1b tests "by its text", so the two must
agree. Either list E40 beside E00 as unprefixed, or drop "alone" from S5.
The prefix is the more useful choice, because it names the word that was
solving when the guard tripped.

## Notes

- **N1. Criterion 4's "both samples come through the compiled caller" is
  stronger than it needs to be.** The tier may decline `lambda` for good
  (D146: a body the tier declined is not offered again), in which case
  both samples come through the interpreter. They are still equal, so the
  criterion holds either way. The text should say equal *whichever* caller
  runs `lambda`, not that it will be the compiled one.
