## Blocking

**B1 — A bundle built `--noeval` evaluates a string through `debug.run`, and
through `debug.feed` with `debug.shell` with nobody at the keyboard. Neither
is named, and neither is the reference's.**

Measured on bundles built `--noeval --noio`, standard input closed:

| program | result |
|---|---|
| `"40 2 + println" debug.run` | prints `42` |
| `"40 2 + println" debug.feed debug.shell` | prints `42` |

`--inspect` reports both as `restrictions --noio --noeval`.

`debug.run` is, in the code's own words, "`bund.eval` with a safepoint
offered before each" term (`crates/bund2-stdlib/src/lib.rs`, the registration
table's comment; `crates/bund2-stdlib/src/terminal.rs`, `debug_run`). D115
kept it working in a bundle on purpose — "`debug.run` runs its string and
offers no stop" — and said nothing about `--noeval`. RFC-0008 does not
contain the word `noeval`; RFC-0006 does not contain `debug.run` or
`debug.feed`.

Three things follow.

- **D78 is not met.** "RFC-0006 states what each flag leaves ungated, by
  name." §B3a names `compile lambda! !`, `debug` and `debug.shell`. This is
  the acceptance review's B4 and the sixth review's B1 again, with one more
  name.
- **§B3a's defence does not reach it.** "These are the reference's boundary
  and not defects in the flag — D79's reading." `debug.run` and `debug.feed`
  are Bund2-only (RFC-0008, "A fourteenth Bund2-only word"). The reference
  has no boundary to inherit here. A word that is `bund.eval` under another
  name, added by Bund2, outside the group `--noeval` disables, is a choice
  somebody made without noticing it was one.
- **§B3a describes `debug.shell` as a person typing.** "Measured … whose
  program is `debug.shell`: the typed line `40 2 + println` prints `42`."
  With `debug.feed` the program supplies the line itself. The route needs no
  open input and no operator, which is the case a builder relying on
  `--noeval` is most likely to have in mind.

**This needs a ruling, not an edit.** Either `--noeval` gates `debug.run`
(Bund2's word, so no deviation from the reference — D119 is the precedent for
moving a word across the line by decision), or it is left and named. Whether
`debug.feed` reaching `debug.shell` matters once `debug.run` is settled is
the same question. The preservation row "What `--noeval` stops — Preserved
exactly" is true of the reference's six words and silent about Bund2's
seventh.

## Should fix

**S1 — `--noio` gates `stdin` and `stdin.`, and the by-name list omits them.**
The reference registers both *only* under the flag
(`reference/Bund/src/stdlib/functions/filesystem/file.rs:95-96`; the `else`
arm at `:100-103` has no `stdin`), and Bund2 does the same
(`crates/bund2-stdlib/src/host.rs`, the `stub!("stdin", …)` pair). Measured:
both answer `bund FILE functions disabled with --noio`. So 61 names answer
with the stub, not 59.

The cause is the method, and the RFC should say so: the measurement iterates
`bund2 words`, which lists an *unrestricted* registry, so a name that exists
only when the flag is set cannot be seen. The RFC cites the very range that
holds them. The error is on the safe side; it is still a list D78 asks for by
name.

**S2 — `--inspect` cannot read an artefact from another container version,
and says something false when it tries.** Measured on a bundle with its
container version patched to 99 and re-signed:

    $ ./m_fmt.bin
    bund2: this artefact carries container version 99 and this runtime reads
    version 1; it was built by a different bund2
    $ bund2 build --inspect m_fmt.bin
    bund2: m_fmt.bin is not a bund2 artefact: 1 sentinel match(es) in this
    binary and none carries a valid header. The region is absent and the
    matches are constants in the code.

The same for a state byte of 7 and a length past capacity. `locate` accepts a
region only if `format == FORMAT`, the state is 0 or 1 and the length fits
(`crates/bund2-cli/src/bundle.rs`, `header_validates`), so `--inspect` can
only ever print "container version 1" and reports every damaged or foreign
artefact as having no region.

§B3a: "The trailer is readable, because a restriction the runner cannot
observe is one they cannot rely on." §B1, after D118: "the version field is
for a reader of `--inspect`." The one reader the version is for cannot read
an artefact whose version differs. No criterion covers `--inspect` on
anything but a well-formed artefact of the same build; criterion 12 is about
running one.

**S3 — The open-questions bullet for D78 repeats both statements §B3a
corrects.** "…the word 'sandbox' is ruled out because `--noio` leaves `args`,
`sleep.seconds` and `io.graph` ungated and does not gate fetching at all."
§B3a calls the first "the ungated words *of one module* presented as the
flag's whole surface" and the second "half wrong". The bullet is D78's
wording, quoted without its correction, forty lines from the end.

**S4 — §B4 still argues from the claim criterion 1 disproved.** "…the size is
the larger cost: `cranelift-codegen` with its ISLE tables is, per the
research, the single largest contributor to any binary embedding the JIT."
§B8, criterion 1 and ERRATA all record that as false for Bund2 (8.9% of
`__text`; `graphitesql` alone is 13.0%). The same staleness is in
Alternatives: "What remains is a size saving §B8 shows cannot be weighed
until a bundle exists" — §B8 weighs it.

**S5 — §B5 "stands as the record of what building it would take" and omits
the cost D83 calls the largest.** D83: "The meaning guards have no cells at
build time … **This risk is not in §B5's list**, and it is the largest." The
Summary mentions "a risk §B5 had missed"; §B5 still says "three things" and
§B8 "§B5's three blocking items". A reader who takes §B5 as the record gets
three of four.

**S6 — Criterion 11's capacity half and criterion 12's evidence do not say
what checks them.**

- `a_program_over_capacity_is_refused_and_writes_nothing` is a unit test of
  `write_into` on a buffer (`crates/bund2-cli/src/bundle.rs`, `tests`), not
  in `bundle_build` as the "what runs these" table says. Nothing drives an
  over-capacity program through `bund2 build`. Done by hand today: a
  1,048,579-byte program is refused with both numbers named, exit 1, no file
  written — so the behaviour is right and the test named does not show it.
- Criterion 12's evidence reads "drives three through the binary … The
  fourth, an absent region, is `an_unbuilt_runtime_carries_nothing` … it is
  the fourth case of the same test now." Two things are called the fourth.
  The test has four damage cases and all pass; the empty region is the fifth
  thing and is not damage, which is what the criterion's own first sentence
  says.

**S7 — "Does CI run it: yes" has never happened.** The workflow runs on a push
to `main` and on pull requests (`.github/workflows/ci.yml:3-6`). `gh run
list` shows one run, on `main`, 2026-09-11, concluded `failure`.
`crates/bund2-cli/src/bundle.rs` was first committed on 2026-09-30, on this
branch. So no criterion of this RFC has run in CI, and the "yes" rows mean
"would, on a merge". That matters for one claim in particular — S8.

**S8 — "What was not tested" is about the form that was not built.** §B1:
"Linux and Windows: ELF and PE carry no equivalent whole-file signature by
default, so appending is *expected* to be unaffected." Appending is not
implemented. What a Linux or Windows user gets is the in-place write into a
copy of the running executable, and the RFC says nothing about whether that
was run anywhere but macOS on arm64. The CI table implies Ubuntu covers it;
S7 says it has not yet.

**S9 — "`save.aliases` and `save.stacks` were not followed" — followed here,
and the format reaches the file by more routes than lambdas.**
`bund_save_stacks` calls `save_stacks`
(`reference/Bund/src/stdlib/functions/bund/bund_save.rs:62-70`), which writes
**every value on every stack** with `to_binary`
(`reference/Bund/src/stdlib/helpers/world/stacks.rs:100`); `save.model` does
the same to a model (`helpers/world/models.rs:90`). `save.aliases` does not
call `to_binary`. So "every lambda" understates it: any value. The RFC rests
on neither D11 nor D31 here, as it says, so nothing downstream moves — but
the sentence admits an unfollowed call that is one file away, and its
"a claim about those two words" points grammatically at the two it did not
follow.

**S10 — Carried, unanswered.**

- `RFC-0005:93` still reads "**Not met** — 4's reachable remainder alone";
  `RFC-0005:4192` reads "**Met, 2026-09-30, by inspection**". The acceptance
  review's S1 and the sixth review's S10. RFC-0005's to fix; this RFC's
  status leans on the second.
- The header's "Supersedes: … §9's phasing" names one section where ERRATA
  names §1 and §9 (`docs/research/ERRATA.md:123`, `:129`).
- The `aot` feature. Measured: a bundle built from `bund2 --features aot`
  inspects as `features: aot` and contains no Cranelift string. After D83
  the feature means "compile the relocation test", and a holder of that
  artefact is told it carries something called AOT.

**S11 — Small.**

- "each one asks its own image whether it carries a program before it reads
  argv" — `run_cli` collects `std::env::args()` on its first line and then
  asks. Before it *interprets* argv.
- The closing paragraph opens "Three reviews have found six blockers between
  them, and all six are answered". There have been six reviews of the
  document and one of the code, and seventeen blockers. True of the three it
  means and misleading as the last word.
- Code comments now contradict the RFC. `bundle.rs`'s module documentation:
  "signing stays outside `bund2 build`" — §B1 calls that "backwards".
  `carried`'s comment names "RFC-0006 §B1's separate prebuilt runtime" as
  "the recorded fallback" if `black_box` is ever folded through; D118 says
  that construction was not taken and the RFC records no fallback for that
  failure. `main.rs`'s module documentation: "no `--emit`, no subcommands
  beyond `script --file`". Not the RFC's text, but they are what the RFC's
  file-and-symbol citations send a reader to.

## Preservation analysis — what it does not enumerate

The sixth review's eight rows are all there now, and D119 has its own. Six
things remain.

**P1 — `--noeval` and Bund2's own words.** B1. The row says "Preserved
exactly", which is a statement about the reference's six. `debug.run` did not
exist in the reference, so its behaviour under the flag is new surface, not
preserved surface, and belongs in the table as that.

**P2 — `stdin` and `stdin.` under `--noio`.** S1. Preserved, and unlisted.

**P3 — A literal `--` is data in a bundle.** Measured with the program
`args println`:

    $ ./a.bin -- x y                         [ -- ::  x ::  y :: ]
    $ bund2 script --file a.bund -- x y      [ x ::  y :: ]

"The runner consumes nothing" (§B3) predicts it, and the `args` row says
"Preserved". It is preserved for the arguments and changed for the
separator, and someone moving a wrapper script from one form to the other
meets it.

**P4 — `--debugger` and `--jit-threshold`.** The "Diagnostic flags" row lists
three. §B3 lists `--jit-threshold` as a fourth that moves to the environment.
`--debugger` has no bundle form at all, by a deliberate choice recorded only
in `run_carried`'s comment; the D115 row covers the *words* and D115's title
says "by a flag or by a word".

**P5 — Four behaviours that are built and tested and appear nowhere in the
document.**

- A bundle cannot build: it owns all of argv, so `./bundle build …` is its
  program's arguments (`a_bundle_cannot_build_another_bundle`).
- `--output` naming the building binary is refused
  (`a_build_refuses_to_overwrite_the_binary_doing_it`).
- A bundle of an empty program is a bundle that does nothing, not the
  interpreter (`an_empty_program_does_not_become_the_interpreter`).
- **Any other existing `--output` is overwritten without a word.** Measured:
  `bund2 build --file m.bund --output keep.txt` over an existing text file
  exits 0 and leaves a Mach-O.

**P6 — What the restriction variables apply to.** `BUND2_NOIO` and
`BUND2_NOEVAL` are read by a bundle and not by `bund2 script`. So the same
program in the same environment is restricted in one form and not the other.
§B3 lists the variables; no row says the asymmetry exists.

## What the RFC assumes and does not state

1. **`bund2 words` lists every name a flag can affect.** It lists an
   unrestricted registry (S1).
2. **Every ungated word is the reference's.** That is what lets §B3a answer
   each one with "D79's boundary". Bund2 has added words since (B1).
3. **Whoever inspects an artefact uses a `bund2` with the same container
   version** (S2).
4. **The compiler does not fold reads of the region.** `black_box` is "a hint
   and not a guarantee" in the code's own words; the only check is
   `cargo xtask bundle`, which runs nowhere automatically. Carried.
5. **The in-place write works on ELF and PE** (S8).
6. **`/usr/bin/codesign` is present and is not a Command Line Tools stub.**
   D81 records it; no criterion does. Carried.
7. **The builder can read its own executable.** Carried.
8. **Nothing worth keeping is at `--output`** (P5).
9. **A bundle reads only the variables §B3 lists.** It also reads
   `BUND_LOG_LEVEL` and `COLUMNS` (`crates/bund2-stdlib/src/logging.rs`,
   `report.rs`), as a `script` run does. Preserved, and not in the list §B3
   calls "part of this design".
