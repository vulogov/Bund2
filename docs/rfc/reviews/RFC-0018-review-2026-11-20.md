## Blocking

### B1. `fit.lm`'s AIC is 2 too high, and so is its BIC

§S3 (RFC `:353`) defines `aic` as "the Gaussian AIC, §Current behaviour's R formula, plus 2(k + 1)". That formula is `nobs*(log(dev/nobs*2*pi)+1)+2 - sum(log(wt))` (`family.R:278-281`). It already counts σ through its `+2`, and R adds only 2·rank to it (`glm.R:376-377`). So R's AIC is the formula plus 2k. The RFC's version is 2 higher.
- `fit.glm` under `gaussian` uses "the family's AIC, R's formula, plus 2k" (§S4), which is right. As written, the two words answer different AICs for the same model.
- `fit.lm`'s `bic` is defined as `aic` − 2(k + 1) + (k + 1)·ln n, so it inherits the extra 2.
- Criterion 2 checks `aic` and `bic` against a fixture computed "from the definitions". The fixture and the text would disagree, and either one could be the one taken as right.
- **Fix:** "plus 2k", as in §S4; or state the AIC as −2 log L + 2(k + 1) with log L written out.

### B2. The null deviance with an offset is not what the citation says

§Current behaviour (`:181`) cites `glm.R:367-369` for the null deviance: the weighted mean of y with an intercept, else linkinv(offset). §S4's `null.deviance` (`:413`) is "at the null model (R's rule)". The cited lines compute `glm.fit`'s value, and `glm()` then replaces it. When there is an offset and an intercept, `glm()` refits the intercept-plus-offset model and takes that fit's deviance (`glm.R:99-119`). The comment at `glm.R:366` says so: "corrected in glm() if offset and intercept".
- Criterion 3 fits a Poisson rate model with a log offset. That is the case where the two values differ.
- The refit is a second IRLS, started from the full fit's μ (`glm.R:113`). It can fail to converge, and R only warns (`:117-118`). Neither the refit nor its refusal is in §S4 or §S8.
- **Fix:** define the null deviance as the deviance of the intercept-plus-offset fit (the offset alone without an intercept), name its start, and add the E110 row. `model.anova`'s first row needs the same definition.

### B3. Step halving on the first iteration

§S4 (`:389`) halves "the step towards the previous coefficients". On the first iteration there are none. R starts `coefold` as NULL (`glm.R:203`) and gives up there: "no valid set of coefficients has been found: please supply starting values" (`:271-272` for a non-finite deviance, `:290-291` for an invalid η or μ).
- Criterion 3 (`:625`) exercises halving with "a Gamma model under `identity` whose first step leaves the valid range". In R that model is refused, not halved.
- **Fix:** say what the first step does. Either refuse, as R does (E101 or E110, with the text in §S8), or halve towards the start η, which is not a coefficient vector and would need its own definition. Then restate criterion 3 to use a model whose second or later step leaves the range.

### B4. A design with no columns cannot be fitted, and `model.anova` needs one

`model.anova` (`:481-486`) fits the intercept-only model first, or "`NULL`" when the design has no intercept. The null model's design has k = 0. `weighted_solve`, which §S4 reuses "unchanged" (Preservation table), computes `scale` as a fold from 0.0 over no diagonal entries, so `scale <= 0.0` holds and it answers E106 (`fit.rs:255-258`). That is from the code; it was not probed.
- So `model.anova` on every design without an intercept would refuse at its first row.
- The same holds for `intercept` false with an empty `terms`, which §S2 does not refuse.
- §S3's and §S4's own E106 now names the first dependent column (K8). That also changes `weighted_solve`, or needs a wrapper, so "shared, unchanged" cannot stand as written either.
- **Fix:** define the k = 0 fit: deviance at linkinv(offset), no coefficients, df n. Have `model.anova` use it, and either allow or refuse a design with no columns in §S2. Restate the Preservation row as "`fit.logistic`'s texts unchanged", not "`weighted_solve` unchanged".

## Should fix

### SF1. A standard error on the response scale can be negative

§S6 (`:458-462`) multiplies the link-scale standard error by μ′(η). R multiplies by `abs(mu.eta(fit))` (`src/library/stats/R/predict.glm.R:60`). For the `inverse` and `1/mu^2` links μ′ is negative, so the RFC's `se` would be negative.

The same links are decreasing, so linkinv(η̂ − q·se) is the upper end of the interval, not the lower one. Mapping "`lower`" and "`upper`" through the inverse link swaps them.

**Fix:** use |μ′(η)|, and define `lower` and `upper` as the smaller and the larger of the two mapped ends.

### SF2. "Bit for bit with `stat.lm`" cannot hold for `r2` and `df` as specified

- **`r2`.** `stat.lm` computes it as 1 − rss/tss (`infer.rs`, `stat_lm`). §S3 gives `fit.lm` "R's `summary.lm` rule", which is mss/(mss + rss), with mss taken about the mean of the fitted values less the offset (`lm.R:304-340`). The two are equal in exact arithmetic, not in their last bits. Criterion 2 asserts bit-for-bit equality of `r2`.
- **`df`.** `stat.lm`'s `df` is a FLOAT (`BundValue::float(df)`) and `fit.lm`'s `df.residual` is an INTEGER. They can be equal in value but not "bit for bit".
- **Offset.** R subtracts the offset from the fitted values before computing mss (`lm.R:304-306`), and so before r² and the overall F. The RFC does not say this.

**Fix:** either say that `fit.lm` computes r² as 1 − rss/tss when unweighted with an intercept and no offset, or drop `r2` and `df` from the bit-for-bit list and compare them by value. State the offset rule.

### SF3. The options reader's key list is shared, so existing frame words' texts change

The Preservation rows (`:546-547`) say the frame words and "the options reader's texts for existing keys" are preserved exactly. But `KEYS` is one list for every word (`frame/opts.rs:28`). `read` reports a key outside it as `an unknown key "family"`, and a listed key the word does not take as `the key "family", which this word does not take` (`:146-153`). Adding this RFC's keys (`intercept`, `weights`, `offset`, `family`, `link`, `type`, `interval`, `conf`, `test`) to `KEYS` changes what `frame.sort` and the other frame words say when given one of them. This is read from the code, not probed.

**Fix:** list it in the Preservation table as changed by design. Or give the model words a key list of their own, and say which.

### SF4. Clamping and separation are stated only for the logit

§S4 (`:392`) clamps "the binomial's η … as `fit.logistic` clamps it" and refuses "a fitted μ numerically 0 or 1 at convergence". Two problems:
- `ETA_LIMIT` is the logit's bound (`fit.rs:47-49`). R's other binomial links clamp differently (`family.R`):
  - probit at ±`qnorm(ε)` (`:61-62`);
  - cauchit at ±`qcauchy(ε)` (`:72-73`);
  - cloglog's μ at [ε, 1 − ε] (`:83-87`);
  - log's μ at ≥ ε (`:100-102`).
  The RFC gives no clamp for those links.
- The separation test is stated two ways. `fit.logistic` refuses when the final |η| ≥ `ETA_LIMIT` (`fit.rs:315-322`). R warns when μ is within 10ε of 0 or 1 (`glm.R:322-325`). K15's agreement needs `fit.glm` under logit to refuse exactly the inputs `fit.logistic` refuses.

**Fix:** a table of the clamp for each link, and one separation test, `fit.logistic`'s, for the logit.

### SF5. K15's 10⁻¹² agreement rests on more than the weight formula

§S4 (`:423`) says the only difference from `fit.logistic` is how W is formed. There is a second difference: `fit.logistic` computes the deviance as a softplus of η (`fit.rs:228-240`), not from μ by R's `dev.resids`. The convergence test reads the deviance. Different deviance arithmetic can stop the two words at different iterations when a change lands near 10⁻⁸, and then they agree only to about 10⁻⁸ (the revision's own K11 estimate).

**Fix:** either specify `fit.glm`'s binomial-logit deviance as `fit.logistic`'s softplus form, or weaken K15's claim to the data criterion 3 states, checked.

### SF6. A Poisson or log-link μ driven to 0 is neither refused nor reported

R warns "fitted rates numerically 0 occurred" (`glm.R:326-329`). A Poisson group with all-zero counts drives a coefficient towards −∞. The deviance test still converges, leaving a large finite coefficient and a huge standard error. The RFC refuses binomial separation but says nothing about this. That case is the Poisson's version of the same problem.

**Fix:** refuse it as separation is refused, or state that it is answered.

### SF7. A constant `y` is refused even where it is a valid fit

§S3 (`:339`) refuses "a constant `y` … as `stat.lm` refuses them". `stat.lm` refuses because its r² divides by the total sum of squares about the mean (`tss == 0.0`), and it always has an intercept. `fit.lm` without an intercept measures r² about 0, so a constant nonzero `y` is a valid fit there.

**Fix:** refuse a constant `y` only with an intercept.

## Notes

- **N1. The prediction-interval weights claim lacks a citation.** §S6's "R's `predict.lm` assumes 1 and warns" is true but uncited: `lm.R:673` sets `pred.var = res.var/weights`, and `:773-774` gives the warning.
- **N2. Criterion 1 cites a MATRIX that the RFC never states.** It speaks of "the stated 7 × 6 MATRIX", but no matrix is stated; the test will state it. Say "the 7 × 6 MATRIX its rows give" or write it out. Also `spec.levels` is a MAP of column to levels, so "holds `[ north south ]`" should read `site` to `[ north south ]`.
- **N3. Criterion 3's tolerance rests on an estimate.** The 10⁻⁶ rests on "some 10⁻⁸", a heuristic for quadratic convergence and not a bound. Separately, "no answer in this RFC depends on an algorithm's choices" (§Acceptance criteria) now contradicts the revision's own K11 text: the stopping rule is such a choice. D260 C4 D brings in R where an algorithm decides. Either say why R's output is still not needed, or reword.
- **N4. The binomial AIC rounding is not stated.** Counts within 10⁻³ of an integer are accepted (K12), and R's AIC then uses round(m·y) and round(m) (`family.R:356-360`). §S4 should say `fit.glm` rounds the same way.
- **N5. K1's list of narrowings could be read as complete.** It names six places where the RFC covers less than §3.3. The table's mixed-models and survival rows (`:128-129`) are other phases by research 07's own order (`:218-221`). Say so, so ERRATA's entry is not read as covering them.
- **N6. Non-convergence departs from R and is not listed.** R warns and answers (`glm.R:319`); `fit.glm` refuses with E110, as `fit.logistic` does. That is a deliberate difference from the R the RFC reasons from, and §Alternatives or the [author] list should say so.
- **N7. The lambda-first claim has two exceptions.** It holds for a plain call. A registered command resolves first, and a sigiled call skips the lambda (`resolve_uncached`). Neither matters for these names, but the claim is stated without the qualifier.

## What the RFC assumes and does not state

- **U1. `model.anova` refits by IRLS.** It refits with `fit.glm`, including a design meant for `fit.lm` (family `"gaussian"`). Its deviances are IRLS results, which differ in the last bits from `fit.lm`'s closed form for the same model.
- **U2. A `fit.lm` fit and a Gaussian `fit.glm` fit can be compared.** `model.compare` accepts the pair: both have family `gaussian` and link `identity`, though their deviances are computed differently.
- **U3. A constant logical column is caught only by E106.** Unused-level dropping applies to factors, not logical columns. A logical column that is all `true` after `"omit"` duplicates the intercept and is caught by E106, which now names it.
- **U4. Some `.` forms take no stack operand.** `model.influence.` takes its only operand from the workbench. This assumes `bench!` handles a form with nothing on the stack, as RFC-0015's one-operand words' forms already do.
- **U5. Where the new `UNVARIED` names go.** The audit compares `UNVARIED` to the registry's order (`assert_eq!`), so the six names must be inserted where `declared_effects` lists them.
- **U6. Observations with μ′(η) = 0.** R drops them from each least-squares step (`glm.R:236`). The RFC's iteration does not say whether `fit.glm` does. With the clamps of SF4, μ′ can reach ε but not 0, so this may not arise. The RFC should say which.
- **U7. A logical response is FLOAT 0/1 for the binomial.** It is read as 1.0 and 0.0 and accepted as a 0/1 binomial response with unit weights.
- **U8. The null model's dispersion in `model.anova`.** Its first row's deviance is the k = 0 or intercept-only fit's (B4), and its tests use the full model's dispersion. The RFC states the second; the first depends on B4's fix.
