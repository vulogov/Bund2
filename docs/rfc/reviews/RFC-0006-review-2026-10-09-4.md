## Blocking

**B1 — Through a proxy, Bund2 fetches and evaluates for URLs the reference
refuses. With `%00` in the user part it needs no proxy.**

§B7: "**In no row does Bund2 ask a listener the reference does not ask.**"
The preservation row: "in no measured row does it ask a listener the
reference does not". D127's ruling: "It does not cover Bund2 fetching where
the reference refuses, or asking a different listener; either is a defect
whenever it is found."

`Authority::of` reads the port as a number and counts the `@` signs
(`crates/bund2-stdlib/src/host.rs`). The host it returns is any text with no
colon outside brackets, and the user part is any text; `http_url` writes
both into the URL `ureq` is handed. libcurl refuses a host that holds any of
eleven characters `http::Uri` accepts, a bracketed host that is not an IPv6
address, and a user or password with `%00`. Measured 2026-10-09; "asks
nobody" means no listener received a connection.

| the program | the one variable set | oracle | Bund2 |
|---|---|---|---|
| `"http://a!b.invalid:<port>/x" use` | `http_proxy`, an HTTP proxy | fails; asks nobody | **`CONNECT a!b.invalid:<port>` to the proxy, then `GET /x`; evaluates the answer** |
| the same with `$`, `&`, `'`, `(`, `)`, `*`, `+`, `,`, `;` or `=` in the host | the same | fails; asks nobody | **the same, each** |
| `http://127.0.0.1!:<port>/x`, `http://127.0.0.1,1:<port>/x` | the same | fails; asks nobody | **the same** |
| `http://[zz]:<port>/x`, `http://[::g]:…`, `http://[1.2.3.4]:…` | the same | fails; asks nobody | **`CONNECT [zz]:<port>`, and so on; evaluates the answer** |
| `"http://a%00b@127.0.0.1:<port>/x" use` | — | fails; asks nobody | **`GET /x` to the origin, `Authorization: Basic YSUwMGI6`; evaluates the answer** |
| `http://u:%00@127.0.0.1:<port>/x` | — | fails; asks nobody | **the same** |
| `http://a%00b@127.0.0.1:<port>/x` | `http_proxy` | fails; asks nobody | **through the proxy** |
| `a~b`, `a_b`, `a-b` in the host (control) | `http_proxy` | through the proxy | through the proxy |
| any of the hosts above | — | fails | fails |

Every other punctuation byte was tried in the host through the proxy: `%`,
`:`, `<`, `>`, `[`, `\`, `]`, `^`, a backtick, `{` and `}` fail on both, and
`|` is fetched by the reference and refused by Bund2 (S2).

**Why it blocks.**

- It is the direction the RFC says does not occur and D127 names a defect.
  The reference refuses the URL; Bund2 evaluates what a listener returns for
  it. With a proxy set, the listener is the proxy, for any host string at
  all.
- The eleven are RFC 3986's sub-delimiters, the characters a second parser
  written to that RFC accepts in a host. `!` and `,` are a typing slip away
  from a real name.
- It is the thirteenth review's B1 with one field moved. That fix is
  headed "**Nothing after the colon is passed on as text**"; the text before
  the colon still is.
- It is closable in `host.rs`: Bund2 writes the URL.

**The last row is not agreement.** Directly, both fail, but Bund2 fails at
name resolution: `http::Uri` accepted the URL and the resolver was asked for
`a!b.invalid`. I did not record resolver traffic. A resolver that answers
every name would make the direct rows differ too.

**What it needs.** No ruling: D127 has made it. A host and a user part read
as libcurl reads them before `ureq` sees either; rows in the measurement for
a refused host through a proxy, which the 278 do not have (row 242, the
non-ASCII host, is the only host tried that way); a test.

**B2 — For five kinds of setting the two ask different listeners, and each
evaluates what it gets.**

Not a refusal on either side. Both fetch; one from the origin and the other
from the proxy.

| the one or two variables set (the URL is `http://127.0.0.1:<port>/x` unless said) | oracle | Bund2 |
|---|---|---|
| `http_proxy=http://a%00b@127.0.0.1:<proxy>` | **direct, from the origin** | **through the proxy**, `Proxy-Authorization: Basic YSUwMGI6` |
| the same with `%01`, `%09`, `%0a`, `%0d` or `%1f` in the user; with `%00` in the password; with no scheme; in `all_proxy` | direct | through the proxy |
| the same, and `all_proxy` naming a second proxy | direct; the second is not tried | through the first |
| the same with `%20`, `%7f`, `%80`, `%ff` (control) | through the proxy | through the proxy |
| `no_proxy=0127.0.0.1`, `00127.0.0.1` or `127.0.0.0001` | direct | through the proxy |
| `no_proxy=127.0.0.9/+8` | direct | through the proxy |
| `no_proxy=127.0.0.9/4294967304` | direct | through the proxy |
| `no_proxy=127.0.0.1/+33` | through the proxy | **direct** |
| URL host `[::ffff:7f00:1]`, `no_proxy=::ffff:7f00:1` | direct | through the proxy |
| URL host `[::ffff:7f00:1]`, `no_proxy=::ffff:127.0.0.1` | through the proxy | **direct** |

Four causes, each a line of `host.rs` against a sentence of §B7's table.

- **A proxy whose credentials libcurl will not decode is no proxy at all, in
  the reference.** An escape for a byte below `0x20` in a proxy's user or
  password, and the oracle fetched directly, as though the variable were
  unset. That is libcurl's behaviour and I did not trace it past the
  measurement; it looks like a defect there. Bund2 passes the user part
  through and uses the proxy. Nothing in §B7's table has a row for it: row
  42 tried `user:pw@`.
- **"an entry is an address only as four decimal numbers".** True of the
  oracle, and `0127` is a decimal number to it. `ipv4` refuses a part longer
  than three digits (`part.len() > 3`), so Bund2 does not take the entry for
  an address.
- **"`/0` and `/x` mean the whole address", "as C's `atoi` leaves them".**
  `atoi` reads a leading `+` and wraps a number past 32 bits;
  `leading_number` reads `+8` as no digits, so as 0, and refuses a long
  number. `/+8` is eight bits in the reference and the whole address in
  Bund2; `/+33` matches nothing in the reference and the whole address in
  Bund2.
- **"An IPv6 host | by its shortest text".** `bypasses` compares
  `Ipv6Addr::to_string()`, which is Rust's canonical text and writes an
  IPv4-mapped address with dots: `::ffff:127.0.0.1`, sixteen characters,
  for a host written in thirteen. The reference compared the thirteen. For
  `::1` the two texts are the same, and `::1` is the only address the 278
  rows try.

**Why it blocks.** F182's own sentence: "the environment was deciding who
supplies code for a URL the program names". Here it still does, differently
on the two binaries, in both directions. Rows two and three of the list are
exotic and I would not hold the RFC for them alone. The first is not:
`http_proxy=http://user:pass@proxy` is the ordinary way to write a proxy,
and what the two do with an odd byte in the password is opposite. And each
is a sentence of the RFC that the code beside it does not implement.

**What it needs.** For the three `no_proxy` causes, the code or the
sentences. For the first, a decision I do not think is mine to predict:
reproducing it means Bund2 ignores a proxy the user set, which is the
reference's behaviour and reads as its defect; not reproducing it is a
deviation in which listener is asked, the kind D124's "Why" says F182 made
the reference's. Either way an entry, and rows.

**B3 — A `file:` path with `..` in it is read as text by the reference and
as a path by Bund2, and through a symlink they are different files.**

§B7: "`file:` follows curl's rules as far as they were measured". F183's
note of 2026-10-09: "libcurl removes dot segments, so `/a/../b` is requested
as `/b`" — said of an `http:` URL, and done for one in `curls_path`.
`Target::of` gives a `file:` path to `percent_decode` and then to
`std::fs::read`, so the operating system resolves `..`.

Measured 2026-10-09. `d/link` is a symlink to `d/real/sub`; `d/t.bund`
prints one word and `d/real/t.bund` another.

| the program | oracle | Bund2 |
|---|---|---|
| `"file:///d/link/../t.bund" use` | **evaluates `d/t.bund`** | **evaluates `d/real/t.bund`** |
| `"/d/link/../t.bund" file bund.eval` | `d/t.bund` | `d/real/t.bund` |
| `"file://localhost/d/link/../t.bund" use` | `d/t.bund` | `d/real/t.bund` |
| `"file:///d/nosuch/../t.bund" use` — no such directory | evaluates `d/t.bund` | fails |
| `"file:///d/data.txt/../t.bund" use` — `data.txt` is a file | evaluates `d/t.bund` | fails |
| `file:///d/link/%2e%2e/t.bund` (control) | `d/real/t.bund` | `d/real/t.bund` |
| `file:///d/real/sub/../t.bund` (control, no link) | `d/real/t.bund` | `d/real/t.bund` |

**Why it blocks.** Both succeed, silently, on different code. It is the
`file` word, which every program that reads a file uses, and not only
`use`. On macOS `/tmp`, `/var` and `/etc` are symlinks, so a path such as
`/tmp/../x` needs no setup to differ — that is reasoning from the layout
and was not run. D125 approves Bund2 reading a file the reference refuses;
nothing approves reading a different one. And the rule is already written
down and implemented, for the other scheme.

**What it needs.** `curls_path`'s dot-segment removal applied to a `file:`
path before it is decoded (`%2e%2e` is not a dot segment to either binary,
as for `http:`), rows, and a test with a symlink.

## Should fix

**S1 — Credentials are sent as written; the reference decodes them first.**
Not in §B7's table, and `a_url_is_rewritten_as_libcurl_sends_it` pins the
undecoded form (`sent("a%40b@h:1/x")` is `to("a%40b@h:1/x")`).

| the URL's user part, or the proxy's | oracle sends `Basic` of | Bund2 sends `Basic` of |
|---|---|---|
| `u:p@` (control) | `u:p` | `u:p` |
| `a%40b:c%3Ad@` | `a@b:c:d` | `a%40b:c%3Ad` |
| `u%20s@` | `u s:` | `u%20s:` |
| `a%0ab@` in a URL | `a`, a line feed, `b:` | `a%0ab:` |
| `%zz@`, `a%@` (control) | as written | as written |

A server that checks the header answers the reference 200 and Bund2 401,
and §B7's own sentence — "the body of an error status is still the
answer" — means `use` evaluates whichever body came. For a proxy the
credentials go on the `CONNECT`, a refusal fails the fetch, and Bund2 fails
closed. The `Host`, `User-Agent` and `Accept` headers of a direct request
were compared for ten settings and agree, in another order and in lower
case; that includes `Host: 127.0.0.1` for `127.1`, which the thirteenth
review listed as a claim with no measurement behind it.

**S2 — D127's rule covers more than the four spellings §B7 lists.** All
fail closed, so all are inside the ruling; the bullet reads as the whole
list and is a third of it.

| the URL, or the proxy | oracle | Bund2 |
|---|---|---|
| `<`, `>`, `[`, `\`, `]`, `^`, a backtick, `{`, `\|` or `}` in the user part | fetches, the byte in the credentials | refuses; asks nobody |
| a user part that is not ASCII, in the URL or in the proxy | fetches | refuses |
| `\|` in a host, through a proxy | asks the proxy | refuses |
| a URL longer than 65,534 bytes | fetches (65,520 and 66,000 bytes of path tried) | refuses |
| `<>` in a query | fetches | refuses (row 211 has `<` alone) |

And two things about the bullet's wording: it says "in a path", and row 211
is a query; it says "of an `http:` URL", and row 261 is a proxy, which
D127's table has and the RFC's sentence does not.

**S3 — Two responses the reference evaluates and Bund2 does not.** §B7: "It
keeps three of the defaults the reference leaves curl at". What counts as a
response is a fourth thing the two clients decide separately. Of 28 shapes
the origin answered with, 26 agree — a body shorter or longer than its
`Content-Length`, none, HTTP/1.0, no status line, 404, 301, 204, 304, 401,
999, `100` and `103` first, chunked, a chunk cut short, a bad chunk size,
`Content-Encoding: gzip` on plain text, bare line feeds, two lengths, a
200,000-byte header, bytes that are not UTF-8. Two differ:

| the response | oracle | Bund2 |
|---|---|---|
| 127 or more header lines (126 agree) | evaluates the body | fails |
| a status line `HTTP/2 200 OK` | evaluates the body | fails |

Both fail closed. The first is `ureq`'s limit and a real server can reach
it.

**S4 — An IPv6 host is sent as written; the reference shortens it.**
`http://[0:0:0:0:0:0:0:1]:<port>/x`: the oracle sent `Host: [::1]:<port>`
and asked a proxy for `http://[::1]:…`; Bund2 sent
`host: [0:0:0:0:0:0:0:1]:<port>`. `http_url` rewrites an IPv4 host for this
reason (F183) and passes an IPv6 one through. The reference shortens only
when the result is shorter: `[::FFFF:127.0.0.1]` went out as written, in
upper case. That rule is also what B2's last two rows turn on.

**S5 — D124's first cost can be said as measured.** §B7: "A proxy that
serves one and refuses the other answers the two differently; that is read
from the code and not measured against a real proxy." Against a listener
that answers `CONNECT` with 403 and `GET http://…` with the program: the
oracle evaluated what the proxy returned and Bund2 failed, having sent the
`CONNECT`. Not a real proxy; a measurement all the same, and it shows the
other half the sentence leaves out — in the reference a proxy's own answer
to the `GET` is evaluated whatever its status.

**S6 — Three things about the measurement file.**

- "In 30 of them Bund2 refuses and asks nobody, where the reference asks
  somebody." Row 276, `tftp://`, is one of the 30 and its oracle cell is
  `timeout · -`. TFTP is UDP and the listeners are TCP, so the table cannot
  show whom it asked.
- "Bund2 is the commit that adds this table: `acf448d` and the answers to
  RFC-0006's thirteenth review." The commit is `caa1e8d`; at `acf448d`
  rows 213 to 217 reach port 80. A file cannot name the commit that adds
  it, and a later note can.
- It records the request line. B2's first row and S1 are differences in a
  header, which `fetch.py` reads and drops.

**S7 — The report is on standard output, and the RFC says standard error
twice.** §B3, on the recorded source path: "so a bundle's stderr matches a
`script` run"; the preservation row "Diagnostic file name": "a bundle's
stderr differs by construction". Measured: `1 nosuch` under `bund2 script`
wrote 2,111 bytes to standard output, the path among them, and nothing to
standard error. The claim is right about the report and names the wrong
stream.

**S8 — A refusal takes time that grows with the square of the string
refused.** Outside this RFC's design and met on its refusal path. A `use`
of an unfetchable string of 20,000 bytes took 1.5 s to report, 40,000 took
6.0 s and 66,000 took 16.2 s, in the debug build; the fetch itself returned
at once. The message carries the operand whole (`{prefix} can not get from
{addr}`), and D36's bound is on values, not on a message. Not measured in a
release build.

**S9 — Small, each one line.**

- The header's paragraph on the thirteenth review stands before the one on
  the twelfth.
- §B7's table: "a proxy with a slash, path or query after its address |
  used, and what follows is ignored". True of the rows; `curls_proxy` also
  cuts at `#`, which no row tries.
- `Authority::of`'s comment: "A number too long to parse is over 65535 as
  well." A port of `00000000000000000080` parses, because the zeros are
  trimmed first; the sentence is about what is left. Read, and row 220
  agrees for two zeros.

**S10 — Carried, all stated in the RFC and none changed.** `cargo xtask
bundle` in neither `cargo test` nor CI; `black_box` a hint; ELF and PE
unmeasured in the built form; `/usr/bin/codesign` possibly a stub; no
criterion has run in CI; the recorded version is `0.0.0`; Q42; the three
loose citations.

## What the RFC assumes and does not state

1. **A string `Authority` accepts is one libcurl accepts.** B1. It checks
   the port and the `@` count; libcurl also checks the host's bytes, the
   brackets' contents and the credentials' escapes.
2. **A proxy value libcurl cannot use fails the fetch.** B2. `proxy_for`
   has two outcomes for a named proxy, use it or fail. The reference has a
   third: carry on without it.
3. **Rust's text for an address is libcurl's.** B2, S4. True of `::1`.
4. **`atoi` is "the leading digits".** B2. It is an optional sign, then
   digits, then whatever the C library does on overflow.
5. **The operating system resolves a path as libcurl rewrites it.** B3.
   True when no component before a `..` is a link, a file or missing.
6. **Agreeing on the request line is agreeing on the request.** S1, S6.
7. **Both fail, so both did the same thing.** B1's last row: one refused
   the URL and the other asked a resolver.
8. **A proxy variable that is not UTF-8 is unset.** Carried from the
   twelfth review; `fetch_uri` reads with `std::env::var(..).ok()`. Read,
   not measured.
9. Carried from the eleventh to thirteenth reviews and unchanged: the
   sentinel cannot occur in what a build writes; no golden fails to parse;
   `--inspect` reports what a header says and not what the runtime does;
   the executable on disk is the one running when `build` copies it.
10. Carried, and stated in the RFC: the compiler does not fold reads of the
    region; the in-place write works on ELF and PE; `/usr/bin/codesign` is
    present and real; a refusal is text and not an exit status; the rules
    are one libcurl's, 8.7.1, on macOS.
