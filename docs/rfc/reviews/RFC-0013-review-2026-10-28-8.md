## Should-fix

### S1. If the engine's poll is missing, the E40 test never ends

Criterion 1b's E40 test trips the guard, then runs `[ loop ]` over
`[ [ loop ] ← [ loop ] ]`. That query ends only when something stops it,
and the RFC gives it nothing else that would:

- the KB has no `inferences` cap, and the default is none (S7's caps
  table: "none");
- with no cap, W1 is a `Warning` and the query goes on (S7, D36, D39);
- the interpreter never polls, since the query starts no body.

So an engine that forgot its poll, which is the one defect this test is
there to catch, makes `cargo test` hang. It does not fail. The revision 8
thread form had the same exposure, and revision 9 kept it.

**Fix:** give the test's KB an `inferences` cap, say 1,000,000, and have
the test assert E40 and not E30. Then a missing poll fails in under a
second, as E30, and the assertion names it.

## Notes

- **N1. "By its text" means a substring for a top-level program.**
  `Runtime::eval_str` goes through `Interp::eval`, which wraps any failure
  as `Attempt to evaluate value <v> returned error: <reason>` (the wrapper
  in `Interp::eval`). So the E40 test sees `KB.QUERY: ` and the guard's
  text inside that wrapper, not as the whole message. The existing guard
  tests use `contains` for this reason. Worth half a line in criterion 1b,
  so that whoever writes the test does not assert equality and spend a
  run finding out why.
