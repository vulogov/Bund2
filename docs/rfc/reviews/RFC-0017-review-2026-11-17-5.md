## Should fix

### S1. "Calls the shared arithmetic": only `variance` is a function there is to call

**The RFC says** (RFC:392-398): `frame.aggregate` "calls the shared arithmetic, not the words' checking wrappers: `vec.sum`'s sum, `describe.rs`'s `variance` and its square root, `stat.median`'s median, `amean`'s sum over count".

**What the source shows.**
- `variance` is `pub(crate)` and takes `&[f64]` (`describe.rs:33`). It is callable as described.
- `vec.sum`'s sum has no function of its own. `fn sum(word, xs)` (`vector.rs:71`) *is* the checking wrapper: `finite(word, xs.iter().sum(), || "Σ xᵢ")`. It is private.
- `stat.median`'s median is inline in the private wrapper `fn median(word, xs)` (`describe.rs:62`), after `at_least`.
- `amean`'s sum over count is inline in `fn amean(vm, side, mode, prefix)` (`series.rs:277-289`), which reads its operand from the VM. No slice-taking function exists.

**Why it matters.** An implementer must choose between two routes, and the RFC names neither:
- **Extract** three functions, which changes RFC-0015's `describe.rs` and `vector.rs` and the reference word's `series.rs`. Preservation lists a visibility change for `data.rs` only (RFC:660).
- **Restate** `xs.iter().sum()`, `sum / n` and the median's middle in the frame code. Then "calls" is "computes by the same expression", and criterion 5's bit-for-bit test is what keeps them equal.

The bit-for-bit claim holds by either route (Verified). Only the description of how it is reached is wrong.

**Suggested fix.** Name the route. Either list the extracted functions and add a Preservation row ("`describe.rs`'s `median`, `vector.rs`'s sum and `series.rs`'s `amean` arithmetic factored into slice functions; the words unchanged, their tests unchanged"), or say the three expressions are restated and that criterion 5 compares them. Restating is the smaller change. It touches no module of RFC-0015 or the reference's word.

### S2. The empty-field rule narrows D258 B1's "NONE" without saying so

**The RFC says.** At RFC:485-486: "In a one-column frame an empty line is one empty field **[D258 B1]**". At RFC:515-517: "An empty unquoted field that the `na` strings do not name is an empty STRING … **[author]**. Under the default `na` it is NONE."

**What the ruling says.** "In a one-column frame an empty line is one empty field, NONE" (`decisions.md:17543`, D258 B1).

**Why it matters.**
- Under `{ na: [ "NA" ] }`, an empty line in a one-column text is an empty STRING by the RFC, not the NONE the ruling names. The RFC's sentence under the D258 B1 mark drops the ruling's "NONE".
- The choice is sensible: it is the fourth review's S4, and it makes `""` in `na` meaningful. But it is a narrowing of a ruling of the same kind as D256 S3's, which the RFC does mark (RFC:251-252).
- The open-questions entry (RFC:887-888) lists the empty-field rule but not that it qualifies D258 B1.

**Suggested fix.** At RFC:486, write "one empty field, NONE under the default `na` (S6 'Fields') **[D258 B1]**, narrowed **[author]**". Add "narrowing D258 B1's NONE to the default `na`" to the list. The owner may want a dated note beside D258, as the scopings of D255 and D258 S2 got. This is drafting, not a new question: the owner can overrule the note.

### S3. CSV refusals in the header row have no row to name, and the width text assumes a header

**The RFC says.** Rows are "counting data rows (row 1 is the first after a header)" **[author]** (RFC:202-203). The quoting refusals name a row: `a quote opened at row 7 is not closed`, `row 7 has "b" after a closing quote`, `row 7 has a quote inside an unquoted field` (RFC:647). The width refusal is `row 7's fields and the header's do not agree: 3 and 4` (RFC:646).

**Gaps.**
- With `header` true, a malformed header has no data-row number. Examples are `"a"b,c`, `a"b,c`, or a header whose quote never closes. Is it row 0, `the header`, or something else?
- With `header` false there is no header. The width comes from the first row (RFC:500-501), but the text says "the header's".

**Why it matters.** Criterion 6 tests an unterminated quote, `"a"b` and `a"b` by text. The text for the same faults in a header is whatever the implementer writes. A TUI or a test that matches texts would differ between implementations.

**Suggested fix.** One sentence and two S8 alternatives, marked **[author]**:
- "A fault in the header row names `the header` in place of `row <n>`."
- With `header` false, the width text reads `row 7's fields and row 1's do not agree`.

Add a header-row quote fault to criterion 6.

### S4. `frame.factor.levels` has no refusals in S8

**The RFC says.** `frame.factor.levels` (`frame name levels -- frame`) is "the same with the given levels, each cell required to be one" (RFC:331). S1 says every refusal is listed with its text in S8 (RFC:200-201, D256 S3).

**What S8 has.** Two rows come near it, and neither fits:
- "`levels` … not distinct STRINGs" names `frame` and reads `levels of "g": <what>` (RFC:625).
- "a factor cell not among its levels" names `frame` (RFC:629).

Both are the frame check's texts, reached only if the word builds the answer and checks it. Nothing says:
- what `levels` that is not a LIST, holds a non-STRING, repeats an entry or is empty does;
- that a cell not among the given `levels` is refused naming the `levels` operand and the row;
- whether a numeric or logical column is refused, as `frame.factor` refuses one (RFC:356-358).

**Why it matters.** An implementer either lets the answer check speak, with a text naming `frame` for a fault in the `levels` operand, or invents texts. Criterion 4 tests `.factor.levels` only on success.

**Suggested fix.** Add S8 rows naming `levels`, for example `levels is outside <w>'s domain: "c" at row 3 is not one of the levels` and `… "a" given twice`. Say whether a numeric or logical column is E101 as for `frame.factor`. Add one refusal case to criterion 4.

### S5. A column of no kind, and a frame of no rows, in the words that ask for a kind

**The RFC says.** A column that is all NONE, or has no rows, "takes no kind until a cell says one" (RFC:246). Then:
- `frame.factor` "takes a string column, or a factor column … A numeric or logical column is E101" (RFC:356-358), and `factors` refuses alike (RFC:465-466).
- `frame.aggregate`: "every statistic but `"count"` needs a numeric column, else E101" (RFC:387-388), and "an empty `by` makes one group of every row" (RFC:390-391).

**Gaps.**
- **`frame.factor`, or `factors`, on a column of no kind.** It is neither a string column nor a numeric or logical one. A wholly missing column in a CSV is common.
  - The reader shares `column_kind`, which calls "no evidence at all" a string (`data.rs:117-125`). So by the code it is a string column, and by S2 it has no kind.
  - Allowed with empty levels, or E101? Unstated.
- **`frame.aggregate` on a frame of zero rows.**
  - With an empty `by`: is that one group of no rows, which "a group with no cells" (RFC:402-404) refuses with E101, or no groups and a zero-row answer?
  - With a non-empty `by`: is a statistic over a column of no kind E101 ("needs a numeric column"), or accepted because no cell contradicts it?
- **`frame.join` settles the same question for itself** ("a `by` column of no kind … agrees with any", RFC:433-434), so the RFC knows the case. These words lack the sentence.

**Suggested fix.** Mark each choice **[author]**:
- "A column of no kind is accepted wherever a kind is asked for, as `frame.join`'s keys are; `frame.factor` makes it a factor with no levels."
- "On a frame of no rows, `frame.aggregate` answers a frame of no rows, an empty `by` included."

Add the zero-row case to criterion 5.

## Notes

**N1.** `… <n> more rows` still reads `… 1 more rows` for 21 rows (the fourth review's S7). Say "row" for one, or say the plural is kept.

**N2.** "Padding is never added at a line's end, but a STRING's own trailing spaces are kept" (RFC:570-571) leaves the separator open. If the last column is left-aligned and a row's cell there is the empty STRING, the line ends with the one space between columns. Is that space padding, and dropped, or kept? A STRING holding a line break, printed "as it is" (RFC:575), breaks the table's rows, and its width in characters counts the break. Say whether that is accepted.

**N3.** The reader's rule for a quoted field's line breaks (RFC:477) does not say they are kept byte for byte, with CRLF not normalised to LF. The round trip of a STRING holding `\r\n` depends on it. `csv` keeps them: a quoted `"a\r\nb"` read through `csv` has `len` 4 (probed). Add "kept as written".

**N4.** RFC:399-401 lists `"sum"`, `"mean"`, `"min"`, `"max"` and `frame.matrix` as inexact above 2⁵³. `"var"`, `"sd"` and `"median"` convert through the same `conv_value` (`series.rs:97`). Probed: `[ 9007199254740993 ] vec.sum println` and `… stat.mean.arithmetic println` both print `9007199254740992.0`. Say "every statistic but `"count"`".

**N5.** `"min"` and `"max"` have no named word (D256 S1), yet criterion 5 asks "each group's answer equal bit for bit to the named word's" for "every statistic". Say what the test compares them with: the smallest cell as a FLOAT. Also, "compared as numbers" leaves a tie between `0.0` and `-0.0` (or INTEGER `0`) open. `math.min` answers `-0.0` for both `[ 0.0 -0.0 ]` and `[ -0.0 0.0 ]`, and `[ -0.0 0 ] math.max` answers `0.0` (probed). Say whether the first, the last, or `-0.0` wins.

**N6.** D252's third note ends "`frame.csv.parse` makes it. An `na` option on those would have nothing to decide" (`decisions.md:17364-17367`). The RFC gives `frame.csv.parse` a key `na` (RFC:208-211, 463), which is P6's missing strings and D255's escape, a different option of the same name. The RFC is right, and D255 itself says "the `na` option" for the reader. One clause at RFC:297 would stop a reader taking the note to forbid the key: "the `refuse`/`omit` option; the reader's `na` key is P6's list of missing strings".

**N7.** S8's `levels` row (RFC:625) ends `<what>` over three faults: `levels` not a MAP, a key not a column, levels not distinct STRINGs. Criterion 2 compares this row's text, which the RFC does not fix. Give the three texts.

**N8.** The row "`frame.factor` or `factors` on a numeric or logical column" (RFC:635) hard-codes `name is outside …`. For `factors` the operand is `opts`. Write `<operand>`, as the row two above now does.

**N9.** "The checks come first" (RFC:392-398) is in the open-questions list (RFC:873-874) but carries no **[author]** mark where it stands.

**N10.** §Current behaviour calls `csv`'s integer "digits only, `is_int`" (RFC:104-105). `is_int` takes a leading `-` (`data.rs:101-103`), which is why a negative INTEGER round-trips. Write "an optional `-` and digits".

**N11.** "Every line is a record" (RFC:484) is literally false for a quoted field holding a line break, which RFC:477 allows. Write "every line outside a quoted field ends a record".

**N12.** The E114 text names a group as `[ "a" ]` (RFC:640). Unstated:
- how a group of two `by` columns renders;
- how a NONE key renders;
- how the single group of an empty `by` renders (`[ ]`?).

Presumably it is `BundValue::summary` of the key LIST. Say so.

**N13.** Preservation lists `bund2 words`' listing (RFC:673). `bund2 effects` (the CLI's usage line: `bund2 words | effects`) prints the declared effects and changes the same way. Add it to the row.

## What the RFC assumes and does not state

- **That `file`'s path is absolute.** `"rel.csv" file` from the file's own directory is `FILE gets no data` (probed). The reading example at RFC:458 writes `"path" file` without saying so (the fourth review's N2).
- **That `file` reaches only the file system.** It also fetches over HTTP (`host.rs:1454-1460`, the `Target::Http` arm), so "No new I/O" holds but `frame.csv.parse` can parse fetched text.
- **That `frame.filter` reaches the bridge.** `dynamics.rs`'s `call` is `pub(super)` (`dynamics.rs:53`), private to `biomath`, so a `frame` module calls `kb::bridge::ask` directly or needs a visibility change. Neither is named.
- **How the three non-`variance` statistics are reached** (S1).
- **That a quoted field's bytes are kept as written** (N3).
- **That a header row is not row 0** (S3).
- **The order of the frame check against other operand checks.** A malformed frame with a bad `opts` gets one refusal or the other. Criterion 9 accepts either, but a text-comparing test would not.
- **That a row MAP per row in `frame.filter` and `frame.rows` is affordable** at Tier 0 (carried from the fourth review; RFC:359-360 says only "bounded").
