Two blockers are new, and **both are one level past the check §S5 now
performs**. §S5's pre-call check pins the effect of the *callee's slot*. It
does not pin the effect of what the callee runs.

- **B1.** A lambda's effect is inferred from the words its body calls. Those
  words can be rebound without touching the lambda's slot, including during
  the call itself.
- **B2.** `execute.` (`!.`) runs arbitrary code, but its effect is declared as
  `eff(1, 0)` rather than opaque. §S5 promotes straight across it, and the
  corpus's own probes call it.

## 1. Blocking

### B1 — the pre-call check pins a lambda's slot, and a lambda's effect is read from other slots

§S5, *A fold, or any change of effect, arriving at run time*:

> Promotion across a call keeps the values below the callee's arity in
> registers, and it trusts the callee's effect *as it was at compile time*.

and, on the third inlining rule:

> The pre-call check trusts only an effect, and **the generation pins the
> binding that effect was read from**.

That holds for a native, whose effect is declared on the `Native` in its own
slot. **It does not hold for a lambda.** A lambda has no declared effect:
`Registry::effect_of` returns `None` for it, and its doc comment says "a
lambda's is inferred rather than declared" (`crates/bund2-api/src/lib.rs`,
`Registry::effect_of`, `Registry::declared_effects`). RFC-0004 §S3 infers a
Bund word's effect by composition: "a call is that word's `Effect`". §S5 relies
on that directly: "A word's declared **or inferred** `StackEffect` gives the
arity".

So a lambda callee's effect is read from **every slot its body calls
through**, and the check reads one of them.

1. **Rebound before the call.** Take `:g { drop } register  :f { g }
   register`, and a body `1 2 3 f` that promotes `1` and `2` across `f`,
   because `f` infers as `(1, 0)`. Then run `:g { drop drop drop } register`.
   `f`'s slot is not touched, so the check passes. `g` pulls three values from
   a stack that holds one. Tier 0 would have handed it all three.
2. **Rebound during the call.** `:f { :g { drop drop drop } register g }
   register`. No check *before* the call can see a rebind the callee performs
   itself. A lambda's body can contain `register`, `alias`, `unregister` or
   `:`, and §S5's own list says each changes "what a later name means".

This is CLAUDE.md's "follow the call one level further" once more. The seventh
review's B2 took the check from the call slot to the target slot. This takes it
from the target slot to the target's body. It is also the same shape as Q34, a
word observing beyond its declared arity, arrived at by inference rather than
by annotation.

**Required:**
- State where a lambda callee's effect comes from at compile time. §S5 and
  criterion 13 cover a declared effect and an absent one, and neither covers an
  inferred one.
- The rule that survives both cases above: **nothing stays promoted across a
  call that resolves to a lambda.** Sync before it, as at an opaque site. A
  weaker rule has to pin every slot the inference read, and it still fails
  case 2.
- Correct "the generation pins the binding that effect was read from" to say
  it is true of natives only.
- Add the case to criterion 22, both the rebind before the call and the rebind
  during it, and add a Preservation row.

### B2 — `execute.` runs arbitrary code under a fixed effect, and the probes call it

`!` is registered `StackEffect::opaque(1)`, and `!.` aliases `execute.`, which
is registered `eff(1, 0)` (`crates/bund2-stdlib/src/values.rs`, `init`:
`execute` and `execute.`). Both reach the same `execute_value`, through
`execute_top` and `execute_from_workbench` respectively. So `execute.` runs a
name, a lambda, a CONDITIONAL, a class or an object while declaring that it
consumes one value and produces none. The binary agrees:

    :!. ?effect println        →  { consumes=1 :: opaque=false :: produces=0 :: }
    :! ?effect println         →  { consumes=1 :: opaque=true :: produces=0 :: }

(Run 2026-09-10 against `target/release/bund2`. The declared `consumes=1` is
also wrong on its own terms: `execute_from_workbench` pulls from the workbench,
and `execute_from_the_workbench_works_on_an_empty_stack` asserts that the main
stack may be empty.)

Consequences for this RFC:

- **§S5 promotes across it.** "Promotion stops at an opaque site", and this
  site does not declare itself one. Promoted values below the claimed arity of
  1 are invisible to whatever the executed value does.
- **It is the second fixed-effect route to a mid-body report.** `!.` on an
  `?error` CONDITIONAL reaches `run_error`, which reports a notice
  (`crates/bund2-stdlib/src/conditional.rs`, `run_error`).
- **§S6's count misses it.** `tests/probes/remaining-vocabulary.bund:52` and
  `:55` call `execute.` and `!.`. Neither appears among the 63 sites in *Where
  promotion stops*, because `bund2 check` reads the declared effect.
- **No criterion catches it.** Criterion 13 covers an *absent* effect.
  Criterion 14 covers Q34's observers, and says "nothing identifies that set".

The rest of the table is in better shape than this one entry suggests. I
listed every stdlib function that re-enters evaluation (`eval_lambda`,
`tail_lambda`, `scoped_call`, `vm.apply`, `vm.call`), sixteen of them, and
checked each one's registered words. `times`, `loop`, `map`, `if`,
`ifthenelse`, `while` and their `.` forms, `apply`, `?move`, `#` and `execute`
are all opaque. The `?`-family constructors `?try`, `?error` and `?ifthenelse`
push a CONDITIONAL and run nothing. **`execute.` is the one exception I
found.** But §S5's soundness rests on the whole table being right, and nothing
mechanical says it is.

**Required:**
- Record `execute.`'s declared effect as a Bund2 defect: RFC-0004's annotation,
  not this RFC's. The number is the owner's to assign.
- Add a criterion: **every native that re-enters evaluation declares
  `StackEffect::opaque`**, checked mechanically. Candidates: a test that runs
  each registered native under a `Vm` whose `eval_lambda`, `tail_lambda`,
  `scoped_call`, `apply` and `call` record that they were reached, or a
  `WordKind` the registry refuses to pair with a fixed effect.
- Re-derive *Where promotion stops* once it is fixed. The count moves by at
  least two.

## 2. Significant

### S1 — two of criterion 22's four parts cannot fail as written

- **"An error with values promoted" constructs no error.** The criterion's
  program is `1 2 "a" +`, with the claim that `+`'s generic path "returns the
  error". It does not: `numeric_op`'s string arm turns an `Int` and a string
  into a string (`crates/bund2-stdlib/src/math.rs`, `numeric_op` and
  `string_op_int`; F64's pass-through family). Run 2026-09-10,
  `1 2 "a" +` exits 0 with no report. The part tests a successful concatenation
  and asserts nothing about an error path. Choose an operand shape
  `numeric_op` refuses (its LIST arm, or its `Incompartible Y argument` arm),
  and confirm against Tier 0 that it errors before the criterion names it.
- **"The reporter, observed through the diagnostic" cannot see the rule it
  tests.** `?error` is `eff(0, 1)` and only pushes a CONDITIONAL
  (`q_error`). The notice comes from `run_error`, which runs only when that
  value is executed by `!`, and `!` is opaque. So by the time the notice is
  reported, promotion has already stopped and synced, and the snapshot matches
  Tier 0's whatever §S5's reporter rule does. The only fixed-effect word that
  reports mid-body today is **`alias`**, which is `eff(2, 0)` and warns when a
  binding resolves back to itself (`crates/bund2-stdlib/src/singles.rs`,
  `alias`). That is the call to promote across. (`!.` is the other, until B2
  is fixed.)

### S2 — "never lower" is argued in bytes and checked in levels, and the decline path decides between them

D44's second requirement is about **capacity**: "Tier 0's capacity is never
less". §S8 argues it in bytes: the thread grows by Tier 1's share, compiled
frames start only above the Tier 1 floor, so Tier 0 keeps its 8 MiB. Criterion
11 checks something else: **the `loop` level with the feature on is no lower**.
Levels are bytes divided by bytes per level, and the RFC leaves bytes per level
open in two places.

1. **What a decline costs.** "At any other position it is `Vm::eval_lambda`:
   one synchronous boundary into Tier 0's part." A compiled body is
   substituted at `eval_lambda` (Preservation, the `Lambda content evaluation`
   row). If the declining body *calls* `Vm::eval_lambda`, every level below
   the Tier 1 floor spends a compiled prologue frame, a second `eval_lambda`
   frame and `run_to` on top of what the tier-off level spends. Each level
   beneath the floor is then larger with the tier on. Whether the extra levels
   above the floor make up the difference depends on frame sizes, not on the
   design. If instead a decline *returns* to its caller with a status, and the
   caller runs Tier 0 in the frame it already holds, the per-level cost below
   the floor is unchanged and the argument goes through. The RFC must say
   which.
2. **The straddle.** The last compiled body entered just above the Tier 1
   floor, together with the non-re-entering callees it runs, extends below the
   floor by up to a reserve. The text contradicts itself on whether that
   stays inside Tier 1's share. *Two floors* says the Tier 1 floor "sits Tier
   1's share below the top", which puts the overhang into Tier 0's part. *The
   reserve* says it is "one reserve above the bottom of Tier 1's share", which
   keeps it out. Pick one. Only the second supports "can never occupy Tier 0's
   8 MiB".

**Required:** specify the decline as a return rather than a nesting call, or
state the bytes-to-levels argument that makes criterion 11's inequality follow.
Fix the floor's position to one statement. Either could let criterion 11 fail
on an implementation that follows the text faithfully.

### S3 — the reporter rule rests on a convention nothing enforces

§S5: "while the reporter wants a snapshot for a severity natives report
mid-body, `Warning` or `Notice`, no value stays promoted across a call." The
rule reads two severities because natives do not report `Severity::Error`
(§S11; D45: "Natives do not report errors: they return them"). That is true
today: the three `vm.report` calls in `bund2-stdlib` are two warnings and a
notice. But `Vm::report` accepts any `Diagnostic`, and nothing stops a native
reporting an `Error` mid-body. `TextReporter::wants_stack(Severity::Error)` is
true, so under the default reporter, promotion across the call to such a
native would give it a short snapshot. D45 rejected classifying reporting
natives because the classification "would be wrong on the day a native started
to warn". This rule is wrong on the day a native reports an error.

It is also missing from *What this design assumes*, which claims to list what
the text relies on.

**Required:** make it structural, for example by giving natives no way to
report at `Error` (a separate method, or a `Vm::report` that refuses `Error`
mid-evaluation as an internal error). Otherwise add it as assumption 7, with a
test that fails when a stdlib native reports `Severity::Error`.

### S5 — smaller items

- **`$name`'s effect.** §S5 has the check read "that name's slot" for a direct
  `$name`. `$` skips the lambda (`Registry::resolve` with `sigil`), so the
  effect trusted at compile time must be the **native** binding's, even when a
  lambda is bound in the same slot. As written, the rule is sound, because a
  lambda registration bumps the generation. But the RFC does not say which
  binding's effect is read.
- **"8 MiB on this machine (`ulimit -s`: 8176 KiB)".** 8176 KiB is not 8 MiB,
  and Tier 0's part is `EVAL_STACK`'s constant, not the main thread's stack
  (`crates/bund2-cli/src/main.rs`, `EVAL_STACK`). The `ulimit` is the reason
  for the default, not its value.
- **A declared region under `jit`.** `set_stack_region` takes a top and a size.
  §S8 says how an *undeclared* thread splits (no Tier 1 share), and how
  `bund2`'s own thread is sized. It does not say how a region an embedder
  declares is divided between the parts, or where the Tier 1 floor sits in it.
- **"`RUST_MIN_STACK` below about 1.25 MiB".** With `ASSUMED_BUDGET` at 1 MiB
  and `STACK_RESERVE` at 256 KiB (`crates/bund2-interp/src/lib.rs`,
  `tier0_floor`), the floor is 768 KiB below the construction point, and the
  reserve lies past the stack's end once less than 1 MiB remains below that
  point. 1.25 MiB is right only if the constructor runs 256 KiB below the
  thread's top. Show the arithmetic, or state that assumption.
- **The dev-profile level, 2,371,** cannot be reproduced with the command the
  RFC names. `cargo xtask depth` accepts `--depth`, `--timeout`, `--require`
  and `--features`, and builds release only (`xtask/src/depth/mod.rs`,
  `run_cmd`). Say how it was measured, or add a profile flag.
- **`std::thread`'s sentence.** "Currently, it is 2 MiB on all Tier-1
  platforms" is in the 1.94.1 `rust-docs` HTML ✓, and in the 1.98.1 `rust-docs`
  HTML. The *source* copy on this machine is the `stable` toolchain's
  `rust-src` (`library/std/src/thread/mod.rs:129`, with `RUST_MIN_STACK` at
  `:134`), not a "1.98.1 source". The pinned 1.95.0 has neither component.
- **Addressing** says "one stack-floor cell for the evaluation thread", and
  two paragraphs later "one set of cells … per `Interp`". The second is the
  rule. Make the first agree with it.

## 7. What the RFC assumes and does not state

1. **A lambda callee's effect is fixed for as long as the promoted values are
   held** (B1).
2. **Every native's declared effect is honest about re-entering evaluation**
   (B2). §S5's opaque rule assumes this, and RFC-0004's table does not
   guarantee it.
3. **No native reports `Severity::Error` mid-body** (S3).
4. **A declined compiled body keeps no frame** below the Tier 1 floor (S2).
5. **The Tier 1 floor sits one reserve above the bottom of Tier 1's share**,
   not at it (S2, S4).
6. **An embedder's declared region is split between the parts in some
   stated way** (S5).

## 8. Recommendation

**Stay Draft.** The response to the seventh review was complete, and
everything I could run agrees with it. D44 and D45 are recorded and built,
`depth` prints the level, `cite` measures a whole range, and every citation in
the document is right. The design has now closed the alias case, and what

   *Where promotion stops*.

   `numeric_op` refuses and a call to `alias` on a cycle. Specify the decline
   as a return and fix the Tier 1 floor's position. Make "natives do not report
   errors" structural, or list it and test it.
4. **S4–S5.** Remove the text D44 made stale, and fix the smaller items.
