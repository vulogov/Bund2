## Blocking

### B1. Criterion 12 asks for `:asked` (and §S7 maps `:known`), which `smysl.prove` cannot produce

- `smysl.prove` takes `handle kb goal opts`, and its `opts` defines only
  `facts` and `source` (line 754).
- RFC-0013 gives `ask` and `known` only as slots of the `query` conditional
  (§S11; the table at lines 1021-1022). An askable goal reached through an
  asking word is E50 (`kb/solve.rs:72,1853`).
- So no proof that `smysl.prove` returns holds `:asked` or `:known`.
  Criterion 12's list (line 1112) cannot be met, and the node table's row
  for `:asked`/`:known` can never apply.

**Fix:** either give `opts` an `ask` LAMBDA and a `known` STRING, with
RFC-0013 §S16's semantics and refusals (E50–E58), or drop `:asked` from
criterion 12 and say the row applies only through a future `prove` slot.
Either way, correct lines 719-721.

## Should-fix

**S1. "Units already present are not written again" rests on a misreading,
and changes SMYSL's semantics.**

- What the skip actually suppresses is the new `Attestation` record, not a
  duplicate unit. SMYSL's model is that "a rerun adds an attestation and
  nothing else" (`smysl-measure/src/lib.rs:28-29`).
- So a unit another agent wrote first is never attested by the handle's
  agent. Under `Origin` authority (`retraction.rs:198-208`), Bund2 then
  can never retract a unit it also authored.
- Criterion 12's "Re-proving … writes no new unit" is true without the
  skip, so it tests nothing.
- §S4 never says that attestations are appended as `Record::Attestation`;
  a relation's attestations "travel as attestation records on the wire"
  (`store/mod.rs:480-483`).

*Fix:*

- Correct the rationale in §Current and §S4.
- Skip only when *this agent* has already attested the uid, or make that
  choice explicit in R15.
- State that each attestation is written as its own record.
- Restate criterion 12 as "the log's length is unchanged".

**S2. The check profile is not fixed.**

- 41 of SMYSL's 60 `.smy` files have a `@doc` header.
  `fixtures/corpus/F2-research.smy:1-6` sets `granularity: { profile: fine }`,
  a view that `CheckOptions::default()` would adopt.
- All three presets have `l0_max: 30` (`view.rs:109-148`), so the bound on
  gists holds whichever applies. But W041's range, and E040's admission,
  follow the view.

*Fix:* pass `CheckOptions::default().with_granularity(GranularityProfile::standard())`
(`check/lib.rs:209`), or say that the store's own profile governs.

**S3. Criterion 16 cannot pass with only the two lists named.**

- `no_native_takes_a_stack_name…` asserts `unvaried == UNVARIED` exactly,
  over every fixed-effect native with more operands than the palette
  varies (`crates/bund2-stdlib/src/lib.rs:708-719`). It does not filter
  `FEATURE_GATED`.
- Under `--features smysl`, `smysl.trace` (four operands), `smysl.label` and
  `smysl.measure` (three each) enter `unvaried`. Listing them in `UNVARIED`
  would break the default build: F123's shape again.
- The preservation analysis does not mention this audit.

*Fix:* filter `FEATURE_GATED` in that audit too, add a preservation row,
and name the audit in criterion 16.

**S4. The `smysl` constructor and `PROMOTABLE.txt`.**

- Criterion 16 and the palette row put "every `smysl.` word" in
  `FEATURE_GATED`. The bare constructor `smysl` (`eff(0,1)`) is not a
  `smysl.` word, yet the Tier 1 row (line 984) assumes it is gated. If it
  is left out, the palette reaches it under `--all-features`, and
  `PROMOTABLE.txt` reports it as "now reached".
- The regeneration writes `# feature-gated: <n>` for each `FEATURE_GATED`
  entry (`lib.rs:1124-1131`). So the file's content *does* change, and
  under D72 that regeneration is the owner's to run.

*Fix:* name `smysl` explicitly in `FEATURE_GATED`. Change the
`PROMOTABLE.txt` row to "gains one comment line per gated word; the owner
regenerates it".

**S5. The CI changes in §S1 do not match the workflow.**

- There is no "test job". The suites run under `cargo nextest run
  --profile ci` in the `check` job, where each test is time-bounded (F141).
  `cargo test` would bypass that bound (`.github/workflows/ci.yml:35-36`).
- No step runs clippy with `--features smysl`, so CLAUDE.md's denied
  `unwrap`, `expect` and `panic` lints never see the feature's code.
- Criterion 3 is not in CI.

*Fix:*

- Use `cargo nextest run -p bund2-stdlib --features smysl --profile ci`,
  and the same form for the example.
- Add `cargo clippy -p bund2-stdlib -p bund2-cli --all-targets --features smysl`.
- Gate criterion 3 in CI, or say it is run by hand.

**S6. Criterion 5's corpus, and what `smysl.parse` does with other
records.**

- Excluding `measured`, `@doc`, `@schema`, `@thread`, `@commit` and
  `@manifest` leaves about nine files. Most are deliberately malformed
  tutorial fixtures (`fixtures/tutorial/ch04-05-creating-formatting/*`),
  which "parse clean" removes. Perhaps two or three documents remain
  (`fixtures/sq/plans/supersession.smy`, `fixtures/library/same-as/anthology.smy`).
- §S4 does not say what `smysl.parse` does with a view, a schema
  declaration, a thread or a manifest.
- The two uid LISTs are compared in order, but the second pass's order is
  whatever order `smysl.write` produces.
- A label MAP's "id" in `smysl.append`'s answer is undefined.

*Fix:* name the fixtures. Specify what `smysl.parse` does with records that
have no §S2 form: SM03, or skip them with a `Warning`. Compare the LISTs as
sets. Define what `smysl.append` answers for a label.

**S7. A hand-built handle defeats R13.**

- The root is canonicalised only by `smysl.create` and `smysl.open`
  (lines 508-509), but §S2 allows hand-built handles (line 520). A handle
  with a non-canonical spelling gets a second mutex, and the VMs meet SM07
  between them.
- `canonicalize` fails on a path that does not exist yet, so `smysl.create`
  must create the library first. The order is unstated.

*Fix:* canonicalise the root in every word, before taking the mutex, and
state the order of `create`.

**S8. Criterion 15's third bullet has no stated mechanism.** "A write after
a caught panic" needs SMYSL to panic while the mutex is held. The only
known site is `library.rs:1370` (`expect("inserted above")`), which a test
cannot reach.

*Fix:* name a test-only probe, as `panic-probe` is for `test.panic`
(D220).

**S9. SM06's prefix.** §S8 prefixes every text but SM11's with `<W>: `.
The house `--noio` text is unprefixed — `bund SAVE.MODEL functions disabled
with --noio` (`bund_models.rs:125`) — and Bund2 matches it
(`crates/bund2-cli/tests/cli_ux.rs:958`).

*Fix:* exempt SM06 from the prefix, as SM11 is.

  that is the half-written case.

- **N10.** §S2's `captured` (a `Date`) and `smysl.measure`'s `value` (an

## Assumptions not stated

1. A library holds no view, or its view's profile is acceptable (S2).
2. Bund2 appends a `Record::Attestation` beside each unit and relation it
   writes (S1).
3. No `smysl.` word is reached with a non-canonical root (S7).
4. `kb.prove`'s engine is called with no `ask` slot, so askable predicates
   are E50 (B1).
5. SMYSL's `=`-pinned crates resolve against Bund2's lock. They do today:
   `unicode-segmentation` 1.13.3, `libm` 0.2.16 and `rand_chacha` 0.9.0. A
   Bund2 bump of any of them would break the feature build.
