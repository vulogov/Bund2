## Blocking

**B1 — `use` is not "Preserved exactly". A bundle's fetch obeys two proxy
variables the reference ignores, and evaluates what the proxy returns.**

The preservation table: "`use` | **Preserved exactly** — D76, under D54's
scheme set." §B7: "It keeps the defaults the reference leaves curl at", and
names three. §B3 lists the environment variables a bundle reads and says the
list is whole.

`fetch_uri` builds its agent from `ureq::Agent::config_builder()` and sets
redirects, status handling and the user agent
(`crates/bund2-stdlib/src/host.rs`, `fetch_uri`). It does not set a proxy, so
it has `ureq`'s default: `proxy: Proxy::try_from_env()` (`ureq` 3.4.0,
`src/config.rs:872`), which reads `ALL_PROXY`, `all_proxy`, `HTTPS_PROXY`,
`https_proxy`, `HTTP_PROXY`, `http_proxy` in that order (`src/proxy.rs:222-240`)
and `NO_PROXY`, `no_proxy` (`:541-549`). The reference sets no proxy option
either (`reference/Bund/src/stdlib/helpers/file_helper.rs:42-46`), so it has
libcurl's defaults. The two are not the same.

Measured 2026-10-09. The program is `"http://127.0.0.1:18720/lib.bund" use`,
with nothing listening on 18720 and a listener on 18721 that answers any
request with `40 2 + println`. Bund2 is a bundle of the program, run under
`env -i`; the oracle is `bund script --file` at `21b40b0`.

| the one variable set to `http://127.0.0.1:18721` | oracle | Bund2 bundle |
|---|---|---|
| none | fails | fails |
| `http_proxy` | `42` | `42` |
| **`HTTP_PROXY`** | **fails — ignored** | **`42`** |
| `ALL_PROXY`, `all_proxy` | `42` | `42` |
| **`HTTPS_PROXY`, `https_proxy`** | **fails — ignored for an `http://` URL** | **`42`** |
| `ALL_PROXY`, and `NO_PROXY=127.0.0.1` | fails — bypassed | fails — bypassed |
| what the listener receives | `GET http://127.0.0.1:18720/lib.bund HTTP/1.1` | `CONNECT 127.0.0.1:18720 HTTP/1.1`, then `GET /lib.bund HTTP/1.1` |

`bund2 script --file` with `HTTP_PROXY` set prints `42` too, so this is the
interpreter's behaviour and a bundle inherits it. A bundle whose target is
the unresolvable `bund2-review.invalid` also prints `42` under `HTTP_PROXY`:
the name is never resolved locally.

Three differences, then:

1. **`HTTP_PROXY`, upper case, is obeyed by Bund2 and not by the reference.**
2. **`HTTPS_PROXY` and `https_proxy` route an `http://` fetch in Bund2 and
   not in the reference.** D54 refuses `https://`, so in Bund2 these two
   variables exist only to redirect plain-HTTP fetches.
3. **The request differs on the wire.** The reference asks the proxy for the
   URL; Bund2 asks it for a tunnel. A proxy that grants one and refuses the
   other gives a different answer to the same program. Not measured against
   a real proxy.

**Why it blocks here and not only under D54.**

- The row says "Preserved exactly", and CLAUDE.md names this shape: "a
  required deviation filed as a non-deviation, so no criterion covers it."
  No golden can reach it — the corpus has no network — and no test sets a
  proxy variable.
- D54 lists its approved deviations: a string with no scheme, and `https://`.
  This is a third, and nobody approved it. The registers do not contain the
  word "proxy" in this sense (searched: `decisions.md`, `defects.md`,
  `open-questions.md`, this RFC, its ten reviews).
- **`use` evaluates what it fetches.** §B7 puts that risk on the person
  running the artefact, for the URL the program names. Here the environment
  decides who answers for that URL, and §B7 says "A bundle adds no check the
  interpreter does not have, and claims none" without saying the interpreter
  is looser than the reference on exactly this.
- The first difference has a known hazard, stated as reasoning and **not
  measured or grounded in this repository**: a host that runs a program as a
  CGI script sets `HTTP_<NAME>` from request headers, so a request header
  named `Proxy` arrives as `HTTP_PROXY`. A shipped artefact is the form of a
  Bund program most likely to be run that way. The reference is unaffected
  by the measurement above.
- §B3's list of variables has been corrected twice for being short — the
  seventh review, then the tenth — and each time said the list was whole. It
  is short by eight names.

**What it needs.** A ruling first, because either answer is the owner's:
a Bund2 defect (read what the reference reads and nothing else; the wire
form may not be configurable in `ureq`, and would then need its own
approval), or an approved deviation under D54 with the three differences
named. Then: the `use` row's disposition changed to say which; §B7's "the
defaults the reference leaves curl at" narrowed to the three it lists or
widened to cover proxying; the eight names in §B3's list; and a test with a
local listener, since no golden can hold it. `url` and `url.` share
`fetch_uri` and the finding, where `--noio` does not stub them.

## What the RFC assumes and does not state

1. **The HTTP client behaves as curl does wherever nobody looked.** Three
   defaults were compared; proxying was not (B1). Timeouts, connection reuse
   and header set were not compared here either.
2. **An environment variable a dependency reads is not one a bundle reads.**
   §B3's list was made from Bund2's own `env::var` calls, which are the ones
   a search of `crates/` finds: `main.rs`, `bund2-runtime`, `terminal.rs`,
   `logging.rs`, `report.rs`. `ureq`'s are in the registry.
3. **`aot` is enough to compile criterion 7's tests** (S1).
4. **A new restriction will come with a new container version** (S2).
5. **The sentinel cannot occur in what a build writes.** True, and unstated:
   its last eight bytes are not valid UTF-8, and the payload, the source
   path, the feature list and the SHA summary are all `&str`. So a program
   cannot carry a second validating header and make `locate` refuse its own
   artefact. Nothing pins it — no comment and no test — and a sentinel
   changed to printable bytes would lose it. Read, and checked by decoding
   the constant.
6. **No golden fails to parse.** `conform --bundles` treats a refused build
   as a failure (`xtask/src/conform/mod.rs`, `build_bundle`). Under D116 a
   program with a syntax error has a `script` run — a report and exit 0 —
   and no bundle, so the first such golden makes the two modes' numbers
   differ by construction and criterion 2 unmeetable as worded. All 145
   build today.
7. **`--inspect` reports what a header says, not what the runtime does.**
   The runtime is whatever binary did the building (D118), and an ad-hoc
   signature names nobody. §B3a offers the line to "someone deciding whether
   to trust what they were handed"; it tells them what an honest `bund2`
   wrote. Read, not measured.
8. **A path is cut between characters** (S3).
9. Carried from the tenth review and unchanged: the executable on disk is
   the one running when `build` copies it; an ad-hoc re-sign replaces
   whatever signature the builder carried.
10. Carried, and stated in the RFC: the compiler does not fold reads of the
