Revision 24's answers to review 2 mostly hold. R44–R46 are written into the design as ruled. The new problems are in how they are implemented, one call down:
- **A library-wide error is permanent** (B1). Step 6, and `clean` at staging, refuse whenever the library itself fails `check`. A dangling ground fails it (`SMY-E060`), and nothing appended can mend one. Phase 1's `smysl.unit` may write a dangling ground, and Phase 2's own `smysl.ingest.text` may commit one, since SMYSL commits each window without testing `has_errors`. After that, no `smysl.ingest` or `smysl.answer` on the library ever commits.
- **R45's cap names a function Bund2 cannot call** (S1). It also loses the first staging's `SMY-W036`s unless the RFC says to keep them (S2).
- **Step 5 checks uids that step 6 may then move** (S3). R46's label rule can therefore write the doubly-bound label that SM08 exists to prevent.
- **The probe's exact model match refuses working hosted configurations, and passes Ollama with no model installed** (S4).
- **R42's condition variable can lose a wakeup** (S5). Its mark has no owner, and criterion 27 needs a feature CI does not build.
- **Criterion 28's panic case cannot pass as written** (S6). SMYSL's lock text names `bund2 smysl.ingest.text`.

## Blocking

### B1. One error anywhere in a library refuses every later Phase 2 commit, permanently, and Phase 1 and the text ingest can both put one there

**Location.**
- §P4 step 6 (lines 2520-2523): "The check runs over the whole library … so an error anywhere in it … refuses the commit".
- The staged value's `clean` (line 2423).
- The Preservation row "The check at commit" (line 2979): "until it is mended".
- R40 A, as ruled.

**Evidence.**
- **`prepare_under` checks the whole overlay** (`smysl-ingest/src/stage.rs:224-230`), and `check` always runs the integrity pass (`smysl-check/src/lib.rs:308-310`).
  - That pass reports every reference in the store that points at no unit as `SMY-E060` (`smysl-check/src/passes/integrity.rs:12-13,62-65`; `smysl-graph/src/store/mod.rs:1019-1029`).
  - `E060` is an error (`smysl-core/src/diag.rs:198`). `Report::is_clean` is false when there is any error (`smysl-core/src/diag.rs:680-682`), so `Staged::has_errors` is true (`stage.rs:80-82`).
- **Phase 1 can write such a library.**
  - A `grounds` or `deps` STRING that is a uid is taken as given (RFC lines 1118-1121).
  - §S7 states that SMYSL "keeps a unit whose ground is absent, reporting it as `SMY-E060`" (lines 1602-1606), and Phase 1 does not refuse an unheld uid.
  - So one `smysl.unit` naming a ground the library does not hold leaves an `E060` in the library.
- **Phase 2's own text ingest can write one.**
  - `ingest_text` stages each window with `prepare_under` and commits `staged.records()` without testing `has_errors` (`smysl-ingest/src/text/run.rs:519-552`; the reply edges likewise, `:625-641`).
  - The local check that drives repair runs Shape, Closure, Granularity and Trust only (`smysl-ingest/src/repair.rs:566-571`), not Integrity. So a model ground that names a full-length uid the library does not hold passes repair, is reported at staging, and is committed.
- **No such error can be mended.**
  - A dangling ground can be filled only by appending a unit whose content hashes to the missing uid.
  - The library is append-only, and no Phase 1 word removes a record. Retracting the unit that holds the ground does not remove it: the record and its ground stay in the store.
  - So "until it is mended" (line 2979) has no mending path for `E060`. The same holds for every other library-wide error that only a later record could resolve.
- **The consequence.**
  - After one such record, every `smysl.ingest` and `smysl.answer` on the library stages `clean` false.
  - Every `smysl.commit` fails step 6 with `staged batch no longer checks clean`, whose diagnostics name a unit the program never staged.
  - Overriding `clean` (line 2441) does not help, because step 6 re-derives the errors.
  - Only `smysl.ingest.text` keeps working, because SMYSL commits regardless.
- **The record does not show this was weighed.** The second review raised the library-wide check as a cost (its N9), and revision 24 answered it with a Preservation row (line 4349). That row names only U17's `E033`, which R45 now prevents. It does not say that the remaining cases are permanent, or that Phase 1 and Phase 2's own words produce them.

**Needed.** A ruling, because R40 A and R45's rejection of option C bear on it:
- **(a)** Step 6 and `clean` judge only errors whose subject is a record of the batch, or a unit the batch's records reference. Library errors are reported as `Warning`s. This is R45 C's mechanism, applied to pre-existing errors rather than to the answer's own `E033`.
- **(b)** Step 6 compares against a check of the library alone, taken under the locks, and refuses only on errors the batch adds. The cost is a second full check per commit (Q54).
- **(c)** Keep the rule. Then state that the condition is permanent, name its sources (Phase 1's unheld uids, the text ingest's unchecked windows, any SMYSL writer), add a criterion that shows it, and consider having `smysl.unit` and `smysl.append` refuse an unheld uid. That last part is a Phase 1 change.

Whichever is chosen, the Preservation row at line 2979 and criterion 26's last bullet need to follow. Criterion 26's last bullet passes only because its fixture holds no other error.

**Needed.** Name `smysl_graph::relink::resettle` (`smysl-graph/src/relink.rs:74-112`) in §P4. M11's spike already checks that each step can be driven through the public API; add the cap to what it drives. The register's R45 text needs no edit: the ruling is about the operation, not the path.

### S2. Re-staging an answer loses the first staging's `SMY-W036`s, and the RFC does not say which store or which report it uses

**Location.**
- §P4's cap (lines 2455-2474): "then `prepare_under` again".
- The staged value's `diagnostics`, "the staging report's and the step's" (line 2424).
- `counts.lowered` (line 2428).
- Criterion 26's second bullet (lines 3560-3561): `diagnostics` hold `SMY-W036`.

**Evidence.**
- **The first staging already applied rule M.**
  - `answer` calls `prepare_under` (`answer.rs:282-283`). That call applies rule M (`stage.rs:192`) and writes each lowering as a `W036` into `staged.report` (`stage.rs:235-242`).
  - `report.lowered` counts those (`answer.rs:284-289`).
- **The second staging finds nothing more to lower.**
  - Bund2's second `prepare_under` receives units that rule M has already brought within their grounds. Capping then lowers a unit to at most `inferred`.
  - Since each unit is at or below its weakest ground, the min of each with `inferred` still satisfies rule M. The second run lowers nothing, and its `report` and `weakened` hold no `W036`.
  - If "the staging report" means the report of the batch that is staged, the `W036`s are lost, and criterion 26's second bullet fails.
- **The store is not named.** The answer's units ground on the dossier's question unit, which the library does not hold.
  - If the second `prepare_under` runs against the library rather than the in-memory copy that holds the dossier (§P6, R37), every unit grounded on the question is `SMY-E060` (B1's pass), and the staging is unclean.
- **The order differs from SMYSL's ingest, and changes the counts.**
  - SMYSL's ingest caps (rule T) before rule M (`repair.rs:166-174`, then `stage.rs:192`). Bund2 caps after.
  - For a `derived` unit over an `inferred` member, SMYSL's order gives one `E033` and no `W036`. Bund2's gives one `W036` and no `E033`.
  - The final uid is the same, but `counts.capped` counts only the units that still exceed `inferred` after rule M. Criterion 26's third bullet gets `capped` 1 only when the `derived` unit grounds on a member at `derived` or above, such as the `cited` question unit (`dossier/mod.rs:976-977`). It does not say so.

**Needed.**
- `diagnostics` is the step's (`AnswerReport::diagnostics`), then the first staging's `report`, then the caps' `E033`s, then the second staging's `report`.
- `counts.lowered` is `AnswerReport::lowered`.
- The second `prepare_under` runs against the same in-memory store `answer` was given.
- State the order (rule M, then cap) and what it does to the counts.
- Name the ground of criterion 26's `derived` unit.

### S3. Step 5's checks run on uids step 6 may move, so R46's label rule can write a doubly-bound label

**Location.** §P4 step 5 (lines 2489-2509), step 6 (lines 2510-2527), step 8 (lines 2528-2531).

**Evidence.**
- **Step 6 can move a uid.** `prepare_under` lowers a unit whose ground was absent at staging and is now held at a lower status (`monotone.rs:112-133`). It remaps the unit's labels and relations to the new uid (`stage.rs:194-211`).
- **Step 5 runs first, on the pre-move uids.** The label rule decides "one the library binds to another unit" there, and so does Phase 1's check that refuses an edge re-written with another weight or note.
- **A worked case.**
  1. The library holds `U`, labelled `c/x`. `U` grounds on `G`, which the library does not hold, so rule M left `U` unlowered.
  2. `G` is appended later, at a lower status.
  3. A re-ingest of the same document stages `U` again, with `c/x → U`.
  4. Step 5 keeps the binding, since the library binds `c/x` to `U` itself.
  5. Step 6 lowers `U` to `U'` and remaps the binding to `c/x → U'`.
  6. Step 8 writes it. The library now binds `c/x` to two units, which Phase 1's SM08 (line 1192) and R46's own row (line 2981) exist to prevent. Every Phase 1 word that resolves `c/x` is then SM08 `binds 2 units`.
- **Edges the same way.** A staged edge `U → V` with no weight, where the library holds `U' → V` with a weight, passes step 5 and becomes `U' → V` at step 6. That is the re-written edge Phase 1 refuses (line 1760).
- **Rule T** is not affected, since rule M only lowers.

**Needed.** Run the label rule and the edge re-write check on what step 6 gives back, after its remap, or run them both before and after. Add a criterion 25 case built on the worked case above.

### S5. R42's condition variable can lose a wakeup, the mark has no owner, and criterion 27 needs `smysl-panic-probe`

**Location.** §P6, "Who waits" (lines 2591-2611); M14; criterion 27's fourth and fifth bullets (lines 3586-3591); §P2's CI step (line 2253).

**Evidence.**
- **Today a writer blocks on a per-root `Mutex`.** `serialise` takes the root's `&'static Mutex<()>` from the table under the table's lock, releases the table, and then blocks on the root mutex (`write.rs:56-69`). A `Serial` is only that mutex's guard (`:50-52`).
- **A lost wakeup.** R42 A has a writer try the root mutex and, while it is held, wait on a condition variable of the table, "signalled when a root's mutex is released".
  - Waiting requires the table's lock, so the try must happen under it.
  - But the root mutex is released by dropping a `MutexGuard`, which does not touch the table. If the releasing thread drops its guard and notifies without first taking the table's lock, the notification can come between the waiter's failed try and its `wait`, and is lost.
  - The waiter then sleeps until some unrelated signal, possibly for good.
  - The text does not say that a release takes the table's lock. A simpler shape is a "held" flag per root in the table, guarded by the table's mutex and its condition variable, instead of a second mutex.
- **The mark needs an owner.** "The text ingest sets the mark before it takes the mutex" (line 2607). It then waits like any writer, and each time it wakes it "tests the mark again" (line 2606).
  - If the mark is a flag, the run finds its own mark and refuses itself with SM07.
  - The mark must name its run, by a token or the thread, and only that run's guard may clear it.
  - A second text ingest on the same root must then be SM07 without touching the first run's mark.
- **Criterion 27 needs Phase 1's pause.** Its fifth bullet needs an earlier write that holds the root's mutex and is paused, with a writer queued behind it before the run sets the mark.
  - `bund2-script`'s pause pauses only inside a model call, and the only Phase 2 word that writes while it calls a model is the text ingest, which sets the mark first.
  - The pause that holds the mutex is Phase 1's, at `write.rs:262`, after `serialise` (`:297`), and it is compiled only under `smysl-panic-probe` (RFC lines 2012-2025).
  - §P2's CI step runs the Phase 2 suites under `smysl-model,smysl-model-probe` (line 2253), so the case is not built.

**Needed.**
- State that releasing a root takes the table's lock before signalling. Or replace the per-root mutex with a flag the table guards.
- Give the mark an owner.
- Run the Phase 2 suites with `smysl-panic-probe` as well, or give `bund2-script` a pause that a non-model write can reach.

## Notes

**N1. The "staged dossier changed under the library" refusal cannot fire for a genuine value, and `Staged::weakened` is the wrong signal for a hand-built one.**
- **Why it cannot fire.** A dossier's `Thread` and `View` name only:
  - the question unit, `cited` with a source and no grounds (`dossier/mod.rs:976-990`);
  - saved-query units, `cited` with no grounds (`saved.rs:409-418`), named in `Gap` steps and `View::roots` (`dossier/mod.rs:1044-1070,1129-1131`);
  - library units, which are not in the batch.

  Rule M never moves any of these.
- **Why `weakened` is the wrong signal.** It lists only the units rule M lowered (`monotone.rs:126-132`). A unit that moved only because its ground moved is in `Applied::remap` (`:52-54,136-139`), which `Staged` does not expose.
- `prepare_under` keeps "same units, same order" (`monotone.rs:50`; `stage.rs:245,260-261`), so Bund2 can compute the full remap by position.
- Uids can be read: `Step::unit` and `View::roots` are public fields (`smysl-core/src/types/thread.rs:374-377`; `view.rs:222-225`).

**N2. `View::threads` and the thread's other fields are not covered.**
- Step 5 checks "every uid" a `Thread` or `View` names. `View::threads` names `ThreadId`s (`view.rs:225`), which no check covers.
- A hand-edited `Thread`'s `owner`, `ts`, `gist` and notes (`thread.rs:423-432`) are written as given. A thread is a last-writer-wins register keyed by `(id, owner)` (`:462-465`).
- "What a commit takes as given" (lines 2436-2446, 2978) lists four fields. It should list these too.

**N3. A program's label in a hand-built staged value gets R46's drop, not SM08.** R46's premise, "every label binding in a staged value is the model's" (line 2499), holds for a value a word produced:
- an answer's labels are the model's (`answer.rs:270-274`);
- a dossier carries no `LabelBinding` (`dossier/mod.rs:1147-1148`; `saved.rs:345-418` returns a unit and edges).

But R40 says a staged value may be built or edited by hand. A program that adds a binding to `records` gets a `Warning` and an unlabelled unit, not SM08. So the Preservation row "A label a program binds keeps SM08" (line 2981) is true only of labels bound outside `smysl.commit`. Say so.

**N4. The cap's `SMY-E033` is an error code reported as a `Warning`.**
- `E033`'s severity is `Error` (`smysl-core/src/diag.rs:223`).
- The staged value's `diagnostics` will then hold an error-coded diagnostic while `clean` is true. That matches SMYSL's ingest, whose rule T `E033`s go to the run's diagnostics and not to `staged.report` (`repair.rs:171-172`; `lib.rs:844,908-919`).
- Under D36 a `Warning` gets one line on stderr. State that the severity shown is Bund2's, and that a program should read `clean`, not scan the codes.
- `ceiling::apply` can also fail to rebuild. It then returns the uncapped unit with a subject-less `E033` (`ceiling.rs:83-92`), and step 5 later refuses the commit. This is unreachable for answers, because `admit` requires grounds (`answer.rs:127-131`) and `inferred` needs only grounds (`ceiling.rs:129`). One sentence would close it.

**N5. M11's spike: the first commit's `E033` stays in its library.**
- The spike commits "as SMYSL stages it and then capped", and checks "the library after each" (lines 2906-2910).
- The trust pass reads every unit (`trust.rs:23-50`), so the first commit's `E033` is still there after the second.
- Step 5 also refuses the uncapped answer, so the first commit must go through SMYSL's API directly.
- Use two libraries, and name the write path.

**N6. The probe's place in each word's sequence is not stated.**
- SMYSL refuses some configuration before egress: a prompt override, a granularity, two passes above temperature 0 (`lib.rs:729-767`; `text/run.rs:205-225`).
- If Bund2 probes first, a hosted probe sends a key-bearing request before a refusal that SMYSL makes with nothing sent, and criterion 22's SM13 cases would count a probe.
- For `smysl.ingest.text`, the RFC does not say whether the probe comes before or after the mark, the mutex and the locks.
- State the order. Probing after Bund2's own `opts` checks and before the mark seems right.

**N7. Criterion 27's "second call" is still the first window.**
- `Passes::TEXT` makes two first calls per window (`consensus.rs:44,47-51`), so the script's second call is window 1's second pass.
- Whether the failed append changes a log, and so whether the word answers "left locked", then depends on which shards window 1's batch writes, and on whether windows 2 and 3 fail on the same shard.
- Name the call, the fixture and its shards, as Phase 1's criterion 15 names a two-shard batch.

**N8. Criterion 26's fixture is under-determined.** "An `inferred` unit grounded on a member" (line 3558) must ground on a member at `inferred` or above, or it is lowered too and `lowered` is 2. The `derived` case needs a member at `derived` or above (S2). Name them, for example the `cited` question unit.

**N9. `opts.path` and `auto`.**
- The configuration's `ingest.path` may be `auto`, which means no override (`config.rs:95-96`; `smysl:src/main.rs:11252-11259`).
- `IngestPath::parse` refuses `auto` (`lib.rs:298-304`).
- The `opts` table (line 2375) says `surface` or `json-ast`. Say that `opts.path` `auto` is SM03, or that it means "no override", as in the file.

**N10. Criterion 22's prompt case.** "The script receives the text of `<project>/prompts/p.hjson`" (lines 3500-3502). The file is an HJSON override, and what reaches the script is the system or user text it sets (`prompt.rs:897-935`). Say "receives the system text that override sets".

**N11. Criterion 25 still has no `step` case.**
- Revision 24 takes `step` as given (line 2437).
