# RFC-0014 review: revision 22, the Phase 2 amendment, 2026-11-06

**This review covers revision 22's Phase 2 amendment only.** Its scope is:
- the header bullet "Revision 22 (2026-11-06), Draft: Phase 2";
- §S10's "A model" bullet and §S12;
- "Design — Phase 2" (§P1–§P10);
- the Phase 2 implementation plan (M11–M15);
- the Preservation rows after the `q` row;
- the three Alternatives bullets after "Re-implementing SMYSL's model in Bund";
- criteria 19–30;
- Q59, both in the RFC and in `docs/registers/open-questions.md`;
- "Rulings asked for (D248)" and D248 in `docs/registers/decisions.md`.

Phase 1 is Accepted and built. It was read only as context, to check that Phase 2 is consistent with it: §S2, §S4 and R15, §S5 and R17, §S8, §S9, R13, R22 and R25.

Nothing was edited apart from this file. The only command run was `cargo xtask cite`: 5250 citations resolve, and none of its advisories is in RFC-0014. That tool does not read SMYSL citations. Each SMYSL citation below was opened by hand in a clone at 4f5ecb9, and the `ureq` 2.12.1 manifest was opened from the cargo registry. Calls were followed one level deeper than the cited function wherever the RFC says what a function does.

**Verdict: Not ready. 5 blocking, 9 should-fix, 14 notes.**

The citations are accurate line for line; almost every one says what the RFC says. The problems are in what the cited functions *do*, one call further down:

- **Rule I.** `Ingestor::ingest` and `ingest_text` turn a provider error into a degraded prose unit. They do not return it (B3).
- **The staged batch.** `prepare_under` attests every unit with one clock and `Op::Imported`. That changes R15 in four ways that no R30–R38 point names (B1).
- **`smysl.commit`.** It writes whatever records a plain MAP carries, so it bypasses Phase 1's write rules (B2).
- **In-process writers.** R13's mutex makes another thread in the same process wait for a text ingest; it does not get SM07. Criterion 27 asserts SM07 (B4).
- **Licences.** The hosted mappers bring in a licence `deny.toml` does not allow, so criterion 20 cannot pass without a licence ruling (B5).

## Blocking

### B1. Every Phase 2 write changes R15's attestation rules, and none of R30–R38 says so

**Location.**
- §P7 (lines 2416-2436): "the clock is §S4's, `Hlc::now` advanced from this agent's newest clock in the library".
- R35 A (lines 3359ff and D248): "§S4's clock".
- §P6's "The answer's dossier" and R37 A.
- Criterion 24's third bullet.

**Evidence.** Each step builds its batch through `stage::prepare_under`. That function attests every kept unit and every relation with one `Attest` (`smysl-ingest/src/stage.rs:249-258`). `Attest::for_unit` writes `Op::Imported`, with the same `now` for every record (`stage.rs:339-357`). The `now` is the caller's, "supplied, never read" (`lib.rs:362-363`). R15 (D244), as §S4 states it at lines 1230-1268, says something different:

1. **Operation `Authored`.** Staging writes `Imported`. §S4 notes that `Imported` is the one operation that may raise a `Computed` ceiling to `measured` (`smysl-core/src/types/provenance.rs:326-331`, read through §S4).
2. **The clock.** §S4 takes it from the agent's newest clock *in the library as re-opened under the locks*, and each attestation advances from the one before it. Phase 2 sets one clock for the whole batch, and for `smysl.ingest.text` one for every window of the run (`text/run.rs:325-331`). For `smysl.ingest` and `smysl.answer` it is computed at staging, from an open taken without locks (§P6). A staged value committed after another commit by the same agent writes clocks that go backwards. §S4 promises they never do ("So an agent's clocks in a library never go backwards").
3. **"Already attested".** §S4 writes an attestation "only if this agent has not attested that uid already". `prepare_under` attests every unit, held or not. `encode_by_shard` drops only byte-identical records (`smysl-text/src/shards.rs:520`), and a new clock makes the record different. `ingest_text` commits inside SMYSL (`text/run.rs:546`), so Bund2 cannot filter its batches at all.
4. **"Every unit and relation Bund2 writes is followed by one attestation."** Under R37 A, `smysl.commit` writes the dossier's records unattested: its question unit, its saved-query units and their edges (`smysl-query/src/dossier/mod.rs:896-991`). That is how SMYSL's `ask --save` writes them.

R35 changes the rung, and the RFC says so. The four changes above are not named anywhere, and R35 A asserts the opposite of item 2.

**Needed.** Either re-attest under Bund2's rules, or rule the changes:
- (a) `smysl.commit` re-derives the attestations under the locks: it drops staged `Attestation` records and writes §S4's own, which is possible for `ingest` and `answer` because `records` is decoded anyway. For `smysl.ingest.text`, state the departure as a ruling.
- (b) Add an R39 that amends R15 for model output: `Imported`, one clock per step, no "already attested" filter, and the dossier unattested.

Either way, correct R35 A's "§S4's clock", and add a Preservation row "R15, attestation of model output".

### B2. `smysl.commit` writes any records a plain MAP carries, bypassing Phase 1's write rules

**Location.** §P4, "A staged value is a MAP" and "`smysl.commit` checks, then writes" (lines 2295-2340); criterion 25.

**Evidence.**
- The staged value "is plain data. It saves and travels as any MAP does" (line 2311). `records` is a BIN.
- `smysl.commit` checks five things: the root, `clean`, that the BIN decodes, that each record's kind is one the step makes, and that no relation is `retracts`. Then it appends the decoded records as they are.
- Nothing binds `records` to what a step produced. A program can edit a staged value, or write one, and `smysl.commit` will append:
  - an attestation by any agent, at any rung, for any uid;
  - a unit of any status, `measured` included. R15 refuses `measured` with SM03 (§S4, line 1262);
  - a relation of a kind `RelKind::parse` refuses. That is SM05 in Phase 1 (R24; §S8);
  - an `x.text` record without D247's declaration;
  - a label binding that SM08 would refuse.
- Step 4 limits the kinds of record, not their content.
- `clean` is a BOOL in the same MAP, so it can be forged as well.

R21 makes agent ids advisory, but no Phase 1 word lets a program write another agent's attestation or a `measured` unit. This quietly widens R15, R23's neighbours (R24, SM05) and D247.

**Needed.** Choose one, and rule it:
- (a) `smysl.commit` re-validates every decoded record with Phase 1's writing rules, as `smysl.append` would: SM05, SM08, the `measured` refusal, D247. It also re-derives the attestations (B1 (a)).
- (b) The staged value carries a digest of `records` keyed by a per-process secret, so that only an unmodified value from this process commits. Then state that one saved and loaded in another process does not, and change criterion 24's last bullet.
- (c) An R-point saying that `smysl.commit` is a raw writer, with a Preservation row naming what it bypasses.

### B3. A provider error is not a refusal for `smysl.ingest` or `smysl.ingest.text`. Rule I degrades it, and the text ingest commits and journals the degraded windows

**Location.**
- §P9 (lines 2454-2465): SM13 for "any `ProviderError` a step returns".
- Criterion 28 (line 3156): "The script returning each of `Unreachable`, `Unauthorized`, `Truncated` and `Config` makes each word SM13".
- §P6's resume claim (lines 2380-2383).

**Evidence.**
- `ingest` and `ingest_text` both call `one_call` (`smysl-ingest/src/lib.rs:839`; `text/run.rs:416`).
- When `provider.complete` fails, `one_call` does not return the error. It degrades the span to an opaque prose unit, `repair::degrade`, at a status no higher than `speculative`, holding the span's text as its body (`smysl-ingest/src/repair.rs:341-361`). It also counts `degraded: 1` and reports `SMY-W304` (`lib.rs:988-1022`).
- The only `ProviderError`s these two steps *return* are the ones raised before the loop: `for_task`'s `Config` and `OfflineViolation`, and the option refusals (`lib.rs:731-768`; `text/run.rs:208-227`).
- `answer` alone propagates the error (`answer.rs:228`, `?`).

So, with the script returning `Unreachable` (or with Ollama simply not running):
- `smysl.ingest` answers a staged value whose units are the input's chunks as prose. `clean` is true, because W304 is a warning. `smysl.commit` would write them.
- `smysl.ingest.text` commits every window as degraded prose (`text/run.rs:519-546`) and **journals each one as done** (`:565-585`). The next run skips them all (`:356-358`), and only `reextract` recovers. That is SMYSL's rule I, but the RFC presents the journal only as a resume property.

Criterion 28 therefore cannot pass for two of its three words.

**Needed.**
- State rule I in §P9, citing `lib.rs:988-1022` and `repair.rs:341-361`.
- Decide what the words do, possibly as an R-point. Options:
  - pass the outcome through: the staged value's `counts.degraded`, plus a `Warning`;
  - refuse with SM13 when every chunk or window degraded on a provider error;
  - for `smysl.ingest.text`, refuse before journalling, which needs U13-like help from SMYSL, because the journal is written inside `ingest_text`.
- Rewrite criterion 28 per word. For `smysl.answer`, keep SM13. For the other two, assert `degraded`, the W304 diagnostics and, for the text ingest, the journal's state.

### B4. A writer in the same process waits for a text ingest; it does not see SM07. Criterion 27 asserts SM07

**Location.** §P6 (line 2375): "Other writers then see SM07 for as long as the model runs". Criterion 27's fourth bullet (line 3143ff): "`smysl.unit` on the same library is SM07 from another thread". The Preservation row "`ingest --text`'s locks".

**Evidence.**
- R13 A (D244; §S9 "Threads", lines 1960-1975) serialises writers *in one process* through a process-wide mutex keyed by root, "before the file locks are taken". It does so precisely so that a second VM does **not** get SM07.
- §P6 has `smysl.ingest.text` hold that mutex for the whole call.
- Another thread's `smysl.unit` therefore blocks on the mutex until the run ends, and then proceeds. Only another *process* sees SM07.
- With a paused probe, criterion 27's test would hang until the probe's own timeout.

There is also a consequence the RFC does not state. A model run takes minutes, and every VM in the process that writes that library is suspended for all of it, with no way to time out. SM07 and `?try` (§S9) do not help, because the waiting writer never sees SM07.

**Needed.**
- Correct §P6 and the Preservation row: other processes get SM07, and other threads in this process wait.
- Change criterion 27's bullet: either a write from another thread completes only after the run, or a second *process* gets SM07.
- Optionally, add an R-point: `smysl.ingest.text` takes the mutex with `try_lock`, and other threads get SM07 while it runs. That would amend R13 for this word.

### B5. Criterion 20 needs a licence `deny.toml` does not allow, and no ruling covers it

**Location.** Criterion 20 (line 3094); §P2's CI bullet; R36; the Preservation rows.

**Evidence.**
- The hosted mappers enable `ureq/tls` (`smysl-provider/Cargo.toml:26`).
- In `ureq` 2.12.1, `tls` is `dep:webpki-roots`, `dep:rustls` and `dep:rustls-pki-types` (`ureq-2.12.1/Cargo.toml:237-241`).
- `webpki-roots` 0.26.11 is in SMYSL's lock (`smysl:Cargo.lock:2785-2788`). It re-exports 1.0.9 (`:2794-2797`), and both declare `license = "CDLA-Permissive-2.0"`, read from each crate's `Cargo.toml` in the registry.
- `deny.toml`'s `[licenses] allow` list does not include it.
- `ring` is `Apache-2.0 AND ISC`, both of which are allowed.

So `cargo deny check` with every mapper fails on licences. Past licence allowances were owner rulings: D152 for `cfonts` and `sys_metrics`, and D216 for GPL, as the `deny.toml` comments record.

**Needed.**
- Name the licence in §P2.
- Either add it to R36 (A allows it in `deny.toml` with its reason; B keeps the hosted mappers out until it is ruled), or raise a separate R-point.
- Add a Preservation row for `deny.toml`.
- Restate criterion 20 as passing after that entry.

## Should fix

### S1. `smysl.ingest.text`'s report MAP has no defined keys

**Location.** §P4's table, the `smysl.ingest.text` row ("answers its report"); criterion 27 ("a report with 3 windows and 0 skipped").

**Evidence.** The staged value has a table of keys. The report has none. `TextReport` has about twenty fields (`text/run.rs:96-156`), among them `windows`, `skipped`, `calls`, `units`, `entities`, `replies`, `spanned`, `spanless`, `degraded`, `repaired`, `retries`, `pivoted`, `agreement`, `verdicts`, `usage`, `recipe`, `family`, `path` and `diagnostics`.

**Needed.** A table, as for the staged value, giving each key's type. Criterion 27 can then name keys.

### S2. SMYSL's configuration file also sets `ingest.path`, `ingest.temperature` and `ingest.prompt`; §P3 adopts the file and is silent on them

**Location.** §P3, "so that a library has one routing table whichever tool calls the model" (line 2206ff). §P4's `temperature` default `0.0` (line 2273). The Preservation row "SMYSL's journal" (line 2616), which says a Bund2 run and an SMYSL run "resume each other when their recipes agree".

**Evidence.**
- `Config` carries `ingest_prompt`, `ingest_path`, `ingest_temperature` and `ask_log` (`smysl-provider/src/config.rs:89-117`).
- SMYSL's `ingest` applies the path and the temperature from the configuration when no flag is given (`smysl:src/main.rs:11244-11303`).
- Both of SMYSL's ingests apply `ingest.prompt`, resolved beside the configuration file (`:10703-10726`, `:10906-10913`, `:11317-11324`).
- The prompt and the path enter the recipe (`text/run.rs:297-320`; `lib.rs:796-807`).
- So under one configuration, Bund2 and SMYSL extract differently and record different recipes, and their journals do not resume each other.

**Needed.** Say for each key whether Bund2 honours it. If it honours `ingest.prompt`, a word reads a second file, relative to the configuration: that needs a Preservation row and a `--noio` note. If it does not, qualify the "one routing table" sentence and the journal row.

### S3. `bund2-script` can be neither configured through the file nor non-local, as §P3 and §P8 stand; criteria 22 and 23 need both

**Location.** §P3, "The registry is built as SMYSL's `load_registry_at` builds it … each configured provider through `build_provider`" (line 2226). §P8, "reports itself local, so `offline` admits it" (line 2446). Criteria 22 and 23.

**Evidence.**
- `build` refuses any kind that no compiled mapper handles, returning "not compiled into this build" (`smysl-provider/src/map/mod.rs:123-142`). A `kind: "bund2-script"` entry is therefore skipped with a Warning, and criterion 22's first case never reaches it.
- Criterion 23 needs a provider at `192.0.2.1` that `offline` refuses. The Phase 2 suites run under `smysl-model,smysl-model-probe` with no mapper (§P2). The only provider available is `bund2-script`, and §P8 makes it always local.
- `admit` reads `caps().offline` (`registry.rs:108`), and the mappers derive it from `ProviderConfig::is_local()` (`config.rs:54-80`; `ollama.rs:263`).

**Needed.**
- In §P3: under the probe feature, Bund2's registry builder handles the kind `bund2-script` itself, before `build_provider`.
- In §P8: `bund2-script` reports `offline = ProviderConfig::is_local()` of its configured endpoint, as the mappers do.

### S4. `smysl.answer` has no defined result when no answer survives

**Location.** §P4's `smysl.answer` row; §P6, "The answer's dossier"; R37 A.

**Evidence.** `AnswerReport::staged` is `None` in two cases (`answer.rs:65-66`):
- the answer does not parse, which gives `SMY-E001` and an `Ok` return (`:232-240`);
- every unit is dropped (`:265-267`).

SMYSL then stages nothing (`smysl:src/main.rs:9607-9610`). The RFC does not say whether `smysl.answer` then answers a staged value holding only the dossier's records, with `clean` true. Such a value would make `smysl.commit` save a dossier with no answer, which R37 A's "an answer is never written without the units it grounds on" does not cover, and which goes beyond R37's amendment of R17.

**Needed.** A rule. For example, the word answers a staged value with empty `records` and `units`, `clean` false and the diagnostics, so that `smysl.commit` refuses it. Add a case to criterion 26.

### S5. A staged value can be committed long after staging, but rule M and `clean` were decided against the library as it was

**Location.** §P4, "What the library gained between staging and commit is not looked at" and its SMYSL precedent (lines 2336-2340); criterion 24's last bullet, which commits after `save.model` and `load.model`.

**Evidence.**
- Rule M weakens each unit to its weakest ground *against the store at staging* (`stage.rs:188-192,213-230`), and `clean` is that check's verdict.
- A ground retracted, or superseded, between staging and commit leaves a unit committed above what its grounds now support.
- The cited precedent (`smysl:src/main.rs:4616-4654`) is SMYSL's immediate `--yes` path. SMYSL's deferred commit, `merge --staged`, does go through `merge` (`:4187-4290`). See "Citations checked".

**Needed.**
- Correct the precedent.
- Either have `smysl.commit` re-run `stage::prepare_under`'s check (rule M and `check`) over the decoded units against the re-opened library, refusing SM03 when it is no longer clean; or state the staleness in a Preservation row with an R-point.
- B1 (a) and B2 (a) already decode and revalidate, so the same pass can do this.

### S6. Detecting a failed commit inside `ingest_text` by `SMY-E001` misfires on a model's empty answer

**Location.** §P6, "A failed commit inside the run is a diagnostic" (line 2383ff).

**Evidence.**
- The commit failures are `SMY-E001`s with the messages "the batch could not be committed: …" and "the reply edges could not be committed: …" (`text/run.rs:546-551,637-640`).
- `one_call` also pushes `SMY-E001`, "attempt N of M: the answer contained no units", into the same diagnostics whenever the model answers nothing (`lib.rs:1092-1105,1155-1166`).
- If Bund2 keys on the code, it applies R25 after a model failure. Because earlier windows wrote, the locks are kept and the word answers SM02 "left locked", although nothing failed to write.

**Needed.** State that Bund2 matches the two message prefixes, cite both sites, and note that this is why U13 matters. Add a criterion 27 case: the script returns an empty answer for one window, and the word does not leave the library locked.

### S7. `opts` reaches `IngestOptions` in ways that change behaviour and recipe, and the mapping is not stated

**Location.** §P4's `opts` table (lines 2266-2283).

**Evidence.**
- `granularity`: `with_granularity` sets `granularity_named` (`lib.rs:532-536`). `ingest` applies the profile only when the granularity is named (`:767`). If Bund2 always passes the default `standard`, its document ingest checks under a profile that SMYSL's default run does not use.
- `source`: `IngestOptions::source` is a pair with a `SourcePolicy` (`lib.rs:416-420`). SMYSL's CLI uses `FillMissing` (`smysl:src/main.rs:11311-11316`). The RFC names no policy, and the policy enters the recipe (`lib.rs:808-811`).
- `level`: an invalid level (`Level::new` returning `None`; `smysl:src/main.rs:10819-10826`) is not mapped to a code.

**Needed.**
- Say that `granularity` is passed only when given.
- Name the `SourcePolicy`.
- Map an invalid `level` to SM03 or SM05.

### S8. The provider thread is one per process: every model call in the process queues on it, and a server's `Retry-After` can block a VM without limit

**Location.** The Preservation row "Process-wide state | One thread more" (line 2614); §P1, "nothing in the VM changes".

**Evidence.**
- `runtime::run` sends each job to a single thread, created once, and waits (`smysl-provider/src/runtime.rs:27-48,54-63`).
- Two VMs calling model words concurrently therefore run one after the other.
- `post_json` sleeps for a 429, 503 or 529 response's `Retry-After`, which is parsed as plain seconds with no cap (`smysl-provider/src/http.rs:110-111,160-177`), and it may do so twice (`MAX_ATTEMPTS`).
- Each attempt has the configured `timeout_secs`, 120 by default (`config.rs:50`).

**Needed.** Add to the row that model calls are serialised process-wide, and that one word may block for the timeout times three plus any `Retry-After`. Consider U15: a cap on `Retry-After`.

### S9. Preservation does not list several host effects Phase 2 introduces

**Location.** The Preservation rows after `q` (lines 2603-2616).

**Missing:**
- **Files read outside the library.** The configuration is read from the *parent* of the library's root (§P3). No Phase 1 word reads outside `root`.
- **A subprocess per call.** The hosted mappers resolve the key on every `complete` (`map/anthropic.rs:68`, through `headers()` at `:292`; likewise `openai.rs:75`, `gemini.rs:68` and `deepseek.rs:63`). So `api_key_cmd` runs once per model call, which for a text ingest means per window and per pass. The row "Running a program" says only "when that provider is used".
- **Environment variables read**: `api_key_env` (`auth.rs:53-62`).
- **Proxies.** `ureq` 2's `AgentBuilder::new()` (`smysl-provider/src/http.rs:137-140`) reads no proxy variable unless `ureq`'s `proxy-from-env` feature is on (`ureq-2.12.1/Cargo.toml:234`), and SMYSL does not turn it on. Bund2's own `url` honours `http_proxy` (D124). A program behind a proxy reaches its model directly, or fails. This is not a deviation, since there is no reference, but it should be stated.
- **The `deny.toml` licence entry** (B5), **`PROMOTABLE.txt`** (four more `# feature-gated:` lines, regenerated by the owner under D72), **the editor syntax file**, **bundles** (`features_built_in` gains six names), and **CI** (the new steps, the probe suites, and the fact that `--all-features` now needs a C compiler for the hosted mappers). These are covered by Phase 1's rows only in so far as those name `smysl`; Phase 2 should say they extend to the new features.
- **Library-root files.** The text ingest's `journal.cbor` is in the row. Also state that Bund2 writes no `.smysl/staged.smy` or `staged.cbor`, because the staged value replaces them (`stage.rs:34,42`).

## Notes

**N1.** §P3 says "`answer` and `ingest_text` take the routed provider alone through `for_task`", which suggests that `ingest` differs. It does not: `ingest` also calls `for_task` (`smysl-ingest/src/lib.rs:768`) and never `Registry::complete`. Say "all three".

**N2.** §P3 says SMYSL resolves "the variable first, then the command". In fact the command runs only when no `api_key_env` is configured. A configured variable that is unset is a `Config` error, with no fall-through (`map/auth.rs:53-67`).

**N3.** §P2's "`ring` compiles C and assembly" has no citation. `smysl:Cargo.lock:1850-1861` shows `ring` 0.17.14 depending on `cc`.

**N4.** §P2 cites SMYSL's `Cargo.lock` for the `rustls` version. Bund2 resolves its own lock, so the versions Bund2 links are whatever `Cargo.lock` here resolves after M11. Criterion 21 checks the build, which is what matters; the RFC should not imply SMYSL's lock binds Bund2.

**N5.** `from_cbor_seq` treats a truncated tail as no error and returns the offset where it stopped (`smysl-core/src/cbor/envelope.rs:2010-2028`). "Decodes whole" (§P4, step 3) must compare that offset with the BIN's length. Say so.

**N6.** §P2 puts the `cargo deny` run "in the `check` job". `deny` is a job of its own using `cargo-deny-action` (`.github/workflows/ci.yml`, job `deny`). Also, `features_built_in` is `crates/bund2-cli/src/main.rs:41`; the constants are in `bund2-stdlib`, as §P2 says.

**N7.** Q59 can be answered by reading, before the spike:
- `Staged::records` emits `SchemaDecl`, `Unit`, `LabelBinding`, `Relation`, `proposals` and `Attestation` (`stage.rs:89-111`), and `proposals` is empty for all three steps (`stage.rs:268`).
- Document ingest and the answer stage no schema (`lib.rs:914`; `answer.rs:283`).
- The text ingest stages `x.text/v1` (`text/run.rs:514-518`).
- A dossier's records are `Unit`, `Relation`, `Thread` and `View` (`smysl-query/src/dossier/mod.rs:896-1162`), plus the `x.query/v1` `SchemaDecl` (`smysl:src/main.rs:6671-6673`).

Keep the spike as confirmation, but state the list.

**N8.** `opts.config`: a relative path is resolved against what? Phase 1 refuses relative roots (SM00). Say that the path is absolute, or relative to the working directory.

**N9.** `smysl.ingest.text` over a text whose reader this build lacks is not covered. R12 gives Bund2 only `txt/1` and `md/1`, and SMYSL may have added the text with another reader. `pane_of` then fails with a diagnostic (`text/run.rs:244-248`), giving zero windows, and Bund2's default level fails like `default_level` does (`smysl:src/main.rs:11138-11143`). Name the code.

**N10.** `leaf_level` is public (`smysl-ingest/src/text/window.rs:201`). Bund2's "own" default level is the dozen lines of `default_level` that resolve the manifest's first part (`smysl:src/main.rs:11108-11151`), and M14's test that the two agree reduces to calling `leaf_level`. Worth saying, so the work is not over-scoped.

**N11.** A panic on the provider thread: §P6's path, where the caller panics at `rx.recv().expect(…)` and the thread dies, happens only when the provider's work runs through `smysl_provider::runtime::run`. The module is public (`lib.rs:30-31`). If `bund2-script` panics on the VM's thread instead, criterion 28's panic case tests D49 but not the U12 behaviour that the Preservation row describes. Say which one `bund2-script` does. If it uses `runtime::run`, one panicking test poisons every later model call in its process, which nextest's process-per-test model tolerates and `cargo test` does not.

**N12.** Criterion 27's "one shard's log made unwritable after the first window" needs an action between windows. The script can take it on its second call; say so. The shard a window's records go to must exist by then.

**N13.** `Ingestor::answer` takes a concrete `&Store` (`answer.rs:188`), and SMYSL clones the corpus's store to append the dossier (`smysl:src/main.rs:6677`). So `smysl.answer` copies the library's whole store in memory on every call. That bears on Q54.

**N14.** An `ollama`-kind provider whose endpoint is `https://` fails as `Unreachable` in a `smysl-ollama`-only build, because there is no TLS (`smysl-provider/Cargo.toml:29`, `ureq` without default features). Worth one line in M15's README.
