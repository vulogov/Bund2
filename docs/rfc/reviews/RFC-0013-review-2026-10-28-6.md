## Should-fix

### S1. Criterion 4 never meets Tier 1 where it is placed, so revision 7's reason does not apply

The acceptance criteria open by saying that each criterion is a test in
`crates/bund2-stdlib` "unless placed otherwise", and criterion 4 is not
placed otherwise. A tier exists only when `bund2-runtime` installs one,
under its `jit` feature (`Runtime`'s constructor). `bund2-stdlib` has no
such feature and does not depend on `bund2-jit`. So in its own tests the
`Interp` has no tier, every answer's `lambda` runs at Tier 0, and the
sample points don't matter.

That cuts both ways:

- **What revision 7 changed is harmless but explained wrongly.** The
  criterion says "under `--features jit` both come from the same compiled
  caller", but no compiled caller exists where the test runs. The fifth
  review's S1, which prompted the change, was marked PLAUSIBLE and rested
  on the same oversight.
- **The claim that matters is untested at Tier 1.** "No Rust depth across
  answers" should hold when `lambda` is compiled too. Nothing checks that,
  because no Tier 1 run reaches the criterion.

**Fix:** place criterion 4 in a `bund2-runtime` test, which the suite runs
with and without `--features jit`. Keep the late samples, and give the
real reason: by the 100,000th answer `lambda` is past D74's threshold of
1024 entries, so under the `jit` build both samples come through the
compiled caller.

### S2. Criterion 1b doesn't say how a test makes a chosen poll meet the trip

S5 says a trip "is taken by whichever poll meets it first". The engine's
poll gives E40, and the interpreter's poll inside λ gives E24 (E57 inside
`ask`). Criterion 1b asks for both, in `oom_guard.rs`, but neither path
can be forced the way the existing tests trip the guard:

- **Tripping before the call doesn't work.** A trip set before `eval_str`
  is taken by the poll at the top-level body's frame, before `kb.query`
  runs (`push_frame_once` polls first; that is how
  `a_trip_fails_the_next_call_like_any_error_and_is_catchable` works). So
  neither code is reached.
- **Tripping from another thread races.** Doing it mid-query, as
  `a_running_program_is_stopped_at_its_next_call` does, races the
  engine's poll against the interpreter's whenever the query runs bridges.
  The code would then differ between runs.

**Fix:** state the mechanism.

- **E40:** a bridge-free query that never ends (`[ loop ]`), tripped from
  another thread. Only the engine polls there.
- **E24:** a λ that calls a native the test registers, which calls
  `bund2_api::memguard::trip` (it is `pub`), followed by a call to a
  registered word, so that the interpreter's poll at that word's frame is
  the next one reached.
