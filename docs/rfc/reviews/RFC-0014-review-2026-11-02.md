# RFC-0014 review: Draft of 2026-11-02

Adversarial review. The RFC was not edited. It was read against Bund2 at
`8c1cc2e` plus the working tree, `reference/Bund` 21b40b0, and SMYSL at
4f5ecb9. Nothing was built or run except `cargo tree -i cc --offline`, which
shows the default `bund2-cli` build has no `cc`.

**Verdict: Not ready for Accepted.** 4 blocking, 12 should-fix, 12 notes.
D244 is OPEN, so nothing can be accepted yet anyway.

**Checked by the RFC's author before filing.** B1, B2, S1, S2, S4, S5, S6,
S10 and S11 were re-opened in the sources and hold. One sentence of S5 does
not: D55 is about words that read the *stack* beyond their operands, not the
filesystem, so it does not bear on the `smysl.` words. And D168 is the
CLI's `async` feature reaching no code, a forwarding precedent beside
F124, not CI's feature matrix, which is the `feature matrix` step in
`.github/workflows/ci.yml`. The rest of S5 stands. Nothing else was
changed.

## Blocking

### B1. `smysl.prove` re-enters evaluation, yet §S9 calls it fixed-effect

§S9 says "every word but `smysl` has a fixed effect and does not re-enter
evaluation", but `smysl.prove` runs `kb.prove`:

- RFC-0013 §S9 declares `kb.prove` `opaque(2)` "because these words may run
  bridges or `ask`", and keeps it out of Tier 1 (§S13).
- The stdlib audit would not catch the mistake.
  `no_fixed_effect_native_runs_a_body` (`crates/bund2-stdlib/src/lib.rs`)
  feeds only lambdas, and `smysl.prove` would refuse those with SM00
  before running anything.

**Fix:**

- Declare `smysl.prove` opaque.
- Add it to Tier 1's never-cross list and to `REENTERING`.
- State the `check` arm it needs.
- State that RFC-0013's E-codes pass through it.

### B2. SMYSL's library lock protocol is omitted, and Q50 asks about a lock that exists

`Library::add` documents: "The caller holds the locks (§3.9.3: the library
lock, then the shards in name order)" (`library.rs:1001-1004`). The lock:

- is taken by `smysl_text::lock::acquire_all` (`smysl-text/src/lock.rs:24-43`),
  built on `smysl-graph/src/lock.rs`;
- fails fast with `SMY-E445`, naming the holder (`lock.rs:3-5`);
- is deliberately left behind when a process is killed (`:20-25`);
- is taken on every write by SMYSL's CLI (`smysl:src/main.rs:8628,12656`).

Q50 and §S9 say "no lock … was found" and design a lock of Bund2's own. So
Bund2 would write a library while bypassing the lock SMYSL's own CLI
honours. The RFC also does not say:

- which SM code `SMY-E445` reaches a Bund program as;
- what a stale lock does, given there is no break-lock word;
- in what order the two locks are taken.

**Fix:**

- Require `acquire_all` around every library write, and map `SMY-E445`.
- Restrict Q50 to the plain log `Store`, whose `append` takes no lock
  (`store/mod.rs:414`).
- Say what a stale lock does to a Bund program.

### B3. §S7 asks the proof tree for things it does not carry

RFC-0013 §S15 gives a rule node as `[ goal ← p₁ … pₖ ]` and a fact node as
`[ goal ← :fact ]`.

- **No clause.** Neither names its clause, so "whose body names the clause"
  cannot be built without changing the engine. That contradicts the
  Preservation row "RFC-0013's words and engine: Preserved exactly".
- **No source KB.** Nothing in a fact node says which KB a fact came from,
  so "a fact node that `smysl.kb` produced about a unit `U` is `U` itself"
  cannot be decided:
  - a program can `kb.assert` `[ unit "b3:…" … ]` itself, or `kb.merge`
    one in;
  - `[ rel … ]`, `[ rank … ]`, `[ label … ]` and `[ effective … ]` facts are
    not "about a unit" whose uid could stand for them.

**Fix:**

- Define provenance by the fact's functor and arity plus a uid that exists
  in the handle's store.
- Say what each of the eight fact kinds maps to.
- Either drop "names the clause" or file the engine change.

### B4. §S7's status rules produce units SMYSL refuses, and miss most proof-node kinds

- **Units SMYSL refuses.** `derived` and `inferred` require grounds
  (`epistemics.rs:76-79`; refused at `unit.rs:163-165`). These cases get
  none and fail with SM02:
  - a rule whose premises are all `:no-proof`, `:bridge`, `:builtin` or
    `:tabled`, each of which "grounds on nothing";
  - a rule with an empty body;
  - a program fact given `opts.facts = "inferred"` or `"derived"`. §S7
    warns only about `cited` and `measured`.
- **Node kinds left out.** §S15 also has `:branch`, `:then`, `:else`,
  `:findall`, `:builtin`, `:tabled`, and transparent `call` and `once`.
  §S7 maps none of them, and criterion 12 tests none.
- **Gist rendering.** The gist is "the goal as the answer instantiated it",
  with no rendering specified. Identity "does the rest" only if that
  rendering is deterministic and covers unbound variables (NODATA).

**Fix:**

- Give a rule for every §S15 node kind.
- Say what a conclusion with no grounds becomes (for example
  `speculative`).
- Specify the gist rendering.
- Extend criterion 12 to cover these cases.

## Should-fix

**S1. Q53 is answerable, and two writes are Bund2's choices, not SMYSL's.**

- `ask(question, &Env, …)` takes the store immutably (`plan.rs:51-52`) and
  returns `records: Vec<Record>`, "the question unit, each slot's saved
  query and edges, the thread and the view" (`dossier/mod.rs:325-326`). It
  writes nothing.
- `measure::run` returns `MeasureResult`s (`smysl-measure/src/lib.rs:239-248`)
  and writes nothing either.

So whether `smysl.dossier` and `smysl.measure` write is a design decision.
R11 B, the locking and criterion 10 all depend on it.

**Fix:** answer Q53 from source, and give every word a read/write column.

**S2. Q51 is partly grounded.**

- "The truncated tail it warns about is already tolerated by
  `from_cbor_seq`" (`smysl-graph/src/lock.rs:20-22`).
- A panic unwinds through `catch_panic` (`crates/bund2-api/src/lib.rs:104`),
  so `Lock` is dropped and released.

**Fix:** cite these, and narrow what remains `[UNGROUNDED]`.

**S3. Criterion 5 cannot be run as written.** `smysl.parse` returns MAPs and
writes nothing, and `smysl.write` takes a handle (§S4). Nothing composes the
two.

**Fix:** have the test parse, append through `smysl.unit`/`smysl.rel`,
write, then re-parse. Or add a word that writes records.

**S4. Criterion 6 checks the wrong thing.** `smysl.text.add` answers a
manifest uid. A manifest is a `Record::Manifest`
(`smysl-core/src/types/record.rs:103`), not a unit, and `smysl.get` answers
NODATA for it.

**Fix:** say which records a text adds and how to find them.

**S5. The Preservation analysis misses behaviours.**

- **The audit lists.** `ACTS_ON_HOST` and `FEATURE_GATED` are at
  `crates/bund2-stdlib/src/lib.rs:625,881`, and "a new feature-gated native
  runs for real until it is named here" (`:877-879`). Under
  `--all-features`, the palette audit would run `smysl.create` on palette
  strings, and `Library::create` does `create_dir_all` (`library.rs:289`).
- **`PROMOTABLE.txt`.** It has a one-file-two-builds rule (F123,
  `tests/golden/PROMOTABLE.txt:8-15`), and D72 says "PROMOTABLE.txt
  regenerates".
- **`bund2 check`.** Its conditional arm covers `"csv" | "sqlite" | "query"`
  (`check.rs:2188`). Any other type is abandoned (`:2233`).
- **Bundles.** A bundle records the runtime's features (`features_built_in`).
  A bundle that uses `smysl.` words can then be run on a runtime without
  the feature.
- **Feature forwarding.** F124 and D168 show that a feature routed through
  the `bund2` facade reaches no code. The existing `grok` feature is not
  forwarded by `bund2-cli` at all (`crates/bund2-cli/Cargo.toml:45-55`).
- **The editor syntax file.** `editors/nvim/syntax/bund_words.vim` is
  generated from `bund2 words` (`editors/nvim/tools/generate-words.sh`),
  so it depends on which build ran it.
- **CI.** CI's feature matrix (D168) and `--all-features`.

*(Author's check: the review also cited D55 here, on the grounds that every
`smysl.` read observes the filesystem beyond its operands. D55 concerns the
stack, so that sentence is set aside.)*

**S6. "`bund2 check` gets an arm for each" is wrong for fixed-effect
words.** `check` reads their declared effect (`effect_of_name`,
`check.rs:1028-1032`). The phrase is RFC-0013's sentence about its opaque
words. What is actually needed is the conditional arm (S5) and an arm for
`smysl.prove` (B1).

**S7. Refusals are underspecified.**

- **No texts.** Criterion 13 asks for "its text", but no SM code has one.
  House style is `<W>: ` (RFC-0013 §S12).
- **SM04 is singular.** It carries "its code", but `plan` and `run` return
  `Vec<Diagnostic>`.
- **SM05 departs from SMYSL.** An unknown measure id is a *result* in
  SMYSL, `SMY-E489`, not a failure (`smysl-measure/src/lib.rs:251-252`).
- **Two diagnostic streams have no D36 route:** `Run.warnings`
  (`exec.rs:109-112`, for example W463) and `MeasureResult.diagnostics`.

**S8. The §S2 mapping loses data, so a read-then-write changes uids.**

- `UnitCore.extra` is hashed (`unit.rs:56-57`) and is not in the MAP.
- A relation's `attestations` and `extra` are not in the MAP either.
- Payload and weight floats are quantised to 1/1024 (`payload.rs:253-257`;
  `relation.rs:179-181`).
- A payload is opaque CBOR for an extension schema, and decoding it can
  fail (`payload.rs:177`).
- Bund values with no HValue form (BIN, MATRIX, LAMBDA, …) have no stated
  refusal.
- `subject` and `source` have no stated shape.

**S9. Agents and attestations are absent.** Retraction defaults to `Origin`
authority: "only an agent that attested a unit can retract it"
(`merge/policy.rs:106-116`). The RFC never says what agent Bund2 attests
as, or whether `smysl.retract` survives a merge.

**S10. The per-VM cache (R4) has no home and no cheap check.**

- RFC-0013 §S2 says "a per-VM store needs a slot `bund2-api` lacks", and the
  `Vm` trait still has none.
- The stamp hashes the shard logs as loaded (`shards.rs:395-415`), so
  checking it against disk means re-reading every log.
- §S3's first bullet ("closes it before returning") contradicts its second.

**Fix:** name the API change, or use a process-wide cache shared with the
§S9 lock. Ground the staleness check in a stamp that can be read from disk.

**S11. "No `.` forms" is an unruled language decision.** RFC-0013 §S9 gave
eight `kb.` words `.` forms "(D18, D24, D111)"; RFC-0014 refuses every one,
with no reason given.

**Fix:** cite D18's scope ("When D14 preserves a word") as the reason, or
add an R-point.

**S12. Handles and roots.**

- A relative `root` saved by `save.model` and loaded in another working
  directory names a different library, yet §S2 promises a handle
  "survives … a fresh process".
- §S9 keys its lock on the canonical root, but the handle is never
  canonicalised.
- Nothing says what a handle means after crossing the bus (RFC-0007).

**Fix:** canonicalise the root in `smysl.create` and `smysl.open`, and say
what a handle means on the bus.

## Preservation analysis: what it omits

Everything in S5, plus:

- **Tier 1.**
  - Opaque `smysl.prove` must never be crossed.
  - The `smysl` constructor (`eff(0,1)`) would reach the palette as
    `query` does, and in only one of the two builds.
- **Honesty audits.** `REENTERING` must name the `smysl` runner and
  `smysl.prove`, and CI must run `cargo test -p bund2-stdlib --features
  smysl`. Otherwise the audits never see the words.
- **`--noio`.** Whether a stub replaces `smysl.parse` and `smysl.check`,
  which do no I/O.

The `bund2 words`/`coverage` row is right (D72), since `IMPLEMENTED` is
joined against the reference's registry. But `bund2 words` itself differs
between builds.

## Assumptions not stated

1. All eight crates are on crates.io at 1.14.0, and the APIs used are
   public and can be constructed from outside: `Env` with its
   `Rc<Reader>`, `AskOptions` and templates, a measure's base `Recipe`, and
   `measure::Input` with a `Corpus`.
2. A process-wide lock table keyed by root is acceptable in Bund2. It is
   global state, the thing RFC-0013 §S2 avoided.
3. SMYSL's `create_new` file lock (`smysl-graph/src/lock.rs:3`) behaves the
   same on every filesystem Bund2 targets.
4. Gist text rendered from a Bund LIST is stable across Bund2 versions. If
   it changes, every exported uid changes.
5. RFC-0013 Phase 2 (`kb.prove`) is built and its proof shape is frozen.
6. Answers from one VM's cache stay consistent with another VM's writes,
   with nothing between them but the stamp to invalidate the cache.
7. SMYSL's guarantee A1 (no panic on untrusted input) holds for any MAP a
   program can build.
