## Significant

### S1 — §D8 describes a history written at session end; Bund2 writes it at every line

R:452-453 and the row at R:512 say the file is written when the session
ends. `Terminal::remember` (`terminal.rs:105-114`) saves after each line,
and says why: the editor is the terminal's and outlives the word, so there
is no end-of-word moment to write at. The reference writes once, at the end
(`debug_debug.rs:119`, `debug_shell.rs:51`). So there are **three**
differences from the reference on this row and the table names two:
where the file is (§D8, F10), whether an empty session writes one (R:512),
and **when** — a session that crashes after three lines keeps them in
Bund2 and loses them in the reference. The third is a change in the
reference's user-visible behaviour with no row and no decision. It is
benign and probably wanted; it is still unrecorded. One row.

### S2 — `--debug-shell` after a `--debugger` failure is a deviation D156 records as "fell out", not as ruled

The reference runs its shell after a `--debugger` run fails
(`run_snippet.rs:31-33`, `:78-80`). Bund2 does not: `shell_after_a_failure`
evaluates `debug.shell`, whose first read under `--debugger` is the end
(`main.rs:1192-1197`, whose own doc says "this is the behaviour that falls
out, not one that was chosen"). D156's addendum says the same in terms:
"as they fell out and not as rulings". The row at R:505 presents it as a
disposition — "**Not after a `--debugger` failure**" — with D156 as its
authority, and D156's ruling ("A, build it") predates the note and did not
rule on it. Two readings are open: D155 already approves that a
`--debugger` session is not the reference's, so the combination is inside
that approval; or it is a second half of a reference flag, unruled.
Either is one sentence from the owner, under D155 or D156. The RFC should
say which it is standing on.

### S3 — D156's build has no criterion in this document

`--debug-shell` was built under this RFC on 2026-10-13 and the row at
R:505 names the date and no check. The check exists —
`debug_shell_after_a_failure_is_on_the_vm_the_program_left`
(`crates/bund2-cli/tests/debugger_words.rs:181`) — and D156 names it; the
RFC does not. The same for F207: R:645-650 says "`debug.dump` now writes
the reference's text for each" and names no test;
`a_forged_tag_gets_the_references_casting_texts` (`console.rs:370`) is it.
Every other met claim in the document names what checks it.

### S4 — Research departures: the closing paragraph is uncorrected where it stands

R:1191-1199 says only the flag spelling was a deliberate departure, that
"none is a departure any more", and that ERRATA gains one entry. Since
D113's ruling, (g) is a departure by decision and ERRATA has two entries;
R:47-54 says so at the header, three hundred lines away, and the paragraph
has no mark. This is the class B4 was about, and the document's own
practice elsewhere (R:457, R:505, R:1241) is to mark the passage.

## Preservation analysis — what the table still does not enumerate

The third review's twelve items each have a row now (R:503-519) or a
ruling. Beyond S1 and S2:

1. **`--debug-shell` under `--noio` and `--noeval`.** D156 says "by the
   word's name, so `--noio` and `--noeval` make of it what they make of the
   word". What the reference's flag does under its own `--noio` was not
   read, and the RFC does not say what Bund2's does. One row, or a sentence
   saying it was not examined.
2. **Which values `debug` accepts.** The contract note (R:146-149) says the
   reference takes "any value that casts". `cast_string` accepts any value
   whose payload is `Val::String` (`cast.rs:33-40`), and by `conv.rs:698-701`
   that includes CALL and PTR, not STRING alone. Bund2's `debug_word` uses
   `as_str` (`terminal.rs:498`), which accepts `Payload::Str` and a scalar's
   inner string (`bund2-value/src/lib.rs:889-897`). Whether the two sets
   coincide for a CALL or a PTR left on the stack is unexamined, and the
   error text `Casting debug snippet returns: This Dynamic type is not
   string` (R:508, "Preserved") is asserted for one operand kind only.
3. **A forged value at the other words of this contract.** F207 says every
   word that switches on a tag and reads a payload meets the same value and
   "was not examined". `debug.display_stack`, `debug.display_workbench` and
   the `debug` table all render values; what each shows for a forged one, in
   the reference and in Bund2, is outside every row. F207's "not looked at"
   is the right place for it; the RFC's Preservation table should point
   there rather than let "Preserved" on those rows cover a case nobody ran.

## What the RFC assumes but does not state

1. **That the `hexdump` crate renders the same in both trees.** Both lock
   files pin `hexdump 0.1.3`; the RFC says the format is matched by the
   oracle's bytes (R:201-204) and never says the match depends on the pin.
2. **That `--debugger`'s approval (D155) extends to every flag combined
   with it** — S2.
3. **That a history written per line is what §D8 means** — S1.
4. **That `as_str` accepts what `cast_string` accepts** — Preservation 2.
5. Carried from the third review, which the amendment at R:1778-1783 says
   are still not answered: (6) that nothing but standard input implements
   the console seam; (8) what `BUND_LOG_LEVEL=bund=info,other=trace` reads
   as under D90's "level after the last `=`"; (9) that the sweep's derived
   list of words that read input stays complete as words are added; (10)
   the order between a fed line and the console's next command.

## Verdict

The document is grounded: every reference citation opened today says what
the RFC, or the note beside it, says it does. The third review's blocking
findings are taken and the decisions they asked for are ruled. What remains
is one unrecorded behavioural difference (S1), one flag combination whose
authority the RFC should name (S2), two met claims with their tests unnamed
(S3), and one stale paragraph (S4). None of these needs code. Ready to
accept once S1 has its row and S2 its sentence, and acceptable as it stands
with both named as owed.
