## Blocking

**B1 — The third mechanism exists: a program constructs code from strings.
The RFC says "if there is one"; D79 said there was one nine days ago.**

§B3a, after its two searches: "A third mechanism, if there is one, appears in
neither, and this section does not claim there is none: it claims these two
were looked for and how." The two are a string parsed and a value decoded.
The third is a value *built*:

- `make.call`, `make.call.` and the alias `call,` turn a string into a CALL
  (`reference/Bund/src/stdlib/functions/values/make_call_value.rs:31-38`,
  registered at `:61-62`; the alias at
  `reference/Bund/src/stdlib/functions/create_aliases.rs:33`).
- `ptr` turns a string into a PTR
  (`reference/rust_multistackvm/src/stdlib/artefacts.rs:80-93`).
- `lambda*` folds the whole stack into a LAMBDA
  (`reference/Bund/src/stdlib/functions/bund/bund_fun.rs:189-202`, registered
  at `:219`), and `lambda!` does it to a LIST (`:218`, which the RFC cites).
- `!` on a STRING, a PTR or a CALL calls the word of that name
  (`reference/rust_multistackvm/src/stdlib/execute.rs:27-30`).

None has a gate. Bund2 has the same words
(`crates/bund2-stdlib/src/values.rs`, `make_call_base`, `ptr`, `fold_lambda`,
`to_lambda`, `execute_one`). No parser runs and nothing is decoded, so
neither of §B3a's searches can return any of them.

Measured 2026-10-08, on bundles built `--noeval --noio` (`--inspect` prints
`restrictions   --noio --noeval`), then on `bund2 script --noeval --noio`,
then on the oracle at `21b40b0` under both flags:

| program | standard input | bundle | `script` | oracle |
|---|---|---|---|---|
| `40 2 "+" make.call "println" make.call lambda* !` | closed | `42` | `42` | `42` |
| `40 2 "+" ptr ! "println" !` | closed | `42` | `42` | `42` |
| `42 "> " input !` | `println` | `42` | `42` | `42` |
| `40 2 "> " input string.tokenize { make.call } map lambda! !` | `+ println` | `42` | `42` | `42` |

The last is a line of words read from standard input, split, made callable
and run. The third is three words long and names nothing §B3a lists as a
route.

**The registers already hold all of it**, and a search by subject finds it:

- D16: "a call target may be named by a string that exists only at run time",
  with `ptr` and `execute`'s `PTR | STRING | CALL` arm cited.
- D79, "Why the behaviour is not changed": "D16 means a call target can be
  assembled at run time, so evaluation cannot be switched off by name-gating a
  word list."
- D34's evidence calls `call,` → `lambda*` → `register` "the canonical
  metaprogramming idiom", from
  `reference/Bund/examples/bund_dynamic_demos/create_lambda_on_the_fly_in_the_context.bund:10-20`.
  That program is in `tests/golden/HERMETIC.txt`, so criterion 2 runs this
  mechanism in every bundle it builds.
- §B3a itself, forty lines below the hedge: "D16 means no build can prove a
  program never calls `fs.rm`: the name may be assembled at run time." The
  RFC uses the fact to justify a switch and does not apply it to what the
  switch leaves.

Three things to weigh, the first two against the finding.

- **It gives a program nothing `compile lambda! !` does not.** The floor is
  where it was, exactly as the ninth review said of `decode.base64`.
- **It is probably ruled already.** D79's sentence above is this finding, in
  the owner's decision. D122 and D123 each ruled on one word because each
  word was the reference's and outside the group; these are too. If the
  owner reads D79 as covering them, no new decision is owed.
- **It is not one more name; it ends the list.** `compile`, `debug`,
  `bootstrap`, `decode.base64` and the `load` words are *sites*: a search
  finds them and an audit can look for them. This mechanism has no site. Any
  program that has `input` or `args`, something that splits a string, and
  `!` is an interpreter for what it is handed — and those are the language's
  ordinary words, the first two of which §B3a lists as ungated for other
  reasons. D123 tells a reader "The names to look for are in §B3a". After
  this the name to look for is `!`.

**What it needs.** No gate: that would be a deviation, and of the feature
CLAUDE.md's first sentence calls "metaprogramming". A paragraph in §B3a
naming the five words and the STRING arm of `!`; the hedge replaced by the
third mechanism and by a plain statement that the list of routes is open by
construction and why; a preservation row; a dated note on D123's "What a
reader should carry away"; and criterion 10's "cannot see" sentence widened
(S4). If the owner does not read D79 as covering it, a ruling first.

## Should fix

**S1 — "A symlink at `--output` is still followed" is true of a link that
resolves and false of one that does not.** §B3, the preservation row, F181
and `place`'s comment all say it. `place` canonicalises `--output` and falls
back to the path as given when that fails
(`crates/bund2-cli/src/main.rs`, `place`), so a dangling link is not
followed: the rename replaces the link. Measured:

| `--output` is | result |
|---|---|
| a symlink to an existing text file | the target becomes the artefact; the link remains |
| a symlink to a path that does not exist | **the link becomes the artefact; the target is not created** |
| a symlink to the builder | refused, as §B3 says |

Before F181 the write went through `std::fs::write`, which would have
created the target (read from its contract, not measured on the old tree).
So "as it was" in `place`'s comment is wrong for this case. One sentence.

**S2 — `--file` and `--output` naming the same file destroys the source and
reports success.** Measured: `bund2 build --file same.bund --output
same.bund` exits 0 with "wrote same.bund — 13 of 1048576 bytes used", and
`same.bund` is a Mach-O executable. §B3's "any other existing file at
`--output` is replaced without a word" covers it to the letter. But the one
guard that exists is against destroying the builder, on the argument that it
is "destructive, silent, and one keystroke away"
(`crates/bund2-cli/src/main.rs`, `build`), and that argument describes this
at least as well: the builder can be rebuilt and the source cannot. §B3 says
refusing "would be a change to decide"; this is the case that makes it worth
deciding. Until then, a sentence that names it.

**S3 — F181 changed what a build needs and what it can leave, and neither
the RFC nor F181 says so.** Read from `place`, the first measured:

- **The directory must be writable, not the file.** Building over a writable
  file in a read-only directory now fails: "writing ro/out: creating
  …/ro/.bund2-build-53728: Permission denied". An in-place write needed only
  the file.
- **That one failure does not end "Nothing was written to …"**, which every
  other failure of `place` does: `create_dir`'s error returns before the
  suffix is added.
- **A build killed between the write and the rename leaves
  `.bund2-build-<pid>/` beside the destination**, holding a copy of the
  runtime. Nothing looks for one from an earlier run, and a directory of that
  name already present fails the build.
- **The replaced file's mode and ownership are not kept**; the artefact gets
  a new inode with the mode `make_executable` sets.

The second and third are worth a line in F181. The first belongs in §B3
beside "a build that fails leaves `--output` as it was".

**"Not measured" can come off one sentence.** §B3: "an artefact rebuilt while
it is running is not rewritten under itself — by the contract of a rename,
not measured." Measured here: an artefact waiting on `input` was rebuilt from
another program; the inode changed, the running copy read its line and
finished as the old program, and the next run was the new one.

**S4 — Criterion 10 and one preservation row still give the list as it stood
two reviews ago.** Criterion 10: "Nor do `"…" debug` and, under `--noeval`
alone, `bootstrap`: neither is a stub, and this criterion cannot see them."
It cannot see `decode.base64`, the three `load` words or B1 either. The row
"What `--noeval` stops" names `compile lambda! !` alone.

**S5 — "Nothing switches it off" is false of the history file: the
environment does.** §B3a: "for a shipped artefact it belongs here, and
nothing switches it off." `history_path` reads `XDG_CONFIG_HOME`, `HOME` and
`APPDATA` and keeps no history when it can name no directory
(`crates/bund2-stdlib/src/terminal.rs`). Measured on a bundle of
`debug.shell` built `--noio --noeval`, one line piped in each time:

| environment | history file |
|---|---|
| `XDG_CONFIG_HOME=<dir>` only | `<dir>/bund2/bund_debug_shell_history.txt` |
| `HOME=<dir>` only | `<dir>/Library/Application Support/bund2/…` |
| none of the three | **none written**; the line still runs and prints `42` |

So three more variables are read by a bundle, and §B3's list of them ends
"listed so the list is whole" two short of what decides where a shipped
program writes. It also means the runner has a way to stop the write that
the RFC tells them does not exist.

**S6 — "Runs on every target Rust runs on" is the research's sentence about
a construction ERRATA superseded.** Summary, of `--emit=bundle`. The source
is `docs/research/02-native-binaries.md:46-47`, "runs anywhere Rust runs",
said of `include_bytes!` into a linked stub. What was built instead is an
in-place write into a copy of the running executable, re-signed where the
platform requires it, read back through a `black_box` the RFC itself calls
"a hint and not a guarantee" — and §B1 says of it "run on macOS, arm64, and
nowhere else". The Summary states as fact what §B1 states as unmeasured.

**S7 — Small.** §B3: "**Four more things `bund2 build` does**" introduces
five bullets; F181's "a build that fails leaves `--output` as it was" made
the fifth.

**S8 — Carried, all stated in the RFC and none changed.** `cargo xtask
bundle` in neither `cargo test` nor CI; `black_box` a hint; ELF and PE
unmeasured in the built form; `/usr/bin/codesign` possibly a stub; no
criterion has run in CI; the recorded version is `0.0.0`; Q42; D78's body
still says `--dump-stack`, with its note; the two loose citations and
`bund_save.rs:26`.

## What the RFC assumes and does not state

1. **Code a program is handed arrives ready-made** — as text or as an encoded
   value. It can arrive as a list of names (B1).
2. **The routes can be listed.** Two of the three mechanisms have sites; the
   third is the language (B1).
3. **`--output`'s directory is writable and holds nothing named
   `.bund2-build-<pid>`** (S3).
4. **`--output` is not the file being built from** (S2).
5. **The executable on disk is the one that is running.** `build` parses with
   the running image and copies `current_exe()` from the filesystem
   (`crates/bund2-cli/src/main.rs`, `build`). §B1's "the parser that accepted
   the program at build is the parser that reads it at start" holds only
   while those are the same bytes — not across a `bund2` replaced under a
   long-lived process, and D118's "builder and runtime cannot differ" rests
   on it. Read, not measured.
6. **Re-signing ad hoc is harmless to the copy.** `codesign -f -s -` replaces
   whatever signature the builder carried, so a Developer-ID-signed `bund2`
   would produce ad-hoc-signed bundles. §B1 says no such binary was tested;
   it does not say this is what would happen. Read from `reseal`.
7. **The runner cannot stop the history write.** They can, by environment
   (S5).
8. Carried, and stated in the RFC: the compiler does not fold reads of the
   region; the in-place write works on ELF and PE; `/usr/bin/codesign` is
   present and real; a refusal is text and not an exit status.

B1 costs a paragraph and removes a sentence. It needs the five words named,
and it needs §B3a to stop presenting the routes as a list that searching can
close. S2 is the only finding here that loses a user's file.

**On the pattern, which this should end.** Six reviews in a row have found a
way a restricted artefact runs what it is handed, and each was answered by
naming the word. That worked while the routes were sites — a parser call, a
